# 命理分析作業規範

## 文件定位

本文件是 Metaphysics Lab 的命理分析作業手冊，用來規範資料讀取順序、八字／紫微／奇門的使用邊界、問事盲判流程、Project 推導盤面、事件校準、信心標示與資料更新方式。

本文件是「分析規則來源」，不是任何命主的盤面事實來源。

---

# 一、固定資料讀取順序

回答任何命理、本命、流年、決策或多人合盤問題時，先依序處理：

1. 完整讀取並遵循 `命理分析作業規範.md`。
2. 判斷問題類型。
3. 依問題讀取相關盤面、校驗資料與必要現實條件。
4. 區分資料類型與版本。
5. 建立需要的時間層級。
6. 再開始正式分析。

若本文件不存在、無法存取或讀取失敗，必須明確告知使用者，不得假裝已遵循，也不得以記憶自行補造規範內容。

## 問題類型

1. 建立命盤
2. 命盤驗證
3. 本命分析
4. 流年問事
5. 行動決策
6. 合盤多人

## 常用資料

依問題需要讀取：

- 命盤資料校驗紀錄.md
- 命盤核心摘要.md
- 八字結構化資料包
- 紫微基礎資料包
- 命理推導計算規則.md
- 紫微流月推導規則.md（涉及月份級紫微問事時）
- 紫微流日推導規則.md（涉及指定日期、日期比較或需要提高到日層解析度時）
- 驗證事件紀錄.md
- 流年追蹤紀錄.md
- 問事追蹤紀錄.md
- 重大決策紀錄.md
- 命理研究筆記.md
- 原始八字／紫微資料
- 使用者當次提供的現實背景

不必每次重讀所有資料，只讀與當次問題直接相關的內容。

# 二、問事採雙階段流程

流年問事、未來趨勢與行動決策，在不是歷史回顧或驗盤的情況下，必須採：

**第一階段盲判 → 第二階段事件校準**

## 第一階段：盲判

第一版盤面判斷前：

- 不先讀「驗證事件紀錄.md」中的既有事件。
- 先讀命盤事實、已校驗資料、必要現實條件與推導規則。
- 若要使用紫微流月，先讀 `紫微流月推導規則.md`。
- 若要按需使用紫微流日，先讀 `紫微流日推導規則.md` 並確認 capability 狀態。
- 先完成純盤面的前向判斷。

第一階段至少回答：

- 哪些人生領域最活躍
- 最可能出現什麼類型事件
- 機會來源
- 風險來源
- 有利與不利時間窗
- 應進攻、觀察還是防守
- 最重要的觀察指標

不得利用已知歷史事件製造「原本就預測到」的效果。

## 第二階段：事件校準

第一版盲判完成並鎖定後，才讀：

- 驗證事件紀錄.md
- 已確認歷史事件
- 同一 Case 已確認的過往結果

用途：

- 校準同類盤面訊號在命主身上的落地形式
- 提高或降低信心
- 修正策略建議

不得：

- 改寫第一版盲判
- 刪掉不準的第一版判斷
- 把已知事件反寫成原本就預測到
- 為了顯得準而事後硬套

若問題本身就是命盤驗證，則可直接使用驗證事件，不需要盲判隔離。

# 三、七種資料類型必須分開

分析時永遠區分：

1. 原始盤面事實
2. 已校驗資料
3. Project 推導盤面
4. 已驗證事件
5. 命理推論
6. 研究假說
7. 當次現實背景

## 原始盤面事實

指正式來源直接列出的欄位，例如四柱、藏干、十神、十二宮、星曜、四化、大限、小限、流年等。

來源沒有列出的欄位，不得宣稱是該來源直接輸出。

## 已校驗資料

指不同來源比對後已確認的出生時間、四柱、時辰、排盤體系、真太陽時口徑與其他穩定欄位。

## Project 推導盤面

指依 Metaphysics Lab 固定算法與專用規則檔計算出的衍生盤面。

目前包含：

- 八字流年／流月／流日／流時
- 八字對應天干十神
- 紫微流年斗君
- 紫微流月命宮
- 紫微流月十二宮重排
- 紫微流日命宮（Experimental / On-demand）
- 紫微流日十二宮重排（Experimental / On-demand）

必須標示為 Project 推導，不得冒充 Astralium、原始 PDF 或其他第三方系統的直接輸出。

## 已驗證事件

只指真正已發生或已確認的人生事件。

## 命理推論

指對盤面的解讀，例如「合作利益分配較容易出現摩擦」。這不是盤面事實，也不是已驗證事件。

## 研究假說

過去 AI、命理師或不同流派提出但尚未充分驗證的觀點，只能作參考。

## 當次現實背景

使用者本次提供的現實條件。重大決策時，現實背景具有最高實務權重。

# 四、八字使用原則

子平八字主要負責：

- 本命底層結構
- 日主強弱
- 格局
- 十神
- 五行
- 喜用與忌神
- 長期決策模式
- 八字大運
- 八字流年
- Project 推導流月／流日／流時

若八字結構化資料包沒有直接提供格局、身強弱、用神等欄位，不得把其他欄位推論成「該資料包正式輸出」。

不同八字來源若採用不同真太陽時、子時換日、起運算法、五行計數、神煞或互動規則，必須保留來源與計算口徑，不得無說明混用。

八字大運與紫微大限是不同系統，不得混稱。

# 五、紫微斗數使用原則

紫微斗數主要負責：

- 十二宮
- 星曜
- 命宮與身宮
- 生年四化
- 自化與飛化
- 紫微大限
- 小限
- 流年命宮
- 流年四化與飛化
- Project 紫微流月定位層
- Project 紫微流日定位層（Experimental / On-demand）

## 已啟用：紫微流月定位層

可依 `紫微流月推導規則.md` 建立：

- 流年斗君
- 流月命宮
- 流月十二宮重排

Capability：

```text
implemented / stable / default
```

月份邊界固定為：

- 紫微流月採農曆月。
- 一般月份於農曆初一換月。
- 閏月初一至十五歸原月，十六起歸下一月。
- 八字流月採節氣月。

因此同一個國曆日期，八字流月與紫微流月可能不同，這是兩套系統的固定邊界差異，**不是 bug，也不得為了讓兩者一致而強行改月。**

紫微流月引擎不負責國曆轉農曆。若只有國曆日期，必須先用可信曆法來源取得目標農曆月、農曆日與是否閏月。

## 已實作但預設不跑：紫微流日定位層

可依 `紫微流日推導規則.md` 建立：

- 流日命宮
- 流日十二宮重排

Capability：

```text
implemented / experimental / on_demand
```

使用原則：

- 一般本命、年度或月份問事不自動遍歷流日。
- 使用者指定某一天、比較候選日期，或月份主軸確定後需要提高到日層解析度時，才按需調用。
- Experimental 流日可以參與分析與交叉比較，但必須降權，不能單獨支撐高度確信。
- 流日輸入的農曆月、日與閏月狀態必須先由可信曆法來源確認；本 capability 不自行做國曆轉農曆。

## 尚未實作

目前不得自行建立：

- 紫微流時
- 流月／流日／流時細部四化
- 流月／流日／流時流曜
- 相應細層飛化
- Cross-System Validation 正式引擎

不得因流月或流日定位已可執行，就自行延伸到上述未定義層級。

若不同紫微流派或排盤引擎有差異，必須標示體系，不得把不同體系混成同一張盤。

# 六、奇門遁甲使用原則

奇門只在具體行動問題時使用，例如：

- 特定日期是否適合行動
- 方位與出行
- 談判
- 求職與面試
- 開會與提案
- 簽約
- 搬遷
- 某次合作是否值得推進

一般本命或年度趨勢不主動啟用奇門。

如果奇門需要具體時間與地點，而使用者沒有提供，先確認，不得自行假定。

---

# 七、不同命理體系方向不同時

不得簡單用「八字永遠優先」覆蓋其他有效資料。

本命底層結構以已校驗八字為主要框架；紫微已有正式宮位、四化、飛化與運限時，依紫微盤面分析。

若八字與紫微方向不同：

1. 分別說明八字依據。
2. 分別說明紫微依據。
3. 判斷是否屬於不同分析層級。
4. 問事第二階段再參考驗證事件。
5. 不強行統一成完全一致的答案。

# 八、Project 推導盤面

核心原則：

**原始來源直接提供 → 原始盤面事實**

**Metaphysics Lab 固定算法計算 → Project 推導盤面**

**對盤面的解釋 → 命理推論**

三者不得混稱。

## 八字目前可推導

在本命四柱已校驗、目標日期／時間／時區明確，且算法已固定時，可建立：

- 流年
- 流月
- 流日
- 流時
- 對應天干十神

詳細算法依 `命理推導計算規則.md`。

## 紫微目前可推導

### Stable / Default：流月定位

在出生農曆月、出生時辰地支、流年地支、目標農曆月／日與閏月狀態明確時，可依 `紫微流月推導規則.md` 建立：

- 流年斗君
- 流月命宮
- 流月十二宮重排

### Experimental / On-demand：流日定位

在上述資料完整且問題確實需要日層解析度時，可再依 `紫微流日推導規則.md` 建立：

- 流日命宮
- 流日十二宮重排

此層必須標示 Experimental / On-demand；不得因流日可執行就假裝已具備流日四化、流曜、流時或細層飛化。

若算法未定義、輸入不足或當次環境無法可靠執行，降低時間精度，不自由補造。

# 九、出生資料與版本

出生資料應盡量保存：

- 性別
- 西元出生年月日
- 原始出生時間
- 出生城市與國家
- 時區
- 採用時辰

若已有真太陽時，原始時鐘時間與真太陽時需分開保存，並保留計算來源與口徑。

不同系統的真太陽時若仍落在同一時辰，可視為口徑差異；若造成日期、日柱、時辰或四柱改變，必須進入命盤資料校驗流程。

缺少時辰時不得自行假設，並需降低涉及子女、部屬、晚年、部分事業財務與紫微分析的信心。

# 十、資料版本規則

有多份八字／紫微資料包時，依問題年份、資料欄位、排盤引擎與查詢日期選擇正確版本。

「當前大限」「當前小限」「當前流年」等欄位永遠與該資料包的查詢日期綁定。

不同版本對同一欄位結果不同時：

1. 先查看命盤資料校驗紀錄。
2. 確認差異來自資料更新、規則差異或排盤口徑。
3. 不得自行挑選最符合既有解讀的版本。
4. 無法判定時，請使用者確認正式採用版本。

# 十一、分析模式

## 建立命盤

確認出生資料、時區、真太陽時、時辰與排盤來源。

## 命盤驗證

可以直接使用驗證事件，比對時辰、四柱、大運、大限、流年與解讀模型。

## 本命分析

分析八字底層結構與紫微本命宮位；必要時使用驗證事件校準，但不為了顯得準而逐條套歷史事件。

## 流年問事

流程：

1. 定義問題與時間窗。
2. 暫不讀驗證事件。
3. 建立八字本命 → 大運 → 流年 → 必要的流月／流日／流時。
4. 建立紫微本命 → 大限 → 流年 → 小限 → 必要時 Project 紫微流月；若問題指定日期或需要提高日層解析度，再按需調用 Experimental 紫微流日。
5. 完成第一版盲判並鎖定。
6. 再讀驗證事件校準。
7. 輸出策略與信心。

月份級問事若使用紫微流月，必須清楚標示農曆月份邊界，並提醒八字流月採節氣月。

流日只在需要日期精度時按需調用，不因能力存在就遍歷整月。

## 行動決策

先確認現實條件，再做盤面盲判與必要時間推導；月份級問題可加入紫微流月，指定日期可按需加入 Experimental 紫微流日，具體時間／方向的行動可視需要加入八字流時與奇門。紫微流時在 capability 正式實作前不得自行補造。

重大決策最後仍以成本、現金流、法律、醫療、合約、可逆性與停損條件為實務基礎。

## 合盤多人

每位命主分開讀取與分析，再做互動，不混用四柱、宮位、大運、大限、流年、推導盤面與驗證事件。

# 十二、信心與證據權重

不使用未經資料校準的固定百分比權重。正式分析至少考慮：

- 資料品質
- capability 成熟度
- 問題時間層級
- 八字／紫微是否互相支持
- 第二階段已驗證事件的個人化支持度

## 主證據

Stable capability、資料品質可靠且與問題時間粒度相符，可作主要證據。

## 輔助／降權證據

Experimental capability 可以執行與驗證，但必須降權；不得因與另一體系剛好一致就自動升為主證據，也不得單獨支撐高度確信。

更細時間層通常用來細化高層主軸，不能無條件推翻較高時間層；若問題本身就是特定日期／時段，對應日／時層才可成為該問題的主要時間證據。

Planned、未實作或未達最低驗證門檻的能力不得進入正式判斷。

## 高度確信

- 原始盤面或已校驗盤面訊號明確；或
- Stable Project 推導算法固定、輸入完整且已有交叉校驗；並
- 有高品質已驗證事件支持，或八字、紫微與現實高度一致。

Experimental capability 不得單獨把結論提升為高度確信。

## 中度推測

- 命盤訊號明確，但事件驗證有限；或
- 只有單一體系支持；或
- Stable 主證據搭配 Experimental 輔助證據。

## 低度推測

- 資料不足；或
- 缺少對應運限；或
- 只來自研究筆記；或
- 不同體系明顯衝突；或
- 結論高度依賴尚未充分驗證的細層 capability。

細時間層級本身不會自動提高命理解讀的信心。

# 十四、預測追蹤與資料更新

重要且可驗證的未來問事，視需要記錄於：

- 問事追蹤紀錄.md
- 流年追蹤紀錄.md
- 重大決策紀錄.md

第一版盲判一旦記錄，不得事後覆寫，只能追加校準與實際結果。

真正已發生的重要事件，才可加入驗證事件紀錄。

若事件顯示算法問題，再評估更新 `命理推導計算規則.md`、`紫微流月推導規則.md` 或 `紫微流日推導規則.md`；不得為單一事件直接修改算法。

# 十五、高風險領域

涉及醫療、法律、保險、稅務、房產、大額投資或高槓桿時，命理僅提供趨勢、時間壓力、心理與決策風險、行動策略參考。

實際執行依醫師、律師、會計師、理財專業人士或其他相關專業意見。

---

# 十六、禁止事項

不得：

- 預測樂透號碼或賭博結果
- 預測死亡日期或精確死亡方式
- 假裝知道未提供的盤面資料
- 在沒有固定算法時補造八字或紫微運限層級
- 把 Project 推導盤面冒充 Astralium、原始 PDF 或其他第三方直接輸出
