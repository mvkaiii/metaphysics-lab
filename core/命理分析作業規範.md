# 命理分析作業規範

## 文件定位

本文件是 MingStack 的命理分析作業手冊，用來規範資料讀取順序、八字／紫微／奇門的使用邊界、問事盲判流程、Project 推導盤面、事件校準、信心標示與資料更新方式。

本文件是「分析規則來源」，不是任何命主的盤面事實來源。

---

# 一、固定資料讀取順序

回答任何命理、本命、流年、決策或多人合盤問題時，先依序處理：

1. 完整讀取並遵循「命理分析作業規範.md」。
2. 判斷問題類型。
3. 依問題讀取相關盤面、校驗資料與必要現實條件。
4. 區分資料類型與版本。
5. 建立需要的時間層級。
6. 再開始正式分析。

若本文件不存在、無法存取或讀取失敗，必須明確告知使用者，不得假裝已遵循，也不得以記憶自行補造規範內容。

## 問題類型

1. 建立命盤
2. 命盤驗證
3. 本命分析
4. 流年問事
5. 行動決策
6. 合盤多人

## 常用資料

依問題需要讀取：

- 命盤資料校驗紀錄.md
- 命盤核心摘要.md
- 八字結構化資料包
- 紫微基礎資料包
- 命理推導計算規則.md
- 驗證事件紀錄.md
- 流年追蹤紀錄.md
- 問事追蹤紀錄.md
- 重大決策紀錄.md
- 命理研究筆記.md
- 原始八字／紫微資料
- 使用者當次提供的現實背景

不必每次重讀所有資料，只讀與當次問題直接相關的內容。

---

# 二、問事採雙階段流程

流年問事、未來趨勢與行動決策，在不是歷史回顧或驗盤的情況下，必須採：

**第一階段盲判 → 第二階段事件校準**

## 第一階段：盲判

第一版盤面判斷前：

- 不先讀「驗證事件紀錄.md」中的既有事件。
- 先讀命盤事實、已校驗資料、必要現實條件與推導規則。
- 先完成純盤面的前向判斷。

第一階段至少回答：

- 哪些人生領域最活躍
- 最可能出現什麼類型事件
- 機會來源
- 風險來源
- 有利與不利時間窗
- 應進攻、觀察還是防守
- 最重要的觀察指標

不得利用已知歷史事件製造「原本就預測到」的效果。

## 第二階段：事件校準

第一版盲判完成並鎖定後，才讀：

- 驗證事件紀錄.md
- 已確認歷史事件
- 同一 Case 已確認的過往結果

用途：

- 校準同類盤面訊號在命主身上的落地形式
- 提高或降低信心
- 修正策略建議

不得：

- 改寫第一版盲判
- 刪掉不準的第一版判斷
- 把已知事件反寫成原本就預測到
- 為了顯得準而事後硬套

若問題本身就是命盤驗證，則可直接使用驗證事件，不需要盲判隔離。

---

# 三、七種資料類型必須分開

分析時永遠區分：

1. 原始盤面事實
2. 已校驗資料
3. Project 推導盤面
4. 已驗證事件
5. 命理推論
6. 研究假說
7. 當次現實背景

## 原始盤面事實

指正式來源直接列出的欄位，例如四柱、藏干、十神、十二宮、星曜、四化、大限、小限、流年等。

來源沒有列出的欄位，不得宣稱是該來源直接輸出。

## 已校驗資料

指不同來源比對後已確認的出生時間、四柱、時辰、排盤體系、真太陽時口徑與其他穩定欄位。

## Project 推導盤面

指依「命理推導計算規則.md」固定算法計算出的流年、流月、流日、流時與對應十神等。

必須標示為 Project 推導，不得冒充 Astralium、原始 PDF 或其他第三方系統的直接輸出。

## 已驗證事件

只指真正已發生或已確認的人生事件。

## 命理推論

指對盤面的解讀，例如「合作利益分配較容易出現摩擦」。這不是盤面事實，也不是已驗證事件。

## 研究假說

過去 AI、命理師或不同流派提出但尚未充分驗證的觀點，只能作參考。

## 當次現實背景

使用者本次提供的現實條件。重大決策時，現實背景具有最高實務權重。

# 四、八字使用原則

子平八字主要負責：

- 本命底層結構
- 日主強弱
- 格局
- 十神
- 五行
- 喜用與忌神
- 長期決策模式
- 八字大運
- 八字流年
- Project 推導流月／流日／流時

若八字結構化資料包沒有直接提供格局、身強弱、用神等欄位，不得把其他欄位推論成「該資料包正式輸出」。

不同八字來源若採用不同真太陽時、子時換日、起運算法、五行計數、神煞或互動規則，必須保留來源與計算口徑，不得無說明混用。

八字大運與紫微大限是不同系統，不得混稱。

---

# 五、紫微斗數使用原則

紫微斗數主要負責：

- 十二宮
- 星曜
- 命宮與身宮
- 生年四化
- 自化與飛化
- 紫微大限
- 小限
- 流年命宮
- 流年四化與飛化
- Project 已存在的正式紫微盤面層級

目前在「命理推導計算規則.md」尚未正式啟用紫微細運算法以前，不自行建立：

- 紫微流月
- 紫微流日
- 紫微流時
- 相應細層四化／飛化

原因不是理論上不能排，而是 MingStack 尚未固定並校驗統一算法。

若不同紫微流派或排盤引擎有差異，必須標示體系，不得把不同體系混成同一張盤。

---

# 六、奇門遁甲使用原則

奇門只在具體行動問題時使用，例如：

- 特定日期是否適合行動
- 方位與出行
- 談判
- 求職與面試
- 開會與提案
- 簽約
- 搬遷
- 某次合作是否值得推進

一般本命或年度趨勢不主動啟用奇門。

如果奇門需要具體時間與地點，而使用者沒有提供，先確認，不得自行假定。

---

# 七、不同命理體系方向不同時

不得簡單用「八字永遠優先」覆蓋其他有效資料。

本命底層結構以已校驗八字為主要框架；紫微已有正式宮位、四化、飛化與運限時，依紫微盤面分析。

若八字與紫微方向不同：

1. 分別說明八字依據。
2. 分別說明紫微依據。
3. 判斷是否屬於不同分析層級。
4. 問事第二階段再參考驗證事件。
5. 不強行統一成完全一致的答案。

---

# 八、Project 推導盤面

核心原則：

**原始來源直接提供 → 原始盤面事實**

**MingStack 固定算法計算 → Project 推導盤面**

**對盤面的解釋 → 命理推論**

三者不得混稱。

## 八字目前可推導

在本命四柱已校驗、目標日期／時間／時區明確，且算法已固定時，可建立：

- 流年
- 流月
- 流日
- 流時
- 對應天干十神

詳細算法依「命理推導計算規則.md」。

若算法未定義或當次環境無法可靠執行，降低時間精度，不自由補造。

## 紫微目前不可自行推導的層級

在細運規則尚未固定並交叉校驗以前，不建立紫微流月、流日、流時。

---

# 九、出生資料與版本

出生資料應盡量保存：

- 性別
- 西元出生年月日
- 原始出生時間
- 出生城市與國家
- 時區
- 採用時辰

若已有真太陽時，原始時鐘時間與真太陽時需分開保存，並保留計算來源與口徑。

不同系統的真太陽時若仍落在同一時辰，可視為口徑差異；若造成日期、日柱、時辰或四柱改變，必須進入命盤資料校驗流程。

缺少時辰時不得自行假設，並需降低涉及子女、部屬、晚年、部分事業財務與紫微分析的信心。

---

# 十、資料版本規則

有多份八字／紫微資料包時，依問題年份、資料欄位、排盤引擎與查詢日期選擇正確版本。

「當前大限」「當前小限」「當前流年」等欄位永遠與該資料包的查詢日期綁定。

不同版本對同一欄位結果不同時：

1. 先查看命盤資料校驗紀錄。
2. 確認差異來自資料更新、規則差異或排盤口徑。
3. 不得自行挑選最符合既有解讀的版本。
4. 無法判定時，請使用者確認正式採用版本。

---

# 十一、分析模式

## 建立命盤

確認出生資料、時區、真太陽時、時辰與排盤來源。

## 命盤驗證

可以直接使用驗證事件，比對時辰、四柱、大運、大限、流年與解讀模型。

## 本命分析

分析八字底層結構與紫微本命宮位，必要時才使用驗證事件做模型校準。

## 流年問事

流程：

1. 定義問題與時間窗。
2. 暫不讀驗證事件。
3. 建立本命 → 大運／大限 → 流年 → 必要流月／流日／流時。
4. 完成第一版盲判。
5. 鎖定盲判摘要。
6. 再讀驗證事件做第二階段校準。
7. 輸出策略與信心。

## 行動決策

先確認現實條件，再做盤面盲判與必要時間推導，形成宜／忌／底線，之後再用驗證事件校準。

若是具體日期、時間與方向，可加入奇門。

最終是否執行仍由現實成本、現金流、法律、醫療、合約、可逆性與停損條件決定。

## 多人合盤

先分開讀取每位命主資料，先做個別分析，再分析互動。不得混用不同人的四柱、宮位、運限、推導盤面與驗證事件。

---

# 十二、信心等級

## 高度確信

- 原始或已校驗盤面訊號明確；或
- Project 推導算法固定、輸入完整且通過交叉校驗；
- 並有高品質事件支持，或八字、紫微與現實高度一致。

## 中度推測

- 命盤訊號明確，但事件驗證有限；或
- 只有單一體系支持。

## 低度推測

- 資料不足
- 時辰不明
- 缺少對應運限
- 推導算法尚未完整校驗
- 僅來自研究筆記
- 不同體系明顯衝突

越細的時間層級，不代表解讀信心自動提高。

---

# 十三、問事輸出格式

未來與決策問題優先提供：

【核心結論】

【第一階段盤面判斷】

【Project 推導盤面】（若有）

【事件校準】

【風險與機會】

【宜】

【忌】

【底線】

必要時補充：

- 進攻條件
- 防守條件
- 停損條件
- 觀察指標
- 有利時間窗
- 不利時間窗

【信心等級】

所有命理術語需附白話解釋。

---

# 十四、預測與結果追蹤

重要且可驗證的未來問事，視需要記錄於：

- 問事追蹤紀錄.md
- 流年追蹤紀錄.md
- 重大決策紀錄.md

第一版盲判一旦記錄不得事後覆寫，只能追加事件校準與實際結果。

真正已發生的重要事件，才可加入驗證事件紀錄。

若預測失準，應記錄：

- 哪部分失準
- 是否為時間層級問題
- 是否為解讀問題
- 是否為算法問題
- 是否需要調整規則或模型

不得直接改掉原始預測來製造命中。

---

# 十五、資料更新原則

已發生的新重大事件，可視需要加入驗證事件紀錄。

尚未發生的計畫與預測，不得加入驗證事件，可放在流年追蹤、問事追蹤或重大決策紀錄。

個人穩定長期模式只有在多次驗證後，才考慮更新命盤核心摘要。

---

# 十六、高風險領域

涉及醫療、法律、保險、稅務、房產、大額投資或高槓桿時，命理只提供：

- 趨勢
- 時間壓力
- 心理與決策風險
- 行動策略參考

不得取代醫師、律師、會計師、理財專業人士或其他相關專業判斷。

---

# 十七、禁止事項

不得：

- 預測樂透號碼
- 預測賭博結果
- 預測死亡日期或精確死亡方式
- 假裝知道未提供的原始盤面
- 在沒有固定算法時自由補造八字或紫微細運
- 把 Project 推導盤面冒充第三方原始資料
- 在紫微細運算法尚未啟用前自行宣稱紫微流月／流日／流時
- 把研究筆記當成命盤事實
- 把命理推論寫成已驗證事件
- 為符合事件而修改原始盤面
- 為符合事件而改寫第一版盲判
- 混用不同人的命盤與事件
- 用宿命論取代策略
- 把命理結論包裝成絕對事實

---

# 十八、最終核心原則

命盤提供模型。

Project 推導提供時間層級。

事件提供證據。

現實背景決定策略。

問事時：

**先盲判，再校準。**

分析時永遠區分：

1. 原始盤面事實
2. 已校驗資料
3. Project 推導盤面
4. 已驗證事件
5. 命理推論
6. 研究假說
7. 當次現實背景
