# 紫微流時推導規則

- 規則版本：v1.0-exp
- Capability：`ziwei.flow_hour_palaces`
- 狀態目標：`implemented / experimental / on_demand`
- 分類：Project 推導盤面
- 適用範圍：流時命宮定位、流時十二宮重排

## 一、定位

本規則只處理紫微斗數的「流時命宮定位」與「流時十二宮重排」。

它不處理民用 datetime、時區、DST、國曆轉農曆、23:00 換日、早子／晚子 policy、流時天干、流時四化、流曜、細層飛化或 Cross-System Validation。

核心原則：

> 上游先確認「這是哪一個農曆日、哪一個時辰地支」，flow-hour core 再做固定命理公式。

## 二、Project 固定算法

十二地支索引固定為：

```text
子 = 0
丑 = 1
寅 = 2
卯 = 3
辰 = 4
巳 = 5
午 = 6
未 = 7
申 = 8
酉 = 9
戌 = 10
亥 = 11
```

先由正式 `engine.ziwei.day` 取得目標日期的流日命宮，再用時辰地支 offset 推導流時命宮：

```text
flow_hour_index
= (flow_day_index + hour_branch_index) mod 12
```

白話：

- 流日命宮就是子時的流時命宮。
- 丑時順行一宮。
- 寅時順行兩宮。
- 之後每一時辰順行一宮。
- 亥時為順行十一宮。
- 超過十二宮後循環。

取得流時命宮後，十二宮排列直接共用：

```python
palaces_from_ming_branch(flow_hour_ming_branch)
```

不得在 `hour.py` 再複製另一套十二宮方向算法。

## 三、輸入責任邊界

flow-hour core 只接受已確認的：

```text
birth_lunar_month
birth_hour_branch
flow_year_branch
lunar_month
lunar_day
is_leap_month
hour_branch
```

`hour_branch` 必須是 `子丑寅卯辰巳午未申酉戌亥` 之一。

以下輸入不得由 core 自行猜測或轉換：

```text
14:00
下午兩點
2pm
2026-09-18 23:30
```

若呼叫端只有民用時間，必須先經Calendar Resolver v1 或其他可信上游解析。

## 四、日界與子時政策

本 capability 不定義民用時鐘的換日規則。

例如上游已提供：

```text
lunar_day = 初八
hour_branch = 子
```

flow-hour core 就把它視為「初八子時」，不自行改成初九。

23:00–00:59 的日期歸屬屬於 Resolver 的 `day-boundary policy`。未來若支援不同流派，必須以可測試的明確時間區間與日期歸屬版本化，不得只寫「早子派」「晚子派」而沒有精確規則。

## 五、閏月處理

flow-hour 不另外建立閏月算法。

它完全繼承 `engine.ziwei.day` 已固定的結果：

1. 流月先依 Project 規則處理閏月前半／後半。
2. 流日用實際 `lunar_day - 1` 推進。
3. 流時只在既有流日命宮上加時辰 offset。

因此流時不得在農曆十六日重新重置日數，也不得自行重做流月或流日的閏月判定。

## 七、Experimental 判定

PR #3 完成後第一版固定標示：

```text
implementation = implemented
maturity = experimental
routing = on_demand
rule_version = 1.0-exp
```

理由：

- 核心公式固定且可重現。
- 有固定第三方程式碼與獨立公開文字來源交叉支持。
- 仍未包含 Calendar Resolver 的日界政策驗證。
- 尚未累積足夠的真實邊界案例與長期 Issue 驗證。

因此 Experimental 輸出分析時需降權，不能單獨支撐「高度確信」。

## 八、調用時機

只有下列情況才按需調用：

- 使用者明確指定某個時辰。
- 比較同一天兩個以上時段。
- 流日主軸已確定，需要提高到時辰解析度。
- 未來 Cross-System Validation 需要 hour-level evidence。
- 具體面試、談判、會議、簽約、出行等時段比較。

一般本命、年度、月份，或只是詢問「某一天如何」時，不自動遍歷十二時辰。

## 九、明確未實作

本規則不代表以下能力存在：

- 流時天干
- 流時四化
- 流曜
- 細層飛化
- 國曆轉農曆
- timezone / DST
- 23:00 換日 policy
- Cross-System Validation

這些能力須由後續獨立 capability / infrastructure PR 固定算法與驗證後再啟用。


## 十、Calendar Resolver 現況

Calendar Resolver v1 已實作，負責 neutral civil/calendar context；本流時定位 core 不負責紫微 23:00 日界 policy。
