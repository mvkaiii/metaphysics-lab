1. 由出生資料建立 **Project 原生盤面** 的 Natal Chart Foundation。

# 一、Phase 2C0 Natal Chart Foundation

## 1.1 輸入契約

完整出生資料 Mode A 最低輸入：

- sex
- Gregorian birth date
- birth time
- birth place

Location Resolver 將 birthplace name 解析為 label、latitude、longitude、IANA timezone 與 provenance；Calendar Resolver 再接受 structured local civil datetime + timezone。

固定原則：

> **Precision must be earned by input.**

輸入不足或不唯一時，只能追問、保留候選或降級分析，不得自行補值。

已知四柱 Mode B 只能建立 Bazi imported/external natal view；不得用四柱反推唯一出生日期／時間，也不得重建完整 Ziwei natal。

Astralium 或其他結構化第三方資料 Mode C 視為 external view；Project 仍可依出生資料獨立重算，兩者進 reconciliation，不互相覆寫。

## 1.2 時間 views

Shared civil base 必須保留，不做全域真太陽時覆寫。至少保留：

```text
reported_civil_time
normalized_civil_time
bazi_effective_time
ziwei_effective_time
```

必要時另保存 true-solar calculation record、adjustment minutes、profile_id、rule_version、calculation_basis、provenance。

**Calendar Resolver 不負責真太陽時。** 它維持 neutral civil/calendar infrastructure；civil date 於 00:00 換日，23:00 已屬子時但不由 Resolver 套用命理 effective-day policy。

## 1.3 真太陽時

Phase 2C0 的真太陽時計算口徑固定記錄為：

> **真太陽時＝經度校正＋均時差**

概念上：

```text
true_solar_adjustment = longitude_correction + equation_of_time
true_solar_time = normalized_civil_time + true_solar_adjustment
```

此公式由 `engine/birth/time_views.py` 的 versioned profile 實作與測試；不得在文字層自由重算。

八字與紫微 time profile **獨立**：

- Bazi Natal v1 採自己的 Project profile，civil effective time 與 true-solar candidate 分開比較；若兩者四柱相同可視為 EQUIVALENT，若跨日柱／時柱等實質邊界則標記 material conflict，不得靜默選邊。
- Ziwei Natal v1 default profile 為 `ziwei-natal-true-solar-common-v1`，會由 Project 自動套用上述真太陽時校正；普通使用者不需自行選「要不要真太陽時」。原始 civil time 永遠保留。

真太陽時差異只有在造成實質盤面差異時才需要突出顯示；未跨時辰／日期等核心邊界時，普通 UX 可只顯示已校正且未改盤。

正式 capability：

```

Project Bazi Natal v1 deterministic facts 包含：

## 1.5 Project Ziwei Natal

```

## 1.6 External / Project / Resolved

本命 cross-system model 固定三層：

```text
External / Project / Resolved
```

reconciliation status：

```text
MATCH / EQUIVALENT / CONFLICT / NOT_COMPARABLE
```

severity：

```text
INFO / CAUTION / BLOCKING
```

External / Project raw view 不得覆寫。Experimental authority 若與 external 衝突，Resolved 預設採 external；未來 capability 經正式 promotion 為 Stable 後可改採 Project，但 CONFLICT 本身不能被消掉。

Astralium 為可選 external qualification source，不是 runtime dependency。

# 二、八字 Project 推導盤面

## 2.1 流年

八字流年以立春交接時刻切換：立春前屬前一干支年，立春後進入新干支年，不以 1 月 1 日切換。

Project 內建太陽視黃經為自包含近似演算法；距離算得交界 15 分鐘內必須產生 boundary warning，使用可信節氣來源覆核後才可做高精度結論。

## 2.2 流月

八字流月採十二節，不以國曆每月 1 日切換：

| 月支 | 起點 | 太陽視黃經 |
|---|---|---:|
| 丑 | 小寒 | 285° |
| 寅 | 立春 | 315° |
| 卯 | 驚蟄 | 345° |
| 辰 | 清明 | 15° |
| 巳 | 立夏 | 45° |
| 午 | 芒種 | 75° |
| 未 | 小暑 | 105° |
| 申 | 立秋 | 135° |
| 酉 | 白露 | 165° |
| 戌 | 寒露 | 195° |
| 亥 | 立冬 | 225° |
| 子 | 大雪 | 255° |

五虎遁：

- 甲己年丙寅起
- 乙庚年戊寅起
- 丙辛年庚寅起
- 丁壬年壬寅起
- 戊癸年甲寅起

## 2.3 流日

固定流程：

**Gregorian effective civil date → Julian Day Number → 六十甲子日序**

Project Bazi flow-time profile 採 23:00 early-Zi：

- 22:59 仍算當日
- 23:00 起八字有效日期前進一天
- 00:00 不 double-rollover

固定索引：

```text
offset = JDN - 11
day_stem_index = offset mod 10
day_branch_index = offset mod 12
```

## 2.4 流時

時支：子 23:00–00:59、丑 01:00–02:59，之後每兩小時一支，亥為 21:00–22:59。

五鼠遁以已完成八字有效日期處理的日干為基準：

```text
時干索引 = (日干索引 mod 5 × 2 + 時支索引) mod 10
```

## 2.5 十神

流年／月／日／時天干十神一律以本命日主為參照，不得把流日天干當成新的日主。

# 三、紫微時間能力

## 3.1 流月定位

```text
implemented / stable / default
```

採農曆月。一般月份初一換月；閏月初一至十五歸原月，十六起歸下一月。八字流月採節氣月，兩者不同步不是 bug。

## 3.2 流日定位

```text
implemented / experimental / on_demand
```

流月命宮作農曆初一流日命宮，每日順行一宮，十二宮循環。是否升 Stable 只依版本化 qualification，不因單一事件吻合升級。

## 3.3 流時定位

```text
implemented / experimental / on_demand
rule_version = 1.0-exp
```

固定公式：

```text
flow_hour_index = (flow_day_index + hour_branch_index) mod 12
```

流日命宮作子時流時命宮，之後每個時辰順行一宮。

# 五、Calendar / Location 責任邊界

Location Resolver：出生地名稱 → geocoding candidates → latitude / longitude / IANA timezone / provenance。多個 material candidates 必須 fail closed，不猜地點。

Calendar Resolver：structured local civil datetime + IANA timezone → neutral `CalendarContext`。處理 timezone、DST、Gregorian→Lunar、civil hour branch 與 calendar validation；**Calendar Resolver 不負責真太陽時**，也不決定 Bazi／Ziwei 命理日界。

Bazi Natal Time Adapter 與 Ziwei Natal Time Adapter 再依各自 profile 產生 `bazi_effective_time` 與 `ziwei_effective_time`。

未來事件的時間應使用事件實際發生地與對應體系規則；不得把出生盤真太陽時校正直接套到所有未來事件。

相同 structured input + 相同 profile/rule version 必須產生相同 structured chart；相同 structured natal + 相同 generated date 必須產生 byte-identical canonical Markdown。

Markdown exporter 只序列化已存在的 deterministic facts，不重新排盤、不猜 missing fields、不自動加入格局／喜忌／性格等命理解讀。
