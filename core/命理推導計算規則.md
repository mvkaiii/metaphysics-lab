- 文件版本：v1.1

- Project 計算引擎：Project Bazi Calendar Engine v1.0.0
- 參考引擎：6tail/lunar-python v1.4.8（commit `000c8a3`）
- 程式實作：`project_bazi_calendar.py`

## 文件定位

本文件規範 MingStack 的「Project 推導盤面」算法。

目的不是取代 Astralium、原始 PDF 或其他第三方排盤來源，而是讓 Project 在第三方資料未提供細部運限時，仍可使用固定、可重現的算法建立衍生盤面。

核心原則：

> 原始來源直接提供的資料，稱為「原始盤面事實」。
>
> 本 Project 依固定算法計算的資料，稱為「Project 推導盤面」。
>
> 對盤面的解釋，稱為「命理推論」。

三者不得混稱。

# 四、年度切換規則

八字流年以「立春」交接時刻作為年度切換基準。

也就是：

- 立春前仍屬前一干支年
- 立春後進入新干支年

不得單純以國曆 1 月 1 日作為八字流年切換點。

Project 引擎以太陽視黃經 315° 的交點估算立春時刻。

若問題時間距離 Project 算出的立春交界 15 分鐘內，必須改用可信節氣來源做外部交叉確認後，才可下高精度結論。

---

# 五、流月切換規則

八字流月採「十二節」切換，不以國曆每月 1 日切換。

| 月支 | 起點 | 太陽視黃經 |
|---|---|---:|
| 丑 | 小寒 | 285° |
| 寅 | 立春 | 315° |
| 卯 | 驚蟄 | 345° |
| 辰 | 清明 | 15° |
| 巳 | 立夏 | 45° |
| 午 | 芒種 | 75° |
| 未 | 小暑 | 105° |
| 申 | 立秋 | 135° |
| 酉 | 白露 | 165° |
| 戌 | 寒露 | 195° |
| 亥 | 立冬 | 225° |
| 子 | 大雪 | 255° |

月份切換以目標所在地時區下的實際交接時間判定。

## 節氣計算方式

`project_bazi_calendar.py` 使用 Meeus／NOAA 類型的太陽視黃經近似公式，求太陽通過上述目標黃經的時間。

這套公式適合一般流月分類，但不是天文台級星曆。

因此 Project 固定加入以下保護規則：

- 距離算得的「節」交界超過 15 分鐘：可正常使用 Project 推導流月
- 距離交界 15 分鐘內：標示 boundary warning
- boundary warning 出現時：必須用可信節氣表或正式曆法引擎交叉確認

不得在交界附近假裝有不存在的分鐘級精度。

# 六、流月天干：五虎遁

以流年天干決定寅月月干：

- 甲、己年：丙寅起
- 乙、庚年：戊寅起
- 丙、辛年：庚寅起
- 丁、壬年：壬寅起
- 戊、癸年：甲寅起

之後每月天干依十天干順序推進一位，地支依寅、卯、辰……順排。

例如丙年：

- 寅月：庚寅
- 卯月：辛卯
- 辰月：壬辰
- 巳月：癸巳
- 午月：甲午
- 未月：乙未
- 申月：丙申
- 酉月：丁酉

# 七、流日算法

Project 流日不再採「萬年曆、函式庫、手算三選一」。

正式固定為：

**Gregorian civil date → Julian Day Number → 六十甲子日序**

## 計算流程

1. 依事件所在地的當地日期取得 Gregorian 年月日
2. 若當地時間已達 23:00，先將「八字有效日期」推進一天
3. 計算該有效日期中午的 Julian Day Number（JDN）
4. 使用固定 offset：

`offset = JDN - 11`

5. 日干索引：

`offset mod 10`

6. 日支索引：

`offset mod 12`

此邏輯與 6tail/lunar-python v1.4.8 的日干支核心索引規則相符。

## Project 子時換日

Project 採：

**23:00 換日。**

也就是：

- 22:59 仍算當日
- 23:00 起日柱前進一天
- 23:00–00:59 為新日子時

此口徑與目前八字結構化資料包的「早子時（23:00 換日）」設定一致。

# 八、流時算法

## 時支

- 子：23:00–00:59
- 丑：01:00–02:59
- 寅：03:00–04:59
- 卯：05:00–06:59
- 辰：07:00–08:59
- 巳：09:00–10:59
- 午：11:00–12:59
- 未：13:00–14:59
- 申：15:00–16:59
- 酉：17:00–18:59
- 戌：19:00–20:59
- 亥：21:00–22:59

## 時干：五鼠遁

以已完成 23:00 換日處理的「當日日干」為基準：

- 甲、己日：甲子起
- 乙、庚日：丙子起
- 丙、辛日：戊子起
- 丁、壬日：庚子起
- 戊、癸日：壬子起

程式索引公式：

`時干索引 = (日干索引 mod 5 × 2 + 時支索引) mod 10`

# 十五、節氣精度限制

目前內建太陽視黃經算法是「自包含、可重現」方案，但不是精密星曆。

已知交叉檢查：

- 1984 立春：Project 約 23:25:50；公開節氣表約 23:21
- 2026 立春：Project 約 03:55:56 Asia/Taipei；日本國立天文台資料換算約 04:02 Asia/Taipei

誤差約數分鐘。

因此：

- 一般日期的流月判定可正常使用
- 接近節氣交界 15 分鐘內不得直接下定論
- 必須使用權威節氣資料覆核

此限制只影響「節氣交界附近的流年／流月切換」，不影響一般日期的 JDN 流日與五鼠遁流時算法。
