# 四、年度切換規則

八字流年以「立春」交接時刻作為年度切換基準。

也就是：

- 立春前仍屬前一干支年
- 立春後進入新干支年

不得單純以國曆 1 月 1 日作為八字流年切換點。

Project 引擎以太陽視黃經 315° 的交點估算立春時刻。

若問題時間距離 Project 算出的立春交界 15 分鐘內，必須改用可信節氣來源做外部交叉確認後，才可下高精度結論。

## 節氣計算方式

`engine/bazi/calendar.py` 使用 Meeus／NOAA 類型的太陽視黃經近似公式，求太陽通過上述目標黃經的時間。

這套公式適合一般流月分類，但不是天文台級星曆。

因此 Project 固定加入以下保護規則：

- 距離算得的「節」交界超過 15 分鐘：可正常使用 Project 推導流月
- 距離交界 15 分鐘內：標示 boundary warning
- boundary warning 出現時：必須用可信節氣表或正式曆法引擎交叉確認

不得在交界附近假裝有不存在的分鐘級精度。

# 七、八字流日算法

Project 八字流日不再採「萬年曆、函式庫、手算三選一」。

正式固定為：

**Gregorian civil date → Julian Day Number → 六十甲子日序**

## 計算流程

1. 依事件所在地的當地日期取得 Gregorian 年月日
2. 若當地時間已達 23:00，先將「八字有效日期」推進一天
3. 計算該有效日期中午的 Julian Day Number（JDN）
4. 使用固定 offset：

`offset = JDN - 11`

5. 日干索引：

`offset mod 10`

6. 日支索引：

`offset mod 12`

此邏輯與 6tail/lunar-python v1.4.8 的日干支核心索引規則相符。

## Project 子時換日

Project 採：

**23:00 換日。**

也就是：

- 22:59 仍算當日
- 23:00 起日柱前進一天
- 23:00–00:59 為新日子時

此口徑與目前八字結構化資料包的「早子時（23:00 換日）」設定一致。

# 十、時區與地點

## 八字原則

流月／流日／流時使用「事件實際發生地」的當地時間與時區。

例如：

- 台北談判 → Asia/Taipei
- 東京面試 → Asia/Tokyo
- 紐約簽約 → America/New_York

不得一律使用出生地時間。

## 紫微流日輸入

目前紫微流日引擎不自行做國曆轉農曆，也不自行宣稱未固定的紫微換日口徑。

輸入的 `lunar_month`、`lunar_day`、`is_leap_month` 必須先由可信曆法來源確認。若未來 router 直接接受國曆時間，國曆→農曆與換日規則必須另行固定、測試與版本化。

## 紫微流時輸入

紫微流時引擎同樣不接受民用 datetime 作為核心算法輸入。除流日所需的農曆月／日／閏月狀態外，還必須由可信上游提供 `hour_branch`。

`hour.py` 不處理 timezone、DST、國曆轉農曆或 23:00 日界，也不自行決定早子／晚子口徑。這些責任留給版本化的 Calendar / Input Resolver。

不得把本命真太陽時校正直接套用到所有未來事件時間。

# 十五、節氣精度限制

目前內建太陽視黃經算法是「自包含、可重現」方案，但不是精密星曆。

已知交叉檢查：

- 1984 立春：Project 約 23:25:50；公開節氣表約 23:21
- 2026 立春：Project 約 03:55:56 Asia/Taipei；日本國立天文台資料換算約 04:02 Asia/Taipei

誤差約數分鐘。

因此：

- 一般日期的八字流月判定可正常使用
- 接近節氣交界 15 分鐘內不得直接下定論
- 必須使用權威節氣資料覆核

此限制只影響「八字節氣交界附近的流年／流月切換」，不影響一般日期的 JDN 八字流日與五鼠遁流時算法。

紫微流日與流時另依可信農曆／時辰輸入及各自專用規則檔的邊界，不套用八字 23:00 換日或節氣月份規則。

# 十七、紫微流月、流日、流時與其他細運邊界

## Stable / Default：紫微流月

紫微流月定位已由 `紫微流月推導規則.md` 固定：

- 流派：斗君流月
- 月份：農曆月
- 一般月份：初一換月
- 閏月：初一至十五歸原月、十六起歸下一月
- 輸出：斗君、流月命宮、流月十二宮重排

正式程式：`engine/ziwei/month.py`。

## Experimental / On-demand：紫微流日

紫微流日定位已由 `紫微流日推導規則.md` 固定第一版：

- 先取得目標日期的流月命宮
- 流月命宮作農曆初一流日命宮
- 每日沿地支順行一宮
- 十二宮循環
- 閏月先依流月拆半，再使用實際 `lunar_day - 1` 推進

正式程式：`engine/ziwei/day.py`。

Capability：

```text
implemented / experimental / on_demand
```

目前只包含流日命宮與流日十二宮定位；不包含流日四化、流曜或細層飛化。

## Experimental / On-demand：紫微流時

紫微流時定位已由 `紫微流時推導規則.md` 固定第一版：

- 先取得目標日期的流日命宮
- 流日命宮作子時流時命宮
- 每一時辰沿地支順行一宮
- 十二宮循環
- 閏月與日數完全繼承 day engine，不重新判定

正式程式：`engine/ziwei/hour.py`。

Capability：

```text
implemented / experimental / on_demand
```

目前只包含流時命宮與流時十二宮定位；不包含流時天干、流時四化、流曜、細層飛化或民用時間 Resolver。

## 尚未實作

未來若要開放細部四化、流曜、細層飛化或 Calendar / Input Resolver，必須另外固定：

- 流曜規則

- 大限／流年／流月／流日／流時疊盤方式
- 交叉校驗與版本管理

完成前，不把這些層級列為 Project 正式推導功能。

# 十八、來源與校驗基準

## 6tail/lunar-python

- Repository：`https://github.com/6tail/lunar-python`
- 固定參考版本：v1.4.8
- 固定參考 commit：`000c8a3`

用途：

- 交叉確認節氣／八字設計方式
- 交叉確認流月依節氣交接
- 交叉確認 JDN 日干支索引
- 交叉確認 23:00 日界分支
- 交叉確認時干索引

## iztro（紫微流日／流時）

固定程式參考 commit：`814b77e6371e1050cac31bbf674db3c3138fcfde`。

流日固定程式公式：

```text
dailyIndex = fixIndex(monthlyIndex + lunarDay - 1)
```

流時固定程式公式：

```text
hourlyIndex = fixIndex(dailyIndex + hourBranchIndex)
```

紫微流時另以獨立公開文字來源交叉支持「流日命宮起子時、順數定流時命宮」。詳細來源層級與限制依 `紫微流時推導規則.md`，不得以本摘要宣稱所有紫微流派完全一致。

## 太陽視黃經

Project 自包含節氣計算採 Meeus／NOAA 類型的太陽視黃經近似公式。

用途僅為八字流年／流月交界計算。

## 權威節氣覆核

節氣交界附近可使用國立天文台等可信星曆資料覆核。

# 十九、最終原則

Project 可以自行計算，但必須：

- 算法固定
- 程式版本固定
- 輸入清楚
- 結果可重現
- 來源標示
- Capability 狀態可追溯
- 與原始盤面分開
- 與命理解讀分開
- 邊界精度不足時主動降級

能力是否存在、成熟度與是否預設執行必須分開管理。

若算法未定義或當次無法可靠執行：

**降低精度，不自由補造。**
