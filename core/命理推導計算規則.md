# 一、Phase 2C0 Natal Chart Foundation

## 1.1 輸入契約

完整出生資料 Mode A 最低輸入：

- sex
- Gregorian birth date
- birth time
- birth place

Location Resolver 將 birthplace name 解析為 label、latitude、longitude、IANA timezone 與 provenance；Calendar Resolver 再接受 structured local civil datetime + timezone。

固定原則：

> **Precision must be earned by input.**

輸入不足或不唯一時，只能追問、保留候選或降級分析，不得自行補值。

已知四柱 Mode B 只能建立 Bazi imported/external natal view；不得用四柱反推唯一出生日期／時間，也不得重建完整 Ziwei natal。

Astralium 或其他結構化第三方資料 Mode C 視為 external view；Project 仍可依出生資料獨立重算，兩者進 reconciliation，不互相覆寫。

## 1.2 時間 views

Shared civil base 必須保留，不做全域真太陽時覆寫。至少保留：

```text
reported_civil_time
normalized_civil_time
bazi_effective_time
ziwei_effective_time
```

必要時另保存 true-solar calculation record、adjustment minutes、profile_id、rule_version、calculation_basis、provenance。

**Calendar Resolver 不負責真太陽時。** 它維持 neutral civil/calendar infrastructure；civil date 於 00:00 換日，23:00 已屬子時但不由 Resolver 套用命理 effective-day policy。

## 1.3 真太陽時

Phase 2C0 的真太陽時計算口徑固定記錄為：

> **真太陽時＝經度校正＋均時差**

概念上：

```text
true_solar_adjustment = longitude_correction + equation_of_time
true_solar_time = normalized_civil_time + true_solar_adjustment
```

此公式由 `engine/birth/time_views.py` 的 versioned profile 實作與測試；不得在文字層自由重算。

八字與紫微 time profile **獨立**：

- Bazi Natal v1 採自己的 Project profile，civil effective time 與 true-solar candidate 分開比較；若兩者四柱相同可視為 EQUIVALENT，若跨日柱／時柱等實質邊界則標記 material conflict，不得靜默選邊。
- Ziwei Natal v1 default profile 為 `ziwei-natal-true-solar-common-v1`，會由 Project 自動套用上述真太陽時校正；普通使用者不需自行選「要不要真太陽時」。原始 civil time 永遠保留。

真太陽時差異只有在造成實質盤面差異時才需要突出顯示；未跨時辰／日期等核心邊界時，普通 UX 可只顯示已校正且未改盤。

# 二、八字 Project 推導盤面

## 2.1 流年

八字流年以立春交接時刻切換：立春前屬前一干支年，立春後進入新干支年，不以 1 月 1 日切換。

Project 內建太陽視黃經為自包含近似演算法；距離算得交界 15 分鐘內必須產生 boundary warning，使用可信節氣來源覆核後才可做高精度結論。

## 2.2 流月

八字流月採十二節，不以國曆每月 1 日切換：

- 甲己年丙寅起
- 乙庚年戊寅起
- 丙辛年庚寅起
- 丁壬年壬寅起
- 戊癸年甲寅起

## 2.3 流日

固定流程：

**Gregorian effective civil date → Julian Day Number → 六十甲子日序**

Project Bazi flow-time profile 採 23:00 early-Zi：

- 22:59 仍算當日
- 23:00 起八字有效日期前進一天
- 00:00 不 double-rollover

固定索引：

```text
offset = JDN - 11
day_stem_index = offset mod 10
day_branch_index = offset mod 12
```

## 2.4 流時

時支：子 23:00–00:59、丑 01:00–02:59，之後每兩小時一支，亥為 21:00–22:59。

五鼠遁以已完成八字有效日期處理的日干為基準：

```text
時干索引 = (日干索引 mod 5 × 2 + 時支索引) mod 10
```

## 2.5 十神

流年／月／日／時天干十神一律以本命日主為參照，不得把流日天干當成新的日主。

## 10.1 責任邊界

Selector 只回答最近歷史流年中「盤面結構互動相對強弱」，不直接預測某年必然離職、結婚、疾病或其他具體事件。

- **Python**：建立最近10個 eligible flow-year periods、計算 evidence、去重／suppression、排序、選出 canonical 4 High + 1 Control、產生 digest。
- **AI**：只能在 Python 選年後解讀可能活躍領域與事件形式；不得選年、換年、重排或用已知歷史事件改 selector truth。
- **使用者**：驗證／訂正實際事件。

Selector payload 不接受 `preferred_years`、`known_event_years`、`event_keywords`、`manual_rank_override` 等 history-based ranking hints。

## 10.2 十年視窗

ranking unit 固定為 Bazi flow-year period，以立春交接時刻為界：

```text
label_year   = 該流年期起始立春所在 Gregorian year
period_start = 該年立春交接時刻
period_end   = 下一年立春交接時刻
```

只取 `as_of_datetime` 前最近10個**已完整結束**的流年期。未走完的當前流年不進第一次 Historical Blind Calibration canonical window。

## 10.3 Tier 定義

方向固定：

```text
Tier 1 = 核心強訊號
Tier 2 = 中度支持訊號
Tier 3 = 輔助訊號
```

Tier 是 activation strength，不是吉凶。

### Tier 1

- `decadal_boundary`：八字大運交界落在該流年期。
- `sui_yun_bing_lin`：流年完整干支與當時大運完整干支相同。
- `natal_pillar_repeat`：流年完整干支伏吟本命任一柱。
- `branch_clash_natal`：流年支與本命任一支六沖。
- `branch_clash_decadal`：流年支與當時大運支六沖。
- `completes_three_harmony`：流年支加入後補成完整三合。
- `completes_three_meeting`：流年支加入後補成完整三會。
- `completes_three_punishment`：流年支加入後補成寅巳申或丑戌未完整三刑。

### Tier 2

- `branch_six_harmony`：六合。
- `partial_three_harmony`：三合半組／待補完整。
- `partial_three_meeting`：三會半組／待補完整。
- `branch_punishment_support`：pairwise 刑／自刑。
- `branch_repeat`：單支伏吟，且未被完整柱伏吟／歲運並臨吸收。
- `stem_combination`：天干五合。

### Tier 3

- `branch_harm`：六害。
- `branch_break`：六破。
- `stem_repeat`：天干同干，且未被完整柱伏吟／歲運並臨吸收。

固定 relation tables 由 `engine/historical/relations.py` version control；一般五行生剋、十神名稱、喜用神、格局分數、神煞、天干沖與 AI 主觀重要度不進 v1 ranking。

## 10.4 Suppression / dedup

同一結構不得灌水：

- 歲運並臨吸收同一 decadal target 的 lower-tier stem/branch repeat。
- 本命完整柱伏吟吸收同一 natal component 的 lower-tier stem/branch repeat。
- 完整三合／三會／三刑形成時，對應 partial pattern 不再重複計數。
- 同一 canonical pattern 即使本命有重複支，也只記一組 pattern evidence。

## 10.5 Ranking

v1 不使用0～100黑箱分數。每年建立 rank vector：

```text
tier1_family_count
tier1_evidence_count
cross_layer_tier1
tier2_family_count
tier2_evidence_count
tier3_family_count
tier3_evidence_count
label_year
```

由上到下 lexicographic descending。`label_year` 只在盤面 evidence 完全同分時作 deterministic tie-break，較近年份優先。

真正排序完成後：

```text
High Years = Top 4
Control    = Bottom 1
```

不得為了年份分散、避免連續、跨大運、聊天內容或已知事件而人工換年。

```text

  Tier 1 family = 0 且 Tier 2 family = 0

  Tier 1 family = 0 且 Tier 2 family > 0
```

`relative_low` 只能稱「近十年相對最低」，不得說成真正穩定年。

## 10.8 Historical Blind Calibration 時間評價

使用者回報實際事件時，以實際日期映射到 Li-Chun flow-year period；不能只比較 Gregorian year label。

例如預測 `2016流年`，若實際事件發生在2017年1月且仍位於2016立春～2017立春前，時間評價仍是 `exact_flow_year`，不是機械式 `shifted +1`。

若使用者只記得粗略年份，且可能跨立春邊界，標 `unscorable_or_ambiguous`；不得逼使用者亂填月份。

## 10.9 可重現性與版本治理

相同 normalized natal + 相同 `as_of_datetime` + 相同 timezone + 相同 profile/rule version 必須產生相同10年 ranking、canonical 4+1 與 `selection_digest`。

歷史事件 ground truth 不得回流改寫同次 selection。未來修改 Tier family、relation table、suppression 或 ranking priority 時，必須升 profile/rule version，不能靜默改 v1。

# 十一、Phase 3.5 Cold-start Structural Interpretation

正式 capability：

```text
distribution.structural_interpretation = implemented / experimental / on_demand
structural_profile = lin_tianji_structural_v1-exp
mapping_profile = lin_tianji_domain_v2-exp
classification = Project 推導盤面
ranking_authority = false
```

Phase 3.5 只把已 materialized 的 deterministic Bazi / Ziwei structural facts 轉成 `EvidenceFeature`。八字使用中立 structural relation truth、當前已存大運、本命四柱與目標 scope；紫微使用 materialized flowing-star category、宮位 ownership、transformation / flying edge 與 geometric provenance。Phase 3 ranker 仍是唯一 ranking authority，`lin_tianji_rank_v1-exp` 的 domain ownership gate、dependency de-dup、specificity ceiling 與 ranking digest 不由本層修改。

三條硬邊界固定如下：

1. **Zero-history usable baseline**：完全沒有 historical event material 時，`resolve_forecast_context → interpret_structural_evidence → rank_evidence` 仍必須產生 deterministic、non-empty、可追溯的 cold-start baseline。
2. **Activation strength ≠ probability / 吉凶**：`weak / moderate / strong` 只代表已版本化 structural activation，不代表事件機率、好壞或必然結果；relation 不得直接翻成離職、破產、結婚等 concrete event。
3. **Historical Personalization only after base ranking**：歷史資料只能在 cold-start evidence 與 Phase 3 base ranking 完成後做個人化排序修正；不得回頭改 deterministic chart、Phase 3.5 structural evidence 或 base ranking digest。

Phase 3.5 public payload 不接受 `historical_records`、`actual_event`、`known_event_years` 等 outcome/history material。已驗證事件不得成為當期訊號來源，也不得拿來調整 closed semantic mapping 或 structural strength class。

`build_evidence_features()` 保留為 compatibility wrapper，但正式 semantic authority 與 `interpret_structural_evidence` 共用同一 v2 Structural Interpretation path；legacy `lin_tianji_domain_v1-exp` 不再是新 prospective path 的正式 authority。
