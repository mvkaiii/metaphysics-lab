# Metaphysics Lab v1.6.0 發布說明

## 版本定位

Metaphysics Lab v1.6.0 將軟體正式發版與研究模型 promotion 分開管理。

本版正式納入已完成工程 qualification 的 v1.6 結構化能力，並加入 Y1 年度紫微四化 materialization。Y1 的定位為 **Experimental / Project-derived**：計算路徑固定、可重現、可稽核並可在正式軟體中使用，但不代表預測準確度已被證明。

## 本版重點

- 保留 Historical Activation Selector v1 作為正式 default。
- 保留 Interpretation Contract v1 作為正式 default。
- 納入 Y1 年度紫微四化 Project 推導能力，並保留明確 Experimental 成熟度上限。
- 保留 v1.6 已建立的結構化 evidence / hybrid / claim-consumption / prospective governance infrastructure，但不因軟體發布而自動切換 Candidate 成為 default。
- 保留 deterministic 三檔 User Package：`metaphysics_core.md`、`metaphysics_lab.py`、`project_instructions.txt`。
- 持續執行 Bazi / Ziwei 時間引擎 qualification、prediction validation、release-surface validation、full regression 與 isolated sandbox release gate。

## Y1 邊界

Y1 來源為已 qualified 的 yearly Ziwei transformation implementation。正式 v1.6.0 只把已驗證的 production/runtime 路徑納入 release；研究用 retrospective benchmark、adjudication 與 outcome 評分資料不屬於正式 release surface。

因此本版可以使用 Y1，但不得把以下敘述當成既成事實：

- Y1 已被 prospective case 證明比舊方法更準。
- Candidate pipeline 已證明優於 Legacy。
- v2 selector / v2 interpretation 已取得 default promotion 資格。

上述研究狀態仍是 `promotion_allowed=false`。

## Prospective 研究保持封存

既有 prospective Case A / Case B 不因 v1.6.0 發版而改變：

- 不提前讀 outcome。
- 不建立 oracle。
- 不執行 private scoring。
- 不依未來結果 retuning。
- 不修改已封存的 forecast / paired-arm / sampling authority。

這些 case 將來提供的是研究模型 promotion 證據，不是 v1.6.0 軟體能否發布的必要前提。

## 相容性

v1.6.0 不以發布名義強迫既有使用者切換到尚未通過 promotion gate 的模型。正式 default routing 維持既有穩定設定；新的 Experimental 能力採可追溯、可限制的方式提供。

## 發布門檻

正式 GitHub Release 只有在 exact release candidate 通過完整自動化 qualification 與真實 isolated sandbox 驗證後才允許建立。任何 PENDING / FAIL 證據都必須 fail closed。
