## Bazi 大運與節氣

Bazi Calendar Engine 已升為 1.1.0，節氣 authority 採 Project bundled `lunar-python==1.4.8` JieQi table。已保存的HKO benchmark顯示48個節氣點全部落在HKO公布的60秒精度範圍內。

大運 exact-Jie boundary固定為：

- forward：第一個 `Jie >= birth_datetime`
- reverse：最後一個 `Jie <= birth_datetime`

Task3 v2.1對封存production candidate的12案例、5條比較路徑完成60/60 MATCH。這支持封存範圍內的**implementation conformance**，不代表命理預測真實性或實證預測效度。

Task3 sealed identity仍是 `bazi-natal-project-v1 / 1.0-exp`。v1.8不在qualification完成後事後改名；工程實作差異改由calendar engine/provider、runtime與release provenance表達。

## Capability與Visualization

`bazi.natal_chart`仍為 **implemented / experimental / on_demand**。

Repo新增：

- Capability Evidence Index / Qualification Matrix
- Visualization Chart Contract v1
- Experimental Bazi decadal projection
- deterministic SVG / text renderer
- repository CLI

v1.8 User Package新增 public runtime action `render_bazi_decadal_timeline`。它接受已建立的 Project natal／Normalized natal與明確的觀察時間，輸出同一份Chart Contract的 deterministic SVG與純文字替代版。圖表仍是 **Experimental presentation surface**，不提升 `bazi.natal_chart` maturity，也不新增預測證據。

一般對話同時改採 **Compact by default / Details on demand**：預設先呈現核心判斷、必要圖表與少量行動建議；使用者追問原因時才切到explain展開命理依據，技術audit只在真正開發稽核時使用。
