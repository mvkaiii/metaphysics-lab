## 這版主要有什麼？

v1.3.0 把命盤建立、紫微細時間計算與 AI Project 使用方式整理成一個正式版本。

一般使用者最直接會感受到：

- Metaphysics Lab 的產品方向仍是從出生資料建立 Project 八字與紫微本命盤。
- **目前過渡期建議先提供 Astralium 八字／紫微命盤**，讓 Project 先保存 External Natal Source，並作為後續 Project 原生計算、reconciliation 與 qualification 的基準資料。
- 加入更細的紫微時間層與流曜相關計算，實際可用範圍由系統判斷。
- 正式提供 ChatGPT Project / Claude Project 使用的三個檔案。
- 出生資料不完整時不應自行猜出生時間、地點或其他缺值。
- Python 負責固定計算，AI 負責解讀與策略分析。

### 目前建議的首次建立流程

在 Portable Offline Natal Pipeline 完成前，建議依下列流程開始：

1. 對 AI 說：**「開始建立我的命理專案。」**
2. AI 應先請你開啟 Astralium 官方網站：<https://getastralium.com/>。
3. 在 Astralium 輸入性別、出生日期、出生時間與出生地，分別取得**八字命盤**與**紫微命盤**。
4. 把八字與紫微資料貼回 Project；若目前只有其中一份，也可以先提供已有資料。
5. Metaphysics Lab 先把 Astralium 資料保存為 **External Natal Source**，再依目前 runtime 能力建立 Project 原生盤、做 reconciliation 或繼續分析。
6. 如果目前執行環境無法完成 Project 原生計算，系統必須明確說明，保留 External 資料，不得假裝已完成 Project 原生盤。

這個順序是**過渡期建議**。等 Portable Offline Natal Pipeline 完成並通過 clean-environment qualification 後，正式主要流程會再回到「只有出生資料即可建立 Project 原生命盤」，Astralium 回到可選的交叉校驗來源。

如果平台提供**較高推理強度**或深度思考模式，完整本命、流年、合盤或重大決策分析可優先使用。

## 命盤資料可以怎麼提供？

### 推薦：出生資料 + Astralium

目前第一次建立 Project 時，建議同時提供出生資料與 Astralium 八字／紫微命盤。

這可以先建立可保存的 External Natal Source，也能在後續 Portable Project Natal 完成後直接做欄位級 reconciliation 與 qualification。

### 只有第三方排盤

如果目前只有 Astralium、其他排盤網站、命理軟體或命理師提供的結構化命盤，也可以先匯入 External 資料；系統不會因此假裝自己已完成 Project 原生計算。

### 只有出生資料

Metaphysics Lab 的正式產品方向仍是由性別、出生日期、出生時間與出生地建立 Project 原生命盤。

但在 Portable Offline Natal Pipeline 完成前，不保證所有 ChatGPT／Claude 執行環境都能直接完成這條流程；若核心 dependency、network 或 location resolution 條件不足，必須 fail closed，不得猜測或假裝成功。

## Astralium 在這套系統裡扮演什麼角色？

Astralium 可以提供八字與紫微的第三方資料。Metaphysics Lab 會把第三方資料與 Project 自己計算的結果分開保存，再比較是否一致。

有差異時會保留差異，不會為了讓結果看起來一致而覆寫任何一方原始資料。

即使目前過渡期優先建議使用 Astralium，它仍然是：

```text
External Natal Source
```

不是：

```text
Project Natal calculation authority
```

詳細方式見：`docs/Astralium資料取得指南.md`。

## 出生時間不確定

如果只知道一段時間範圍，系統不應自行補成區間中點或任意時辰。資料足夠時，可以保留多個候選狀態，只使用所有候選都一致的部分。

詳細方式見：`docs/命盤資料準備指南.md`。

## 技術狀態

v1.3.0 是正式 GitHub Release，但**正式發版不等於所有新能力自動升為 Stable**。部分能力仍處於實驗或按需使用狀態。

一般使用者不需要自己判讀能力表；技術上目前實際可執行的能力以 `runtime_info` 為準，完整版本紀錄見 `VERSION.md`。
