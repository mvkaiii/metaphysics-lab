## 這版主要有什麼？

v1.3.0 把命盤建立、紫微細時間計算與 AI Project 使用方式整理成一個正式版本。

一般使用者最直接會感受到：

- Metaphysics Lab 可以從出生資料建立 Project 八字與紫微本命盤。
- 目前 single-file runtime 內建固定版本的核心曆法 dependency 與有限、版本化的 **offline registry**；支援地點可以在**不需要網路**、**不需要額外 Python 套件**的條件下建立 Project Natal。
- Astralium 八字／紫微命盤回到**可選的 External Natal Source／交叉校驗來源**，不是 Project Natal calculation authority。
- 加入更細的紫微時間層與流曜相關計算，實際可用範圍由系統判斷。
- 正式提供 ChatGPT Project / Claude Project 使用的三個檔案。
- 出生資料不完整時不應自行猜出生時間、地點或其他缺值。
- Python 負責固定計算，AI 負責解讀與策略分析。

### 首次建立流程：Birth Data first

AI 只確認還缺哪些必要出生欄位：

1. 性別。
2. Gregorian 出生日期。
3. 出生時間。
4. 出生地。

位置解析順序固定：

1. 已提供完整 `resolved_location` → 直接使用並保留 provenance。
2. 否則先查 Project 內建 offline registry。
3. offline registry 找不到 → 預設 fail closed。
4. 只有使用者明確啟用 network location resolution 時，才使用網路 fallback。
5. offline alias ambiguous → 直接回報，不讓網路結果偷偷覆蓋 ambiguity。

offline registry 是有限、版本化的 coverage，不是全球地理資料庫。未支援地點可以提供已確認的座標＋IANA timezone，或明確選擇啟用 network location resolution。

Astralium 仍可提供 External Natal Source。若同時有 Project Natal，兩邊分開保存並做 reconciliation；Astralium 不取代 Project 原生 calculation authority。

如果平台提供**較高推理強度**或深度思考模式，完整本命、流年、合盤或重大決策分析可優先使用。

## 命盤資料可以怎麼提供？

### 只有出生資料

提供性別、出生日期、出生時間與出生地即可開始。若出生地命中支援的 offline registry 記錄，可直接建立 Project 原生命盤，不需要網路，也不需要額外 Python 套件。

### 出生資料 + Astralium

如果手上已有 Astralium 八字／紫微命盤，也可以一起提供。Metaphysics Lab 會把它保存成 External Natal Source，再和 Project Natal 做 reconciliation／交叉校驗。

### 只有第三方排盤

如果目前只有 Astralium、其他排盤網站、命理軟體或命理師提供的結構化命盤，也可以先匯入 External 資料；系統不會因此假裝自己已完成 Project 原生計算。

## Astralium 在這套系統裡扮演什麼角色？

Astralium 可以提供八字與紫微的第三方資料。Metaphysics Lab 會把第三方資料與 Project 自己計算的結果分開保存，再比較是否一致。

有差異時會保留差異，不會為了讓結果看起來一致而覆寫任何一方原始資料。

Astralium 是：

```text
External Natal Source
```

不是：

```text
Project Natal calculation authority
```

詳細方式見：`docs/Astralium資料取得指南.md`。

## 出生時間不確定

如果只知道一段時間範圍，系統不應自行補成區間中點或任意時辰。資料足夠時，可以保留多個候選狀態，只使用所有候選都一致的部分。

詳細方式見：`docs/命盤資料準備指南.md`。
