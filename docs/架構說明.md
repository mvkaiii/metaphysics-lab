# 架構說明

Metaphysics Lab 將命理分析拆成七層：

1. 原始盤面事實
2. 已校驗資料
3. Project 推導盤面
4. 已驗證事件
5. 命理推論
6. 研究假說
7. 當次現實背景

## 資料流

```text
原始盤面
  ↓
資料校驗
  ↓
本命模型
  ↓
固定算法建立時間層級
  ↓
第一階段盲判
  ↓
鎖定原始預測
  ↓
第二階段事件校準
  ↓
現實策略與底線
  ↓
事後結果驗證
```

## 八字與紫微分工

八字主要負責底層結構與時間骨架；紫微主要負責十二宮、星曜、四化、飛化、大限、小限、流年與月份領域定位。

目前八字年月日時可由 Project 固定算法推導；紫微已啟用「流月定位層」，只包含斗君、流月命宮與流月十二宮。紫微流日、流時、流月四化、流曜與細層飛化仍未啟用。

月份邊界必須分開：八字流月採節氣月；紫微流月採農曆月，初一換月，閏月拆半。兩者不同步不是 bug。

## Python 引擎模組

v1.2 重構將八字與紫微正式實作分開：

```text
engine/
├── bazi/
│   ├── __init__.py
│   └── calendar.py
├── ziwei/
│   ├── __init__.py
│   ├── common.py
│   └── month.py
├── project_bazi_calendar.py
└── project_ziwei_month.py
```

`engine/bazi/calendar.py` 負責八字流年、流月、流日、流時與天干十神等既有正式算法。

`engine/ziwei/common.py` 只保存紫微時間模組共用的地支索引、十二宮名稱與輸入驗證；`engine/ziwei/month.py` 負責目前已啟用的斗君流月定位。

根目錄兩支 `project_*.py` 目前保留為 compatibility wrapper（相容入口），因此既有 ChatGPT Project 不需要因這次內部重構立即改用新的 package path。

後續紫微流日、流時與 Cross-System Validation 會在各自規則固定並測試完成後再新增，不先建立會讓人誤認為功能已啟用的空殼模組。
