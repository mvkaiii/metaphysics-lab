# 架構說明

Metaphysics Lab 正式 release identity 目前仍為 v1.2.0；本文件另記錄 **Unreleased Phase 2C0｜Natal Chart Foundation** 的工作樹架構。

## 八種資料類型

1. 原始盤面事實
2. 已校驗資料
3. Project 原生盤面
4. Project 推導盤面
5. 已驗證事件
6. 命理推論
7. 研究假說
8. 當次現實背景

這八層不能互相冒充。Project 由出生資料建立的本命屬於 **Project 原生盤面**；Project 由本命／運限／目標時間建立的細時間層屬於 **Project 推導盤面**。

`Project 推導盤面` 是**資料分類，不是 capability prefix**。

固定原則：

> **Precision must be earned by input.**

Input Resolution / Precision Gate 在所有高精度 capability 前執行。輸入不足或不唯一時，只能追問、保留候選或降級分析；不得自行補值。

# 二、Birth Input Resolver

完整 Mode A 最低輸入：

- sex
- Gregorian birth date
- birth time
- birth place

自然語言層只解析使用者已提供的資料並回報 `missing_fields` / `allowed_actions`；engine 不生成追問文案。

已知四柱 Mode B 只允許建立 Bazi imported/external view，不反推唯一 civil birth identity，也不建立 Ziwei natal。

Astralium structured data Mode C 是 external source；可與 Project 由出生資料重算的結果並存。

---

# 三、Location Resolver

使用者只需提供出生地名稱，例如「台北市」。Location Resolver 解析：

- canonical label
- latitude
- longitude
- IANA timezone
- source / provenance

零候選或多個 material candidates 時 fail closed，不猜地點。

---

# 四、Calendar Resolver 邊界

Calendar Resolver v1 接受 structured local civil datetime + IANA timezone + optional offset hint，負責：

- timezone / DST validation
- Gregorian civil datetime normalization
- Gregorian→Lunar context
- neutral civil hour branch
- provider provenance / calendar validation

**Calendar Resolver 不負責真太陽時。**

也不負責：

- 自然語言日期解析
- 出生地 geocoding
- 八字 23:00 early-Zi policy
- 紫微 23:00 metaphysical effective-day policy
- Qimen day boundary

civil date 只在 00:00 換日；23:00 已屬子時，但 `metaphysics_day_boundary_applied = false`。

# 五、Birth Time Views

Phase 2C0 不把校正後時間覆蓋使用者原始輸入，至少保存：

```text
reported_civil_time
normalized_civil_time
bazi_effective_time
ziwei_effective_time
```

另外可保存 versioned true-solar record、adjustment minutes、calculation basis、profile id、rule version、provenance。

真太陽時由 downstream time profile 決定，**不是 Calendar Resolver 的全域行為**。

八字與紫微 profile 獨立。Ziwei Natal default profile 為 `ziwei-natal-true-solar-common-v1`；ordinary UX 自動套用 Project 的真太陽時 profile，但原始 civil time 永遠保留。Bazi Natal 依自己的 profile 與 qualification rules 判斷 civil／true-solar 是否 materially different。

只有會改變日柱、時柱、命宮、身宮或其他核心依賴欄位的差異才升級為 material conflict。

# 六、Normalized Natal Model

Cross-system model 固定三層：

```text
External / Project / Resolved
```

External = 第三方／imported raw view。

Project = Metaphysics Lab deterministic Project 原生盤面。

Resolved = reconciliation 後供下游使用的欄位選擇。

固定 status：

```text
MATCH / EQUIVALENT / CONFLICT / NOT_COMPARABLE
```

固定 severity：

```text
INFO / CAUTION / BLOCKING
```

External / Project raw values 不得覆寫。Resolved source selection 不得改寫原 status / severity。

Experimental authority：external 與 Project 衝突時預設採 external；Stable authority 未來可採 Project，但仍保留衝突記錄。

Astralium 為可選 external qualification source，不是 runtime dependency。

# 七、Natal Builders

## Bazi Natal

```text
bazi.natal_chart = implemented / experimental / on_demand / 1.0-exp
```

依賴 Birth foundation + Calendar。輸出 deterministic natal facts；主觀格局／喜用神等屬後續命理解讀，不由 builder 自動補值。

## Ziwei Natal

```text
ziwei.natal_chart = implemented / experimental / on_demand / 1.0-exp
```

依賴 `birth.true_solar_time`、`ziwei.transformations`、`ziwei.flying`。Project true-solar output 是 Project 計算，不得寫成 Astralium output。

## Reconciliation / Markdown

```text
natal.reconciliation  = implemented / stable / on_demand / 1.0
natal.markdown_export = implemented / stable / on_demand / 1.0
```

Markdown exporter 只序列化已存在的 structured facts，不重新排盤、不猜 missing fields、不偷偷加入命理解讀。

# 十、Qualification 與 Privacy

公開 qualification 可提交 public/synthetic vectors、versions、aggregate status、counts 與 digest。

私人 Astralium 或使用者命盤不得提交 raw birth input、raw chart、full address 或 external raw payload；private qualification 只允許 aggregate counts/digest/status。

Infrastructure outage 與 algorithm mismatch 必須分開報告；不能把網路／provider failure 重命名成 PASS 或產品 FAIL。

---

# 十一、分析責任

Natal Foundation 只提供 deterministic chart facts、source classification、validation、reconciliation 與 canonical export。命理 interpretation、問事盲判、事件校準與現實策略仍在分析層執行。

因此：

- Project 原生盤面 ≠ 命理推論
- Project 推導盤面 ≠ 命理推論
- qualification match ≠ 命理預測正確
- capability implemented ≠ maturity Stable
