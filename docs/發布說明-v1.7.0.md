## 本版四個重點

### Capability Manifest / SSOT

`runtime_info()` 聚合各 engine registry 作為 capability 技術真相來源。正式 release 不會因某能力已 materialize 或可執行，就自行把 maturity、routing 或 qualification 寫高。

### Case Doctor + Legacy Reconciliation

Case Doctor 可診斷 canonical authority、legacy、duplicate、metadata conflict 與 schema/validation 問題，並產生 deterministic reconciliation dry-run。

它**不自動刪除**使用者檔案，也不提供任意一鍵改寫所有 Case 的捷徑。需要 mutation 時，仍要走既有 `migrate_case`、`update_case_record` 或 subject actions；semantic conflict 需要使用者選擇。

### Prospective Validation 2.0

v1.7 將 validation context 明確分成：

- `clean_prospective`
- `conditional_prospective`
- `hidden_existing_reality`
- `retrospective_calibration`

只有真正未知、且在 knowledge cutoff 前沒有已知必要安排的 `clean_prospective` 才能進 **clean prospective denominator**。`conditional_prospective` 與 `hidden_existing_reality` 可以追蹤／研究，但不得灌入 clean prospective 命中率；`retrospective_calibration` 則走歷史校準，不走 prospective lock。

既有 v1.5/v1.6 frozen prospective lock 保持 readable 與 exact，不因 v1.7 改寫歷史 identity。

### Guided Inquiry

AI 在合適時主動顯示 **3～4 個**後續詢問方向，**預設 3 個**。不足合法建議時可以少於 3 個或不顯示；使用者永遠可以直接自由輸入，不必選建議。

Guided Inquiry 是對話導航，不是新的命理證據。它不得提高 specificity、confidence 或 ranking authority，也不得為了產生建議而在第一階段盲判前讀取已驗證事件。

## 不會因本版自動 promotion 的能力

v1.7 正式發版不等於研究能力 promotion。Selector default 仍是 v1、Interpretation default 仍是 v1；Ziwei experimental/on-demand 能力與其他 **Experimental** capability **不因 v1.7 發布而自動升級**成 Stable/default。

同樣地，正式發布不代表某研究候選已被 prospective accuracy 證明優於舊方法。
