# 更新與版本同步

本文件說明 GitHub Metaphysics Lab 更新後，如何安全同步到 ChatGPT Project，而不覆蓋私人 Case。

目前正式版本仍為：**v1.2.0｜2026-08-21**。

**Phase 2B 與 Phase 2C0 都是 Unreleased overlay；不得因工作樹已實作就改寫正式 release identity。**

---

## 一、版本文件

每次更新先看：

```text
VERSION.md
CHANGELOG.md
docs/更新與版本同步.md
```

- `VERSION.md`：正式 release identity。
- `CHANGELOG.md`：release 與 Unreleased 工作樹變更。

規則、Project Instructions、requirements、capability metadata 都可能影響行為，不能只比 Python 檔案。

## 三、Phase 2C0 使用者資料契約

完整 Mode A：性別、Gregorian 出生日期、出生時間、出生地。

例如：

> 男，1984年3月13日19:20，台北市出生

輸入不足時只追問缺少欄位；例如「1990年5月6日，高雄出生」只追問性別與出生時間。

模糊輸入例如「大概晚上7、8點」不得取中點；保留候選或降級。

固定原則：**Precision must be earned by input.** 不得自行補值。

## 四、資料分類 migration

Phase 2C0 將核心資料分類由七種擴充為八種，新增：

**Project 原生盤面**

新的關係：

- third-party direct output → 原始盤面事實
- Project deterministic natal build → Project 原生盤面
- Project future/cycle calculation → Project 推導盤面
- interpretation → 命理推論

如果 Project Instructions 仍顯示「七種資料類型」，代表同步不完整。

## 五、Time / Calendar migration

Phase 2C0 至少保存：

```text
reported_civil_time
normalized_civil_time
bazi_effective_time
ziwei_effective_time
```

Calendar Resolver 保持 neutral；**Calendar Resolver 不負責真太陽時**。

八字與紫微使用獨立 time profile。Project 的真太陽時口徑記錄為「經度校正＋均時差」；Project output 不得寫成 Astralium output。

## 六、External / Project / Resolved migration

本命 cross-check 固定：

```text
External / Project / Resolved
MATCH / EQUIVALENT / CONFLICT / NOT_COMPARABLE
```

External / Project raw views 不得覆寫。Experimental authority 發生實質衝突時，Resolved 預設採 external；若未來 capability promotion 為 Stable，才可改預設 authority，且 CONFLICT 仍保留。

Astralium 為可選 external qualification source，不是 runtime dependency。

8. 若文件說 Phase 2C0 final acceptance 已 PASS，必須有 Task 10 正式 gate evidence；在此之前只可標示 Unreleased / pending final acceptance。
