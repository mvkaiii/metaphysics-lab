# 快速開始

這份文件給第一次使用 Metaphysics Lab v1.2.0 的人。目標是先把最小可用環境建立起來，再依需要加入細時間 capability 與 Ziwei Transformation / Flying Core。

建議搭配：

- [安裝到 ChatGPT Project](安裝到ChatGPT-Project.md)
- [命盤資料準備指南](命盤資料準備指南.md)
- [Astralium 資料取得指南](Astralium資料取得指南.md)
- [更新與版本同步](更新與版本同步.md)

---

## 1. 準備出生基本資料

至少準備：

- 性別
- 西元出生年月日
- 原始出生時間
- 出生城市／國家
- 出生時間是否確定

出生時間不確定時，不要自行猜一個時辰。

---

## 2. 取得八字與紫微原始資料

建議準備一份八字結構化資料與一份紫微結構化資料。

可使用 Astralium 或其他可靠排盤來源，但要保留來源名稱、產出日期與時間口徑。

第三方排盤直接提供的內容屬於「原始盤面事實」；Metaphysics Lab 自己計算的內容屬於「Project 推導盤面」，兩者不得混稱。

---

## 3. 建立 ChatGPT Project

把 `core/核心提示詞.md` 複製到 Project Instructions。

基礎規則至少加入：

```text
core/命理分析作業規範.md
core/命理推導計算規則.md
core/紫微流月推導規則.md
```

相容入口：

```text
engine/project_bazi_calendar.py
engine/project_ziwei_month.py
```

若只是讓 AI 閱讀正式算法來源，wrapper 可作入口索引；若環境要實際執行 Python，wrapper 不是獨立單檔，必須連同對應 package 一起同步。

---

## 4. 完整 Python 執行環境

八字與紫微基礎 modules：

```text
engine/bazi/__init__.py
engine/bazi/calendar.py

engine/ziwei/__init__.py
engine/ziwei/common.py
engine/ziwei/capabilities.py
engine/ziwei/month.py
```

若需要 Calendar Resolver：

```text
requirements.txt
engine/calendar/__init__.py
engine/calendar/precision.py
engine/calendar/models.py
engine/calendar/timezone.py
engine/calendar/lunar.py
engine/calendar/resolver.py
engine/ziwei/calendar_adapter.py
```

並安裝 exact dependencies：

```bash
pip install -r requirements.txt
```

v1.2.0 固定：

```text
lunar-python==1.4.8
tzdata==2026.3
```

---

## 5. 需要紫微流日／流時定位時

流日：

```text
core/紫微流日推導規則.md
engine/project_ziwei_day.py
engine/ziwei/day.py
```

流時：

```text
core/紫微流時推導規則.md
engine/project_ziwei_hour.py
engine/ziwei/hour.py
```

狀態：

```text
紫微流日 = implemented / experimental / on_demand
紫微流時 = implemented / experimental / on_demand
```

兩者都只處理宮位定位，不代表流日／流時四化、飛化或流曜已實作。

一般年度／月份問事不預設遍歷流日或流時；只有指定日期、時辰、候選時間比較或需要更細解析度時才按需調用。

## 6. 需要 Ziwei Transformation / Flying Core 時

同步：

```text
engine/ziwei/errors.py
engine/ziwei/models.py
engine/ziwei/basis.py
engine/ziwei/transformation_profiles.py
engine/ziwei/transformations.py
engine/ziwei/flying.py
engine/ziwei/composition.py
```

能力：

```text
Ziwei Transformation Core = implemented / stable / on_demand
Ziwei Flying Core = implemented / stable / on_demand
```

目前可處理：

- 十天干四化
- 本命十二宮宮干飛化
- 生年四化
- 大限四化／飛化
- 流年四化／飛化
- 不同 layer 共存、不互相覆寫

目前不能處理：

- 流月四化／飛化
- 流日四化／飛化
- 流時四化／飛化
- 流曜

原因不是四化 core 不會算，而是 Fine Cycle Stem Resolver 尚未固定並 qualification。

從 `templates/` 複製空白模板，建立自己的：


第一次不用全部填滿。優先完成：

1. 命盤資料校驗
2. 命盤核心摘要
3. 有把握的重要歷史事件

私人 Case 不應提交回共用 GitHub repo。

---

## 8. 第一次先做命盤校驗

不要一開始就直接問「今年會發生什麼」。

先確認：

- 是否成功讀到 `命理分析作業規範.md`
- 出生年月日時與地點是否正確
- 八字四柱、日主、大運是否一致
- 紫微命宮、身宮、大限、流年是否可讀
- 不同來源是否有真太陽時、子時換日或其他口徑差異
- 哪些資料是原始盤面，哪些是 Project 推導
- capability 狀態是否能區分 Stable / Experimental / Planned 與 Default / On-demand

有差異先寫入 `命盤資料校驗紀錄.md`。

---

## 9. 開始問本命或流年

本命分析可直接讀已校驗盤面。

未來趨勢、流年問事與行動決策採：

**第一階段盲判 → 第二階段事件校準**

第一版完成以前，不先讀驗證事件來製造預測感。

---

## 10. 八字時間推導

正式模組：

```text
engine/bazi/calendar.py
```

相容入口：

```text
engine/project_bazi_calendar.py
```

可建立：

- 流年
- 流月
- 流日
- 流時
- 對應天干十神

結果屬於 Project 推導盤面，不是第三方排盤系統的直接輸出。

---

## 11. 紫微流月定位

正式模組：

```text
engine/ziwei/month.py
```

Stable / Default 流月目前包含：

- 流年斗君
- 流月命宮
- 流月十二宮重排

紫微流月採農曆月；八字流月採節氣月。兩者同一天可能不同月，不是 bug。

---

## 12. Calendar Resolver 的邊界

Calendar Resolver v1 已正式實作，可把 structured civil datetime + IANA timezone 正規化為 `CalendarContext`。

但它不負責：

- 自然語言日期解析
- 真太陽時
- 八字換日 policy
- 紫微 23:00 命理日界 school policy

23:00 已屬子時，但 Resolver civil date 只在 00:00 換日。
