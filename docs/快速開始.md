# 快速開始

這份文件給第一次使用 Metaphysics Lab 的人。你不需要先懂程式碼儲存庫或 Python 模組，只要把三個正式檔案放進 ChatGPT Project 或 Claude Project，就可以開始。

> 以下姓名、生日與識別碼皆為**虛構示例**，不對應任何真實使用者。

## 1. 下載三個檔案

目前最新正式版本為 **v1.9.0｜2026-10-03**。既有命主資料與個案紀錄可以沿用；Project Contract升為1.3，Case Schema仍維持1.1。

優先下載 `Metaphysics-Lab-v1.9.0-User-Package.zip`；ZIP 內固定只有三個正式檔案。若只想查看單一檔案，也可以在正式發布頁的下載區（Assets）個別下載。

| 用途 | 實際檔名 | 怎麼用 |
|---|---|---|
| **命理計算程式** | `metaphysics_lab.py` | 上傳到 ChatGPT Project 或 Claude Project |
| **命理分析核心規則** | `metaphysics_core.md` | 上傳到同一個 ChatGPT Project／Claude Project |
| **Project 設定指令** | `project_instructions.txt` | 全文貼到 Project Instructions |

不需要下載 GitHub 自動產生的原始碼壓縮檔（Source code），也不需要另外安裝程式碼儲存庫裡的模組。

從 **v1.8.0 升到 v1.9.0** 請同步三個發行檔案；本版將 Project Contract升到1.3。保留 `命主索引.md`、既有個案資料、驗證事件、流年／問事／重大決策紀錄與已鎖定預測；既有1.2 Case仍可讀，舊lock不回填或重簽。

如果平台提供**較高推理強度**或深度思考模式，完整本命、流年、合盤與重大決策分析可以優先使用。

設定完成後直接輸入：

> **「開始建立我的命理專案。」**

## 2. 選擇命盤資料來源

你可以用三種方式開始：

### 只有出生資料

提供：

- 性別
- 出生日期
- 出生時間
- 出生地

虛構示例：

> 女，1992年8月17日14:30，高雄市出生

AI 應缺什麼只追問什麼，不自行補值。

### 出生資料 + Astralium

如果你另外有 Astralium 的八字或紫微排盤，也可以一起提供。Metaphysics Lab 會把第三方資料與系統自行計算的結果分開保存，再做交叉校驗。

Astralium 是**可選**來源，不是使用 Metaphysics Lab 的必要條件。

### 只有第三方排盤

如果目前只有 Astralium、其他排盤網站、命理軟體或命理師提供的結構化八字／紫微資料，也可以先建立第三方來源資料。系統不會因為看到了第三方盤，就假裝自己的命盤計算也已完成。

## 3. 一個專案可以管理多人

AI 會先讀取或建立：

```text
命主索引.md
```

每位命主有自己的 `subject_id`。這是系統用來避免多人資料混在一起的識別碼，不由姓名或生日推導。

例如：

```text
subject_display_name: Alex
subject_id: subj_7f3a2c91d4e8
subject_short_id: 7F3A2C
```

新建個案資料的實際檔名格式是：

```text
<filename_label>_<SUBJECT_SHORT_ID>_<slot>_<canonical_title>.md
```

例如：

```text
Alex_7F3A2C_01_命盤核心摘要.md
Mina_91C40B_01_命盤核心摘要.md
```

名稱可以改，但 `subject_id` 不跟著改。

## 4. 不知道出生時間也不要猜

如果完全不知道出生時間，或只知道「大概晚上7、8點」「大約13:00～15:00」，AI 不得自行補 12:00、19:30 或區間中點。

當 `runtime_info` 顯示 `natal.candidate_envelope` 可執行，而且出生日期、出生地與時區等必要資料足夠時，Python 可以建立**候選盤面集合（Candidate Envelope）**：保留不同時間可能造成的候選盤面，只把所有候選都一致的部分當成確定資料。

這時可以建立部分個案資料（`partial` Case），但需要唯一出生時辰才能成立的時柱、紫微本命細節或單一命盤個人化預測，仍會保持未確定。候選不是多數決，也不會挑一張看起來最像的盤冒充唯一答案。

## 5. 第一次建立個案資料

第一次本命資料足夠時，系統先建立基礎個案資料，不會一開始就塞滿空白追蹤檔。

以虛構命主 Alex 為例：

```text
Alex_7F3A2C_00_專案索引.md
Alex_7F3A2C_01_命盤核心摘要.md
Alex_7F3A2C_02_命盤資料校驗紀錄.md
Alex_7F3A2C_03_八字結構化資料包.md
Alex_7F3A2C_04_紫微基礎資料包.md
```

`00`～`04` 是內部正式檔位；一般使用者只要知道它們是同一位命主的基礎資料即可。

後續有實際內容時，才逐步新增驗證事件、流年追蹤、問事追蹤或重大決策紀錄。

v1.7 的**個案資料檢查（Case Doctor）**可以協助找出正式資料來源、舊版檔案、重複資料與內容衝突，並先提供不會直接修改檔案的校驗預演；它不會自行刪除檔案，也不會要求你為了升級而重建個案資料。

## 6. 第一次問未來時

未來趨勢、流年與行動決策採「先盲判，再事件校準」。AI 先根據盤面完成第一版判斷，再用你已確認的人生事件做歷史事件校準；不會先看答案再回頭改第一版預測。

你可以直接說：

> 幫我看 Alex 今年下半年。

> 幫我看 Mina 明年的工作。

> Alex 是本人、Mina 是合作夥伴，幫我看合作互動。

角色只是這次問題中的關係，不會改變命主本身的識別資料。

v1.7 也會在合適時主動顯示 **3～4 個**後續詢問方向，**預設 3 個**。建議只是導航；你仍可以直接自由輸入，不需要選建議，而且導航本身不會增加命理證據或提高結論的具體程度。

## 7. Astralium／第三方資料怎麼處理

若第三方盤與系統計算結果同時存在，系統會分開保留第三方來源、系統計算結果與已校驗採用結果；內部狀態代碼如下：

```text
External / Project / Resolved
MATCH / EQUIVALENT / CONFLICT / NOT_COMPARABLE
```

簡單說：原始第三方盤保留原樣，系統計算結果也保留原樣，再記錄兩者是一致、等價、衝突，或無法直接比較。不能為了讓結果好看而互相覆寫。

## 8. 如果 AI 無法執行 Python

若 AI **無法執行 Python**，它必須直接說明，**不得假裝**已經完成新的命盤計算。

可以在本機執行同一個命理計算程式：

```bash
python metaphysics_lab.py request --input request.json --pretty
```

也可以從 stdin 傳入 request：

```bash
python metaphysics_lab.py request --input - --pretty
```

把輸出的 JSON 交回 AI，再繼續分析。

## 9. 平常更新什麼？

一般只更新執行程式時，通常只需要替換 `metaphysics_lab.py`；但 **v1.8.0 → v1.9.0** 因專案規格（Project Contract）同步更新，請依本頁開頭與[更新與版本同步](更新與版本同步.md)把三個發行檔一起同步。

`命主索引.md` 與私人個案資料不需要重建。只有專案規格（Project Contract）或個案資料格式（Case Schema）明確變更時，才依正式發布說明處理；本次個案資料格式仍是 1.1。

## 10. 隱私

私人 `命主索引.md`、出生資料、個案資料 Markdown、事件紀錄、第三方原始命盤資料、PDF 與截圖都留在自己的 ChatGPT Project、Claude Project 或本機，不要提交回公開 GitHub 儲存庫。

更多資料準備與 Astralium 選項見[命盤資料準備指南](命盤資料準備指南.md)、[Astralium資料取得指南](Astralium資料取得指南.md)與[v1.9.0 發布說明](發布說明-v1.9.0.md)。
