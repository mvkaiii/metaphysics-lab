# 快速開始

這份文件只處理一件事：讓第一次使用 Metaphysics Lab 的人，不需要懂 repo、不需要懂 Python 模組，也能把系統放進 ChatGPT Project 或 Claude Project 開始使用。

## 你需要的三個檔案

```text
metaphysics_lab.py
METAPHYSICS_CORE.md
PROJECT_INSTRUCTIONS.md
```

其中真正要加入 Project 檔案區的是前兩個；`PROJECT_INSTRUCTIONS.md` 的內容要貼到 Project Instructions。

## 第一次設定

1. 建立一個新的 ChatGPT Project 或 Claude Project。
2. 上傳 `metaphysics_lab.py`。
3. 上傳 `METAPHYSICS_CORE.md`。
4. 開啟 Project Instructions，把 `PROJECT_INSTRUCTIONS.md` 全文貼進去。
5. 完整命盤、流年、合盤或重大決策分析，建議選 **High reasoning**。
6. 輸入：**「開始建立我的命理專案。」**

接下來應由 AI 主導流程，不需要你自己決定要跑哪個命理模組。

## 一個 Project 可以管理多人

Metaphysics Lab 不假設 Project 裡只有「本人」。你可以替自己、家人、朋友或合作對象建立不同命主。

第一次建立某位新命主時，AI 會先讀取或建立 Project-level：

```text
命主索引.md
```

AI 負責發起 identity creation，opaque `subject_id` 由 runtime 自動產生，不由使用者自己編，也不由姓名或生日推導。

例如：

```text
subject_display_name: Kai
subject_id: subj_7f3a2c91d4e8
subject_short_id: 7F3A2C
```

名稱是人類辨識用；真正 identity authority 是 `subject_id`。同名命主可以共存，名字之後也可以改，但 `subject_id` 不變。

新 Case 檔名格式固定為：

```text
<filename_label>_<SUBJECT_SHORT_ID>_<slot>_<canonical_title>.md
```

例如：

```text
Kai_7F3A2C_01_命盤核心摘要.md
Amy_91C40B_01_命盤核心摘要.md
```

所以多人放在同一 Project 時不會出現一堆無法辨識的 `01_命盤核心摘要 (1).md`。

## AI 第一次應該怎麼做

AI 會先確認「這次是在問哪位命主」，再從 `命主索引.md` 對應既有 `subject_id`；只有確定是新命主時才建立新 identity。

完整出生資料通常需要：

- 性別
- Gregorian 出生日期
- 出生時間
- 出生地

例如：

> 男，1984年3月13日19:20，台北市出生

缺什麼只追問什麼。固定原則：**Precision must be earned by input.**

## 不知道出生時間也可以先建立 partial Case

如果完全不知道出生時間，或只知道「早上」「下午」「大概晚上7、8點」或「大概13:00～15:00」，AI 不得自行補12:00、19:30或區間中點。

當 runtime 宣告 `natal.candidate_envelope` 可執行，而且出生日期、出生地、timezone 等必要 basis 足夠時，Python 會建立 Candidate Envelope：

```text
exact
bounded
unknown_time
external_only
```

對 `bounded / unknown_time`：

- Python 掃描不確定時間範圍內會造成盤面差異的 material timing states。
- 共同不變的資料列為 invariant facts。
- 會因候選時間不同而變的資料列為 candidate-dependent facts。
- 不用多數決把不確定資料變成確定資料。
- 不把任何候選盤冒充唯一正式命盤。

因此可以建立 `partial` Base Case，但需要唯一出生時辰才能成立的紫微／時柱／單一命盤個人化預測仍會被封鎖。

如果連出生地／timezone basis 都不足，runtime 仍會 fail closed，不猜地點。

## 地點解析

一般情況下，你只要提供出生地名稱。若 AI host 能可靠取得並確認地點資訊，會把 canonical name、經緯度與 IANA timezone 交給 deterministic runtime。

如果地點有多個合理候選，AI 應該請你確認，而不是選一個看起來最像的答案。

## 建立完成後先得到五份 Base Case

第一次本命建立完成後，不會先建立一堆空白追蹤檔。以 Kai 為例：

```text
Kai_7F3A2C_00_專案索引.md
Kai_7F3A2C_01_命盤核心摘要.md
Kai_7F3A2C_02_命盤資料校驗紀錄.md
Kai_7F3A2C_03_八字結構化資料包.md
Kai_7F3A2C_04_紫微基礎資料包.md
```

`00`～`04` 是 canonical slot；實際檔名永遠帶命主 label 與 short ID。

把這五份與 `命主索引.md` 加入同一個 Project。`00` 會記錄該命主目前已 materialize 的 Case 檔案與 Historical Calibration 狀態。

後續檔案在第一次真正有資料時才建立：

```text
Kai_7F3A2C_05_驗證事件紀錄.md
Kai_7F3A2C_06_流年追蹤紀錄.md
Kai_7F3A2C_07_問事追蹤紀錄.md
Kai_7F3A2C_08_重大決策紀錄.md
```

Case 的 record type 仍是 00～08，但不是第一天就一定有九個實體檔案。

## 第一次問未來前的 Historical Blind Calibration

若該命主 Case 尚未完成個人化歷史校準，而你第一次問未來趨勢／流年／行動決策，流程固定為：

1. AI 先確認 subject，再只使用該 subject 的 00～04 完成並鎖定 Stage 1 盲判。
2. Python 執行 `historical.activation_selector`，計算最近 10 個已完整結束的立春流年期。
3. Python deterministic 選出真正 4 個高活化年 + 1 個相對最低控制年；AI 不得改年、換年或因已知事件重排。
4. AI 對這 5 個年份先提出「年份＋主要事件領域／事件形式」的歷史盲讀。
5. 你逐題回答：符合／部分符合／不符合／想不起來；年份不對時直接提供正確年份與事件。
6. 只有你確認的實際事件才寫成已驗證事件；盲讀本身保留為命理推論，命中／偏移評價保留為已校驗資料。
7. Historical Calibration 完成後首次建立該命主的 05，再進入該未來問題的 Stage 2。

若 canonical 年份在對話中早已被揭露，會標成 `contaminated`；它仍保留在 Python 的 canonical Top 4 + Bottom 1，但不冒充真正盲測命中。

## 平常可以直接問

你可以說：

> 幫我看 Kai 今年下半年。

> 幫我看 Amy 明年的工作。

> 這次 Kai 是本人、Amy 是合作夥伴，幫我看合作互動。

角色是當次問題 context，不是永久 Subject Identity。

AI 會先 resolve subject，再判斷要讀哪些 Case 檔、是否需要 Historical Blind Calibration、要不要計算新的時間盤，以及哪些追蹤檔需要 materialize／更新。

## 第三方命盤不是必需品

有 Astralium 或其他 structured chart 時，可以拿來做 External / Project / Resolved cross-check；沒有也可以在輸入精度足夠時由 Project deterministic runtime 建立本命。

若有第三方資料，固定保留：

```text
External / Project / Resolved
MATCH / EQUIVALENT / CONFLICT / NOT_COMPARABLE
```

External 與 Project 不互相覆寫。

## 問未來時的固定流程

流年、近期趨勢與行動決策固定：

1. 先 resolve 命主。
2. 第一階段先盲判，不先讀該命主已驗證事件。
3. 取得需要的 deterministic 時間盤。
4. 完成第一版盤面判斷並鎖定。
5. 若 Case 尚未校準，先完成 Historical Blind Calibration。
6. 第二階段才讀已驗證事件做校準。
7. 輸出策略、風險、時間窗與信心。

第一版盲判一旦鎖定／進追蹤紀錄，不得事後為了配合結果而覆寫。

## 如果 AI 無法執行 Python

若 AI **無法執行 Python**，它必須直接說明，不得假裝已計算。此時可在本機執行同一個單檔 runtime：

```bash
python metaphysics_lab.py request --input request.json --pretty
```

也可從 stdin 傳 request：

```bash
python metaphysics_lab.py request --input - --pretty
```

把輸出的 JSON 貼回 AI，再依 `METAPHYSICS_CORE.md` 與 Project Instructions 做解讀。

如果連本機 Python 也沒有，AI 只能分析已經存在的可信盤面資料，不能宣稱新的 deterministic 計算已執行。

## 平常需要更新什麼

一般 runtime 升級通常只需要換新的 `metaphysics_lab.py`。固定核心與私人 Case 不跟著每次 runtime 更新重建。

只有 Project Contract 或 Case Schema 明確變更時，才依 [更新與版本同步](更新與版本同步.md) 處理固定 Markdown、`命主索引.md` 或 Case migration。

## 隱私

私人 `命主索引.md`、Case Markdown、出生資料、Historical Calibration 回答、私人事件、第三方 raw chart、PDF 與截圖都屬私人資料。不要提交回共用 GitHub repo。
