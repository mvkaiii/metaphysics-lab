# 快速開始

這份文件給第一次使用 Metaphysics Lab 的人。目標是先把最小可用環境建起來，再逐步補齊個人資料與追蹤紀錄。

完整細節請搭配：

- [安裝到 ChatGPT Project](安裝到ChatGPT-Project.md)
- [命盤資料準備指南](命盤資料準備指南.md)
- [Astralium 資料取得指南](Astralium資料取得指南.md)
- [更新與版本同步](更新與版本同步.md)

---

## 1. 準備出生基本資料

至少準備：

- 性別
- 西元出生年月日
- 原始出生時間
- 出生城市／國家
- 出生時間是否確定

出生時間不確定時，不要自行猜一個時辰。

---

## 2. 取得八字與紫微原始資料

建議準備一份八字結構化資料與一份紫微結構化資料。

可使用 Astralium：

https://getastralium.com/

也可以使用其他可靠排盤來源，但要保留來源、產出日期與時間口徑。

如果使用 Astralium，請看 [Astralium 資料取得指南](Astralium資料取得指南.md)。

---

## 3. 建立 ChatGPT Project

把 `core/核心提示詞.md` 複製到 Project Instructions。

Project 檔案至少加入：

```text
core/命理分析作業規範.md
core/命理推導計算規則.md
core/紫微流月推導規則.md
engine/project_bazi_calendar.py
engine/project_ziwei_month.py
```

建議再加入：

```text
tests/命理推導測試案例.md
tests/紫微流月推導測試案例.md
```

詳細步驟請看 [安裝到 ChatGPT Project](安裝到ChatGPT-Project.md)。

---

## 4. 建立私人 Case

從 `templates/` 複製空白模板，建立：

```text
命盤核心摘要.md
命盤資料校驗紀錄.md
驗證事件紀錄.md
流年追蹤紀錄.md
問事追蹤紀錄.md
重大決策紀錄.md
```

第一次不用全部填滿。

先完成：

1. 命盤資料校驗
2. 命盤核心摘要
3. 有把握的重要歷史事件

其他追蹤紀錄可以之後慢慢累積。

---

## 5. 第一次先做命盤校驗

不要一開始就問「今年會發生什麼」。

先請 Project 確認：

- 是否讀到 `命理分析作業規範.md`
- 出生年月日時與地點是否正確
- 八字四柱是否一致
- 日主與八字大運是否確認
- 紫微命宮、身宮、大限、流年是否可讀
- 不同來源是否有真太陽時、子時換日或其他口徑差異
- 哪些資料是原始盤面，哪些是 Project 推導

有差異先寫入 `命盤資料校驗紀錄.md`。

---

## 6. 建立命盤核心摘要

校驗完成後，把穩定、不容易變動的核心資料整理到：

`命盤核心摘要.md`

不要把所有歷史事件與所有命理解讀都塞進核心摘要。

---

## 7. 開始問本命或流年

本命分析可直接讀已校驗盤面。

未來趨勢、流年問事與行動決策則採：

**第一階段盲判 → 第二階段事件校準**

第一版完成以前，不先讀驗證事件來製造預測感。

---

## 8. 需要八字細時間層級時

使用：

`engine/project_bazi_calendar.py`

可建立：

- 流年
- 流月
- 流日
- 流時
- 對應天干十神

例如：

```bash
python engine/project_bazi_calendar.py "2026-08-20 17:12" --tz Asia/Taipei --day-master 丙 --pretty
```

結果屬於 Project 推導盤面，不是第三方排盤系統的直接輸出。

---

## 9. 需要紫微月份定位時

使用：

`engine/project_ziwei_month.py`

目前只做：

- 流年斗君
- 流月命宮
- 流月十二宮重排

紫微流月採農曆月；八字流月採節氣月。兩者同一天可能不同月，**不是 bug**。

紫微流日、流時、流月四化、流曜與細層飛化目前仍未啟用。

---

## 10. 開始累積追蹤資料

真正開始長期使用後，再逐步補：

- 已驗證事件
- 流年追蹤
- 問事追蹤
- 重大決策紀錄

第一版盲判一旦記錄，不要事後覆寫；實際結果另外追加。

---

## 11. GitHub 更新後要記得同步 Project

GitHub 與 ChatGPT Project 不會自動同步。

核心規則或 Python 引擎更新時，需要手動替換 Project 中的對應檔案；私人 Case 不要覆蓋。

請看 [更新與版本同步](更新與版本同步.md)。
