# 快速開始

這份文件只處理一件事：讓第一次使用 Metaphysics Lab 的人，不需要懂 repo、不需要懂 Python 模組，也能把系統放進 ChatGPT Project 或 Claude Project 開始使用。

## 你需要的三個檔案

```text
metaphysics_lab.py
METAPHYSICS_CORE.md
PROJECT_INSTRUCTIONS.md
```

其中真正要加入 Project 檔案區的是前兩個；`PROJECT_INSTRUCTIONS.md` 的內容要貼到 Project Instructions。

## 第一次設定

1. 建立一個新的 ChatGPT Project 或 Claude Project。
2. 上傳 `metaphysics_lab.py`。
3. 上傳 `METAPHYSICS_CORE.md`。
4. 開啟 Project Instructions，把 `PROJECT_INSTRUCTIONS.md` 全文貼進去。
5. 完整命盤、流年、合盤或重大決策分析，建議選 **High reasoning**。一般設定或簡單紀錄可用 Medium；Instant 不建議作為完整分析預設。
6. 輸入：**「開始建立我的命理專案。」**

接下來應由 AI 主導流程，不需要你自己決定要跑哪個命理模組。

## AI 第一次應該怎麼做

AI 會先確認是否已有 Case。若沒有，完整出生資料通常需要：

- 性別
- Gregorian 出生日期
- 出生時間
- 出生地

例如：

> 男，1984年3月13日19:20，台北市出生

缺什麼只追問什麼。若你說「大概晚上7、8點」，AI 不應自己猜成 19:30；輸入精度不足就保留候選或降低分析精度。

固定原則：**Precision must be earned by input.**

## 地點解析

一般情況下，你只要提供出生地名稱。若 AI host 能可靠取得並確認地點資訊，會把 canonical name、經緯度與 IANA timezone 交給 deterministic runtime。

如果地點有多個合理候選，AI 應該請你確認，而不是選一個看起來最像的答案。

## 建立完成後先得到五份 Base Case

第一次本命建立完成後，不會先建立一堆空白追蹤檔。AI 應先產生：

```text
00_專案索引.md
01_命盤核心摘要.md
02_命盤資料校驗紀錄.md
03_八字結構化資料包.md
04_紫微基礎資料包.md
```

把這五份加入自己的 Project。`00_專案索引.md` 會記錄目前已 materialize 的 Case 檔案與 Historical Calibration 狀態。

後續檔案在第一次真正有資料時才建立：

```text
05_驗證事件紀錄.md    ← 完成 Historical Blind Calibration 或新增已確認事件時
06_流年追蹤紀錄.md    ← 第一次需要永久保存流年／年度預測時
07_問事追蹤紀錄.md    ← 第一次需要永久保存一般問事時
08_重大決策紀錄.md    ← 第一次需要永久保存重大決策時
```

所以 Case 的 record type 仍是 00～08，但不是第一次就一定有九個實體檔案。

## 第一次問未來前的 Historical Blind Calibration

若 Case 尚未完成個人化歷史校準，而你第一次問未來趨勢／流年／行動決策，流程固定為：

1. AI 只使用 00～04 完成並鎖定該題 Stage 1 盲判。
2. Python 執行 `historical.activation_selector`，計算最近 10 個已完整結束的立春流年期。
3. Python deterministic 選出真正的 4 個高活化年 + 1 個相對最低控制年；AI 不得改年、換年或因已知事件重排。
4. AI 對這 5 個年份先提出「年份＋主要事件領域／事件形式」的歷史盲讀。
5. 你逐題回答：符合／部分符合／不符合／想不起來；年份不對時直接提供正確年份與事件。
6. 只有你確認的實際事件才寫成已驗證事件；盲讀本身保留為命理推論，命中／偏移評價保留為已校驗資料。
7. Historical Calibration 完成後首次建立 `05_驗證事件紀錄.md`，再進入該未來問題的 Stage 2 事件校準。

若某個 canonical 年份在對話中早已被你揭露，會標成 `contaminated`；它仍保留在 Python 的 canonical Top 4 + Bottom 1，但不冒充真正盲測命中。

## 平常可以直接問

Base Case 建好後，你可以直接問：

> 幫我看今年下半年。

> 幫我看 9 月工作。

> 我剛換工作，把這件事記錄進去。

AI 會依工作流程判斷要讀哪些 Case 檔、是否需要先做 Historical Blind Calibration、要不要計算新的時間盤，以及哪些紀錄應增量 materialize／更新。

## 第三方命盤不是必需品

有 Astralium 或其他 structured chart 時，可以拿來做 External / Project / Resolved cross-check；沒有也可以先由 Project deterministic runtime 建立本命。

若有第三方資料，固定保留：

```text
External / Project / Resolved
MATCH / EQUIVALENT / CONFLICT / NOT_COMPARABLE
```

External 與 Project 不互相覆寫。

## 問未來時的固定流程

流年、近期趨勢與行動決策固定：

1. 第一階段先盲判，不先讀已驗證事件。
2. 取得需要的 deterministic 時間盤。
3. 完成第一版盤面判斷並鎖定。
4. 若 Case 尚未校準，先完成 Historical Blind Calibration。
5. 第二階段才讀已驗證事件做校準。
6. 輸出策略、風險、時間窗與信心。

第一版盲判一旦鎖定／進追蹤紀錄，不得事後為了配合結果而覆寫。

## 如果 AI 無法執行 Python

有些 AI Project 環境可以保存 `.py`，但不代表當次對話一定能執行它。

若 AI **無法執行 Python**，它必須直接說明，不得假裝已計算。此時用本機 Python 執行同一個單檔 runtime：

```bash
python metaphysics_lab.py request --input request.json --pretty
```

也可從 stdin 傳 request：

```bash
python metaphysics_lab.py request --input - --pretty
```

把輸出的 JSON 貼回 AI，AI 再依 `METAPHYSICS_CORE.md` 與 Project Instructions 做解讀。

如果連本機 Python 也沒有，AI 只能分析你已經有的可信盤面資料，不能宣稱新的 deterministic 計算已經執行。

## 平常需要更新什麼

一般 runtime 升級通常只需要換新的 `metaphysics_lab.py`。固定核心與私人 Case 不跟著每次 runtime 更新重建。

只有 Project Contract 或 Case Schema 明確變更時，才需要依 [更新與版本同步](更新與版本同步.md) 處理固定 Markdown 或 Case migration。

## 隱私

私人 Case Markdown、出生資料、Historical Calibration 回答、私人事件、第三方 raw chart、PDF 與截圖都屬私人資料。不要提交回共用 GitHub repo。
