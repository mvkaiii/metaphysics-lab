# Metaphysics Lab v1.4.0

發布日期：**2026-08-26**

這份是給一般使用者看的發布說明。完整 qualification、版本治理與技術歷史請看 `VERSION.md` 與 `CHANGELOG.md`。

## 這版主要有什麼？

v1.4.0 把 v1.3.0 之後已經合併到 `main` 的 Project 管理、離線本命建立、歷史校準與細時間驗證正式收斂成同一個 Release。

一般使用者最直接會感受到：

- **Birth Data first**：只要提供命主稱呼、性別、出生日期、出生時間與出生地，就可以開始建立 Project；Astralium 仍是可選的外部交叉校驗來源，不是必要前置步驟。
- **Portable Offline Natal**：支援的 offline registry 地點可在不需要網路、不需要額外 Python 套件的條件下建立 Project 八字／紫微本命。
- **多人 Case 更安全**：Project Contract 1.1 / Case Schema 1.1 使用固定命主識別，避免不同人的命盤與事件紀錄混在一起。
- **漸進式 Case**：第一次只建立本命基礎檔案；驗證事件、流年追蹤、問事與重大決策紀錄有真正內容時才建立。
- **出生時間不確定時不亂猜**：可以保留候選狀態，不使用中點、預設時辰或多數決製造假精度。
- **歷史校準維持先盲判、後驗證**：第一次個人化未來分析可先鎖定盤面判斷，再用已確認事件校準；校準是建議而非強制門檻。
- **一般回答更白話**：內部狀態碼與工程實作詞不再直接當成一般使用者結論；除非明確要求技術檢查，系統優先說明實際意義與下一步。
- **細時間計算證據更完整**：八字流日／流時、紫微流日／流時與紫微月層都有新增的可重現 qualification 與邊界測試；其中紫微閏十二月下半月不再只有 synthetic internal coverage。

## 從 v1.3.0 升級

v1.4.0 不只是單純 Runtime 修正，Project Contract 與 Case Schema 已正式收斂到 1.1。因此從 v1.3.0 升級時，建議：

1. 替換 Project 裡的 `metaphysics_lab.py`。
2. 替換 `metaphysics_core.md`。
3. 把新版 `project_instructions.md` 全文重新貼到 Project Instructions。
4. 保留既有私人命盤、事件、流年、問事與重大決策紀錄，不要為了升版自行清空或重建。
5. 更新後讓 AI 執行 `runtime_info`，確認 Project Contract、Runtime Schema、Case Schema 與 capability 狀態。

Legacy Case 1.0 仍可讀，不要求破壞性重建。只有真的需要 schema migration 時，才走正式 `validate_case` / `migrate_case` 流程。

## 紫微月層與細時間驗證

v1.4.0 把近期 qualification 工作納入正式版本紀錄，但**沒有因此修改 production 命理公式，也沒有把 Experimental capability 自動升 Stable**。

目前新增的可重現證據包括：

- 八字流日／流時的日期、23:00、五鼠遁、DST 與單檔 runtime parity 邊界。
- 紫微流日／流時的 late-Zi、五鼠遁、DST 與單檔 runtime parity 邊界。
- 紫微月層公開 qualification：**86 個 month-oracle checks、0 mismatch**。
- 真實閏月十五／十六日、一般換月、農曆跨年、23:00 不獨立換月、DST 與下游 source reuse 邊界。
- 閏十二月下半月使用 pinned `lunar-python` 的實際下一個農曆月 continuity 作外部支持；`lunar-lite` 對這個稀有案例本身仍有直接 runtime oracle 限制，該限制保留在技術紀錄中。

這些 PASS 代表既有 deterministic 計算在指定公開證據與邊界上吻合，不代表命理預測準確率的科學證明。

## 能力成熟度沒有因發版自動改變

v1.4.0 是新的正式 GitHub Release identity，但 release 本身**不提升 capability maturity**。

例如紫微 Fine Cycle、紫微流日／流時、流曜、本命自動建立與歷史 activation selector 等既有 Experimental / On-demand 能力，仍維持原本狀態。實際執行能力以 `runtime_info` 為技術權威來源。

## 隱私與資料

私人出生資料、完整住址、Case Markdown、事件紀錄、PDF、截圖與私人 Astralium raw chart 不應提交到共用 repo。Release 只包含公開 runtime、核心規則與 Project Instructions。
