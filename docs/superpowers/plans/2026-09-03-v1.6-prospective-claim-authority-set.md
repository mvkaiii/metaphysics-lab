# v1.6 Prospective Claim-Authority Set Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add an outcome-blind composite claim-authority set that binds every S1 INCLUDE case's validated per-case claim-authority manifest into one deterministic batch authority digest without changing prediction, EFA, S1 eligibility, or scoring semantics.

**Architecture:** Add one isolated distribution module that validates the frozen S1 source manifest with its frozen protocol, derives the deterministic INCLUDE case set, validates one existing per-case claim-authority manifest per INCLUDE case, and emits a canonical sorted composite authority. A thin private-artifact CLI may serialize the authority outside git. Existing S1 claim-universe validation remains unchanged; integration tests prove it accepts the composite profile/digest strictly as provenance while preserving exact case/claim completeness.

**Tech Stack:** Python 3.9, stdlib (`json`, `hashlib`, `argparse`, `pathlib`), `unittest`, existing `engine.distribution.claim_consumption_sampling_eligibility`, existing `engine.distribution.claim_authority_manifest`, existing deterministic AI distribution builder.

**Spec:** `docs/superpowers/specs/2026-09-03-v1.6-prospective-claim-authority-set-design.md`

### Task 2: Composite authority builder/validator GREEN

**Files:**
- Create: `engine/distribution/prospective_claim_authority_set.py`
- Test: `tests/test_distribution_prospective_claim_authority_set.py`

**Interfaces:**
- Consumes:
  - `validate_sampling_protocol(protocol) -> dict`
  - `validate_sampling_source_manifest(source_manifest, protocol) -> dict`
  - deterministic S1 INCLUDE derivation from validated source records using the same fixed precedence as S1
  - `validate_claim_authority_manifest(manifest) -> dict`
- Produces:
  - `PROSPECTIVE_CLAIM_AUTHORITY_SET_SCHEMA = "v1.6-prospective-claim-authority-set.v1"`
  - `PROSPECTIVE_CLAIM_AUTHORITY_SET_PROFILE = "lin_tianji_prospective_claim_authority_set_v1"`
  - `build_claim_authority_set(...) -> dict`
  - `validate_claim_authority_set(...) -> dict`

- [ ] **Step 1: Implement canonical helpers and exact schemas**

Use the repository canonical form:

```python
def _canonical_bytes(value: object) -> bytes:
    return json.dumps(
        value,
        ensure_ascii=False,
        sort_keys=True,
        separators=(",", ":"),
        allow_nan=False,
    ).encode("utf-8")


def _digest(value: object) -> str:
    return hashlib.sha256(_canonical_bytes(value)).hexdigest()
```

Reject missing/unknown fields at input, member, and serialized-output levels. Validate lowercase 64-character SHA-256 strings.

- [ ] **Step 2: Validate source census before member authorities**

The builder must call:

```python
validated_protocol = validate_sampling_protocol(sampling_protocol)
validated_source = validate_sampling_source_manifest(source_manifest, validated_protocol)
```

Derive the INCLUDE IDs mechanically from validated source records using frozen S1 status precedence. Do not accept caller-supplied INCLUDE status.

- [ ] **Step 3: Validate each member and exact-match the census**

Each member input must contain exactly:

```json
{
  "opaque_case_id": "opaque-id",
  "source_record_digest": "<sha256>",
  "claim_authority_manifest": {"...":"existing validated per-case manifest"}
}
```

For each member:

```python
validated_manifest = validate_claim_authority_manifest(member["claim_authority_manifest"])
```

Require member `source_record_digest` to equal the digest on the matching validated source record. Require the member case-ID set to equal the deterministic INCLUDE set exactly. Reject duplicates, excluded cases, and foreign cases.

- [ ] **Step 4: Emit canonical sorted authority**

Output body fields exactly:

```json
{
  "schema_version": "v1.6-prospective-claim-authority-set.v1",
  "claim_authority_profile": "lin_tianji_prospective_claim_authority_set_v1",
  "source_manifest_digest": "<validated source digest>",
  "case_authorities": [
    {
      "opaque_case_id": "opaque-id",
      "source_record_digest": "<sha256>",
      "claim_authority_profile": "lin_tianji_prospective_claim_authority_manifest_v1",
      "claim_authority_digest": "<validated per-case digest>"
    }
  ],
  "promotion_allowed": false
}
```

Sort `case_authorities` lexicographically by `opaque_case_id`, then append `claim_authority_digest = SHA256(canonical body)`.

- [ ] **Step 5: Implement serialized validator**

`validate_claim_authority_set(payload, source_manifest, sampling_protocol)` must revalidate protocol/source census, require exact output fields/profile, exact-match case IDs and source-record digests, validate the set digest, and return normalized canonical content without consulting outcomes or prediction outputs.

- [ ] **Step 6: Run focused GREEN**

```bash

  tests.test_distribution_prospective_claim_authority_set \
  tests.test_distribution_claim_authority_manifest \
  tests.test_v16_claim_consumption_sampling_eligibility
```

Expected: all GREEN.
