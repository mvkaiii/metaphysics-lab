## Resolution 1｜Task 3 Ziwei regression modules 鎖定實際存在檔名

主 plan Task 3 Step 5 中的模糊 fallback 取消。正式 regression command 固定為：

```bash
python -m unittest \
  tests.test_distribution_ziwei_structural_interpretation \
  tests.test_distribution_forecast \
  tests.test_ziwei_flowing_stars \
  tests.test_ziwei_flowing_star_view \
  tests.test_ziwei_flying \
  tests.test_ziwei_fine_cycle_integration \
  tests.test_ziwei_fine_cycle_stems -v
```

不得使用不存在的 `tests.test_ziwei_fine_cycle`，也不得在執行時自由挑「最接近」的 module。

## Resolution 2｜Task 2 history-boundary test 使用精確錯誤型別

主 plan Task 2 的 direct Bazi interpreter history-boundary test 不使用 `assertRaises(Exception)`。

正式要求：

```python
from engine.distribution.errors import DistributionError

with self.assertRaises(DistributionError) as caught:
    interpret_bazi_structural_features(context, "yearly", "c" * 64)
self.assertEqual(caught.exception.code, "invalid_structural_interpretation_payload")
```

Phase 3.5 不接受 broad-exception test 作為 anti-contamination contract。

## Resolution 3｜`tests/test_ai_distribution_build.py` 不列為 Phase 3.5 修改檔

已確認現有 build test 的 bundle input discovery 對 `engine/` 採 allowlisted recursive discovery，沒有硬編碼 Phase 3.5 source module 清單。

因此 Phase 3.5 正式計畫：

- `tests/test_ai_distribution_build.py` **保持不修改**；
- 新 source modules 應由現有 `discover_bundle_inputs()` 自動納入；
- 既有 `tests.test_ai_distribution_build` 作 regression gate，證明新增 modules 沒有破壞 builder contract。

如果 implementation 出現此 test 失敗，先找 builder/source root cause；不得預先修改 test 來接受新行為。

## Resolution 4｜Task 4 clean-tree gate 順序修正

主 plan Task 4 Step 12 在 source commit 前執行 `git diff --exit-code` / `git status --porcelain` 會與尚未 commit 的合法變更衝突，因此順序修正如下。

### Step 12a｜Commit 前只做 deterministic rebuild / patch sanity

```bash
python tools/build_ai_distribution.py
python tools/build_ai_distribution.py --check
git diff --check
```

Expected：build `--check` exit 0；`git diff --check` exit 0。此時 working tree 有尚未 commit 的 Phase 3.5 正式變更是合法狀態，**不得**要求 clean tree。

### Step 12b｜Commit Task 4

依主 plan Task 4 commit file set 提交 source、tests、docs、workflow、generated artifacts；不包含 `tests/test_ai_distribution_build.py`。

### Step 12c｜Commit 後才執行 strict clean-tree gate

```bash
python tools/build_ai_distribution.py --check
python -m unittest discover -s tests -p 'test_*.py' -v
python -m compileall engine tests tools
git diff --exit-code
test -z "$(git status --porcelain)"
```

Expected：全部 exit 0，且 working tree 為空。

若 commit 後重新 build 產生 dirty generated artifact：

1. 視為 deterministic generation blocker；
2. 找 Root Cause；
3. 以最小 generated-artifact 修正建立新 commit；
4. 對新 exact SHA 重跑完整 gates；
5. 不得弱化 clean-tree gate。

## Resolution 5｜Task 4 final `git add` 集合移除條件式 add

主 plan 中：

```bash
git add tests/test_ai_distribution_build.py 2>/dev/null || true
```

正式取消。

Task 4 不使用 `|| true` 隱藏 staging 問題。正式 staging set 只包含 plan 明定會修改的 files；若實際 diff 出現非預期檔案，先審查 Root Cause，再決定是否屬於 approved Phase 3.5 scope。
