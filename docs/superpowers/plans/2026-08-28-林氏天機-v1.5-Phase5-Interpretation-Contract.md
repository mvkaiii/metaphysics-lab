# 林氏天機 v1.5 Phase 5 Interpretation Contract Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在不改寫 Phase 3 ranking authority、不讓 Phase 4 歷史個人化升格成盤面真相的前提下，建立 deterministic Interpretation Contract，讓 AI 能安全使用 ranking、personalization、local windows 與 locked forecast 進行台灣繁體中文解讀與現實策略。

**Architecture:** 新增 `engine/distribution/interpretation_contract.py` 作為 Phase 3/4 與 AI 解讀之間的獨立 boundary。它只驗證並整理既有 deterministic metadata：Phase 3 base ranking 是唯一 ranking authority，Phase 4 只影響 presentation order，Phase 3 local-window metadata 只可降低 specificity，Phase 1 locked forecast 只提供 immutable prospective boundary；Phase 5 本身不重新計 score、rank、maturity specificity、事件機率或歷史準確率。

**Tech Stack:** Python 3.9+、stdlib `hashlib` / `json` / `typing`、現有 `engine.distribution` runtime/capability registry、`unittest`、deterministic AI distribution builder、GitHub Actions feature validation workflow。

**Spec:** `docs/superpowers/specs/2026-08-28-林氏天機-v1.5-Phase5-Interpretation-Contract-設計.md`

## Global Constraints

- Phase 5 profile 固定為 `lin_tianji_interpretation_contract_v1-exp`。
- Phase 3 `lin_tianji_rank_v1-exp` 仍是唯一 base ranking authority。
- Phase 4 `lin_tianji_historical_personalization_v1-exp` 保持 `ranking_authority=false`，只可調整既有 domain / event-family 的 presentation order。
- Phase 5 不得新增或刪除 Phase 3 domain / event-family candidate。
- Phase 5 不得修改 Phase 3 ordinal score、base rank、EvidenceFeature、dependency relation 或 `ranking_digest`。
- Phase 5 不建立第二套 maturity / specificity scoring policy；maturity 只可作 explanation metadata。
- `effective_specificity` 只能等於 Phase 3 `allowed_specificity`，或被 Phase 3 已產生的 applicable local-window cap 降低。
- `PRIMARY_DOMAIN_DISPLAY_LIMIT = 3`；這只是 UX organization，不參與 ranking / eligibility / personalization。
- 現實背景不得改變 ranking、personalization、local-window classification、forecast confidence 或 contract digest。
- cutoff 前已知事件不得被改寫為 prospective hit；Stage 2 不得改寫 Stage 1 locked forecast。
- Phase 5 不輸出 probability、accuracy estimate、命中率或 numeric weight / threshold rationale。
- `locked_forecast` 只接受 Phase 1 `lock_prospective_forecast()` 的 immutable object，必須重驗 `canonical_digest` 與 anchor equality。
- 一般使用者語言固定台灣繁體中文；工程欄位只在技術稽核 context 使用。
- 「林氏天機」是 method identity，不是每句命理解讀的權威前綴。
- 本 Phase 不提升任何 capability maturity，不改 Bazi / Ziwei 排盤公式，不新增 Case Schema。
- 測試 fixtures 只用 synthetic / outcome-free data，不以 Kai 2026 已知結果調 mapping、threshold 或 expected ranking。
- 每個 Task 先 RED、再最小 GREEN、focused tests、commit；Task 5 再跑完整 Phase Gate。
- Phase 5 完成後停在 merge-ready；未經使用者明確授權不得 merge。

PRIMARY_DOMAIN_DISPLAY_LIMIT = 3


def _raise(message: str, details=None):
    raise DistributionError(
        "invalid_interpretation_contract",
        message,
        {} if details is None else dict(details),
    )


def _canonical_bytes(value):
    try:
        return json.dumps(
            value,
            ensure_ascii=False,
            sort_keys=True,
            separators=(",", ":"),
            allow_nan=False,
        ).encode("utf-8")
    except (TypeError, ValueError) as exc:
        _raise("interpretation contract input must be canonical JSON", {"error": str(exc)})


def _digest(value):
    return hashlib.sha256(_canonical_bytes(value)).hexdigest()
