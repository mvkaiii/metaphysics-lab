# Metaphysics Lab v1.7 Capability Manifest v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 把既有各 engine `_CAPABILITIES` registry 擴充成 v1.7 的單一 capability truth，讓 `runtime_info()`、文件與 release validation 都從同一份 machine-readable authority 驗證 implementation / maturity / routing / qualification 狀態。

**Architecture:** 不建立第二份人工維護 manifest。`engine/distribution/manifest.py` 繼續聚合各 engine capability registry，新增 manifest schema/version 與欄位正規化／驗證；`runtime_info()` 對外回傳 manifest version 與 canonical capabilities。文件只保留人類摘要，由 contract tests 檢查不得與 runtime truth 漂移。

**Tech Stack:** Python 3.9+、標準函式庫、`unittest`、現有 deterministic AI distribution build、GitHub Actions。

**Spec:** `docs/superpowers/specs/2026-09-08-v1.7-reliability-guided-inquiry-design.md`（使用者已於 2026-09-08 核准）

## Global Constraints

- Capability authority 仍是各 engine `_CAPABILITIES` registry；不得新增另一份手工 authority JSON。
- `capability_manifest_version = "1.0"`。
- Project Contract 目標版本 `1.2`；Case Schema 維持 `1.1`。
- 不因 v1.7 release 自動提升任何 v1.6 capability maturity / routing。
- Selector v2 / Interpretation v2 不 promotion。
- Materialized 不等於 Stable。
- Runtime Schema 若 envelope shape 不必改，維持 `1.1`。
- 所有輸出 deterministic；同一 source tree 的 manifest canonical JSON 必須 byte-identical。

```python
class CapabilityManifestV1Tests(unittest.TestCase):
    def test_manifest_exposes_version_and_sorted_capabilities(self):
        manifest = load_capability_manifest()
        self.assertEqual(manifest["manifest_version"], "1.0")
        self.assertEqual(
            list(manifest["capabilities"]),
            sorted(manifest["capabilities"]),
        )

    def test_required_core_fields_are_present(self):
        required = {
            "id", "implementation", "maturity", "routing",
            "rule_version", "module", "dependencies",
        }
        manifest = load_capability_manifest()
        for capability_id, capability in manifest["capabilities"].items():
            self.assertTrue(required <= set(capability), capability_id)
```

- [ ] **Step 3: Implement minimal schema normalization**

Add in `engine/distribution/manifest.py`:

```python
CAPABILITY_MANIFEST_VERSION = "1.0"
_REQUIRED_FIELDS = frozenset({
    "id", "implementation", "maturity", "routing",
    "rule_version", "module", "dependencies",
})
_OPTIONAL_FIELDS = frozenset({
    "output_classification", "ranking_authority",
    "qualification_status", "supported_scopes", "required_inputs",
    "supported_profiles", "conditional_dependencies",
```

`validate_capability_registry_entry()` must reject:
- id/key mismatch;
- missing required fields;
- unknown top-level fields;
- invalid `implementation` outside `implemented|not_implemented`;
- invalid `maturity` outside `stable|experimental`;
- invalid `routing` outside `default|on_demand|unavailable`;
- non-string dependency ids;
- non-JSON-safe values.

`load_capability_manifest()` must return:

```python
{
    "manifest_version": "1.0",
    "capabilities": {capability_id: normalized_entry, ...},
}
```
