# 林氏天機 v1.5｜Phase 4 Historical Personalization Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在 Phase 3 immutable base ranking 之後加入 deterministic Historical Personalization Layer，只用 finalized Historical Calibration 的 machine-readable 結構化紀錄，有限重排既有 domains / event families，且永遠不能新增當期訊號、改寫 base ranking digest 或突破 specificity ceiling。

**Architecture:** 採已批准的方案 A：`Phase 3.5 structural evidence → Phase 3 base ranking → Phase 4 historical personalization`。Phase 4 由獨立 policy module 定義封閉 normalization / ordinal adjustment contract，由 core module 驗證 base ranking、正規化 finalized historical records、計算 bounded modifiers、輸出 personalized ordering 與獨立 digest；runtime 只新增 `personalize_ranking` action，不把 personalization 邏輯塞入 `evidence_ranker.py`、`forecast.py` 或 `calibration.py`。

**Tech Stack:** Python 3.9、stdlib `hashlib/json`、既有 `DistributionError`、`unittest`、GitHub Actions、`tools/build_ai_distribution.py` deterministic portable bundle。

**Spec:** `docs/superpowers/specs/2026-08-28-林氏天機-v1.5-Phase4-Historical-Personalization-設計.md`

## Global Constraints

- Personalization profile identity 固定為 `lin_tianji_historical_personalization_v1-exp`。
- Phase 3 base ranking authority 固定為 `lin_tianji_rank_v1-exp`；Phase 4 不建立新的 base ranking authority。
- Phase 4 不得修改 `base_ranking.policy_version`、`target_scope`、`evaluated_features`、`opened_domains`、domain set、`ordinal_score_scaled`、`allowed_specificity`、base event-family candidate set 或 `ranking_digest`。
- History 不得新增 domain、event family、Bazi/Ziwei structural relation、current strength、current timing trigger 或 current target evidence。
- `allowed_specificity` 是 Phase 3 硬上限；Phase 4 不升級、不重算、不覆蓋。
- Phase 4 v1 只讀 `record_type == historical_calibration` 的 finalized Historical Calibration machine-readable fields；不得把 `user_confirmed_actual.actual_event`、`blind_prediction.hypothesis`、06/07/08 prospective records、research notes 或 Kai 2026 outcomes 餵入 scoring。
- `blindness_status == contaminated`、`verification_state == cannot_recall`、unscorable records 不得影響 modifiers；control records v1 只做 audit。
- Legacy normalization 必須 exact / closed / versioned；至少支援 `工作／職責 → career`，禁止 fuzzy matching、embedding、LLM semantic guess；legacy event-family v1 沒有明確 alias 時不得猜。
- 同一 `predicted_flow_year` 只有第一筆有效 blind high-activation record有 scoring authority；Case canonical append order / input order決定 first-valid-blind。
- Domain-specific scoring 僅接受 normalization 後恰好一個 domain；family-specific scoring 僅接受 normalization 後恰好一個 family。
- Domain / family evidence units 固定：`matched = +2`、`partial = +1`、`missed = -2`、`unscorable = excluded`。
- 單一 domain / family 至少 2 筆 eligible records 才能形成 active personalization；modifier cap 固定 `[-2, +2]`。
- 所有 modifier / ordering score 都是 deterministic ordinal adjustment，不是 probability、likelihood 或命中率。
- `history=[]`、`uncalibrated`、全 contaminated/cannot_recall/unscorable/unmapped/insufficient 時必須 deterministic no-op，base order byte-semantically preserved，仍產生 audit digest。
- 自由文字內容變更不得改變 `historical_source_digest`、modifier、personalized ordering 或 `personalization_digest`。
- 新 Phase 4 測試只用 synthetic finalized records / outcome-free base rankings；不得用 Kai 2026 outcome 做 expected answer 或 threshold tuning。
- 每個 Task 嚴格 TDD：先 RED、確認失敗原因正確，再最小 GREEN；Task focused tests 全綠才 commit。
- Generated artifacts 只在最後 integration task rebuild；手改 `dist/ai/*` 禁止。

def _canonical_digest(value: object) -> str:
    raw = json.dumps(
        value,
        ensure_ascii=False,
        sort_keys=True,
        separators=(",", ":"),
        allow_nan=False,
    ).encode("utf-8")
    return hashlib.sha256(raw).hexdigest()
