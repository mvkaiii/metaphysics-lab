# Metaphysics Lab v1.6｜Benchmark, Qualification & Release Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在 Selector v2 與 Interpretation vNext 都通過 focused gates 後，建立可重現的 V0–V4 離線 benchmark、cutoff-safe V4、private qualification aggregate、AC-01..AC-10 release runner，最後才把 v2 profiles 切為 v1.6.0 正式預設並完成 distribution / release qualification。

**Architecture:** Benchmark 不在測試中即時呼叫任何 LLM；它只評估已鎖定、結構化的 variant outputs，因此同一 fixture 必須產生相同結果。私人 Case 由外部／未追蹤 input 進 qualification tool，公開 repo 只保存 aggregate counts、digests 與 gate status。Release integration 採「先 qualification、後 default flip、再 rebuild distribution」；v1.5.0 release files/workflows/tests 保持歷史 snapshot，不被改寫。

**Tech Stack:** Python 3.9+、stdlib argparse/datetime/hashlib/json/pathlib、existing distribution runtime、pytest/unittest、existing deterministic distribution/release builders、GitHub Actions YAML。

**Spec:** `docs/superpowers/specs/2026-08-31-v1.6-Selector-v2-Interpretation-vNext-設計.md`

## Global Constraints

- This plan starts only after both `2026-08-31-v1.6-Selector-v2.md` and `2026-08-31-v1.6-Interpretation-vNext.md` exit gates are GREEN.
- Historical bake-off is retrospective research, not prospective accuracy. Reports must label it `historical_debug_only`.
- V0–V4 benchmark uses normalized structured predictions recorded before scoring; the evaluator never generates or rewrites prediction prose.
- V4 must be cutoff-safe per target. Any personalization record with `knowledge_available_at > knowledge_cutoff_at` is a hard contamination error; the evaluator must fail closed rather than silently drop it.
- Accuracy-like metrics, honesty/safety metrics and UX/explanation metrics remain separate. No single “overall accuracy score” may combine them.
- Public benchmark fixtures are fictional/synthetic only. No private name, birth data, event text or exact private Case dump enters the repository.
- Private qualification input may live outside the repo; public qualification output contains aggregate metrics and digests only.
- Private qualification must never promote an experimental capability to stable by itself.
- v1.5.0 tag/release, `tests/test_v15_release_contract.py`, `.github/workflows/lin-tianji-v1.5-validation.yml`, `.github/workflows/release-v1.5.yml`, and v1.5 release evidence remain immutable historical artifacts.
- v1.6 software version = `1.6.0`.
- On v1.6 release, Distribution Runtime version = `1.2-exp`; Project Contract = `1.1`; Runtime Schema = `1.1`; Case Schema = `1.1` unless an earlier implementation plan explicitly proved and documented an unavoidable schema incompatibility.
- `core/命理推導計算規則.md` document version becomes `v1.5` because Historical Selector deterministic behavior changes; this document version is independent from Core release version `v1.6.0`.
- Default selector profile may switch to v2 only after Selector focused gate, AC-01/03/04, private aggregate review, full regression and distribution parity are GREEN.
- Default interpretation profile may switch to v2 only after Interpretation focused gate, AC-02/05/06/07/08, cutoff gate, private aggregate review, full regression and distribution parity are GREEN.
- No release claim may say v1.6 “proved more accurate” from historical bake-off alone. Allowed language: improved control qualification, reduced unsupported specificity, added abstention and evidence traceability; prospective accuracy remains to be accumulated.
- If GitHub Actions starts but runs zero steps / fails before checkout, report runner/startup failure; never label CI GREEN.
