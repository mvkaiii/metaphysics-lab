# Metaphysics Lab v1.7 Prospective Validation 2.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在完全保留 v1.5/v1.6 prospective lock byte identity 的前提下，加入 claim-level validation context，正式區分 clean prospective、conditional prospective、hidden existing reality 與 retrospective calibration，並讓評估 denominator 不再混算。

**Architecture:** `engine/distribution/prospective.py` 保留原 v1 contract 路徑，新增 deterministic context classifier 與明確 versioned v2 claim lock。`prospective_evaluation.py` 驗證 v1/v2 lock，對 v2 claim 回傳 scoring bucket；舊 v1 evaluation output 不變。Portable runtime 新增 classifier/evaluation routes，但不把 retrospective claim 塞進 prospective lock。

**Tech Stack:** Python 3.9+、標準函式庫、`unittest`、canonical JSON + SHA256、既有 Case tracking / prediction validation infrastructure。

**Spec:** `docs/superpowers/specs/2026-09-08-v1.7-reliability-guided-inquiry-design.md`（使用者已於 2026-09-08 核准）

## Global Constraints

- Existing v1 `METHOD_VERSION = "lin_tianji_v1.5-exp"` output and canonical digest must remain byte-compatible.
- Old payload shape `{anchor, claims}` must continue to mean v1 contract.
- v2 is opt-in with explicit contract version; no silent reinterpretation of old locks.
- Four context classes are fixed:
  - `clean_prospective`
  - `conditional_prospective`
  - `hidden_existing_reality`
  - `retrospective_calibration`
- `retrospective_calibration` cannot enter a prospective lock.
- Hidden/conditional claims never enter the clean denominator.
- Runtime never guesses epistemic state from prose; classification consumes explicit booleans/status only.
- Historical Calibration remains the authority path for retrospective validation.
