# Metaphysics Lab v1.7 Case Doctor + Reconciliation Planner Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 新增只讀 `diagnose_case` 與 deterministic dry-run `plan_case_reconciliation`，讓使用者知道 canonical Case、legacy/generic 檔案、duplicate/conflict 與安全處理方向，而不自動刪除或事後改寫證據。

**Architecture:** 新建 `engine/distribution/case_doctor.py`，重用 `case_pack.validate_case()`、front matter parser、subject-aware filename contract 與 tracking record parser；Doctor 先把 Project 檔案分類成 canonical Case / formal legacy Case / generic legacy / unrelated，再建立 findings。Planner 只能依 canonical diagnostic result 產生 dry-run actions；真正 mutation 仍走既有 `migrate_case`、`update_case_record`、`subject.rename` 等 authority path。

**Tech Stack:** Python 3.9+、標準函式庫、`unittest`、canonical JSON + SHA256、現有 Case Schema 1.1。

**Spec:** `docs/superpowers/specs/2026-09-08-v1.7-reliability-guided-inquiry-design.md`（使用者已於 2026-09-08 核准）

## Global Constraints

- Case Schema 維持 `1.1`；不得為 Doctor 順手 bump schema。
- Doctor / Planner 都不得刪檔、rename 或寫 Case。
- Exact duplicate 可 deterministic 辨識；semantic possible duplicate 只能 WARN，不自動 merge。
- Historical Blind Set、locked prospective forecast、verified event 等 evidence-bearing record 不得被覆寫。
- `BLOCKED` 必須停止一般 Guided Inquiry，改走 recovery guidance。
- 所有 plans deterministic；相同輸入 canonical JSON byte-identical。
- Generic legacy 不等於 formal Case Schema 1.0；兩者必須分開標示。

### Task 4: Build deterministic reconciliation dry-run planner

**Files:**
- Modify: `engine/distribution/case_doctor.py`
- Create: `tests/test_v17_case_reconciliation.py`

**Interfaces:**
- Produces: `plan_case_reconciliation(payload: Mapping[str, object]) -> dict`
- Input:

```python
{
    "project_files": {...},
    "diagnostic": diagnose_case(...),
}
```

- Output:

```python
{
    "status": "no_change|safe_plan|blocked",
    "actions": list[dict],
    "requires_user_confirmation": bool,
    "preserve_files": list[str],
    "do_not_delete_yet": list[str],
    "conflicts_requiring_user_choice": list[dict],
    "plan_digest": "<sha256>",
}
```

- [ ] **Step 1: Write tamper-detection RED test**

Planner must recompute Doctor result from `project_files`; if supplied diagnostic digest/content differs:

```python
with self.assertRaises(DistributionError) as caught:
    plan_case_reconciliation(payload)
self.assertEqual(caught.exception.code, "case_diagnostic_mismatch")
```

- [ ] **Step 2: Write safe-plan RED tests**

Expected action types are allowlisted only:

```text
ignore_exact_duplicate
import_missing_record_via_update_case_record
migrate_formal_legacy_case
request_subject_resolution
request_semantic_duplicate_resolution
retain_unrelated_file
```

No action type named `delete`, `overwrite`, `replace_locked_forecast`, or generic `apply`.

- [ ] **Step 3: Run RED**

```bash
python -m unittest tests.test_v17_case_reconciliation -v
```

- [ ] **Step 4: Implement dry-run planner**

Rules:
- `PASS` + no legacy → `no_change`, `requires_user_confirmation=False`;
- BLOCKED diagnostic → `blocked`;
- missing structured legacy record with safe canonical target → propose `import_missing_record_via_update_case_record`, but do not mutate;
- semantic ambiguity → place in `conflicts_requiring_user_choice`;
- all legacy files remain in `do_not_delete_yet` until post-reconciliation re-diagnosis is PASS.

- [ ] **Step 5: Determinism test**

Run planner twice and with reversed mapping order; payload + digest must match exactly.

- [ ] **Step 6: Run GREEN**

