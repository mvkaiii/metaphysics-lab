# Metaphysics Lab v1.7 Guided Inquiry Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 讓 AI 在合適時機主動提供 3～4 個高價值下一問方向，預設 3 個；若使用者已直接提出 substantive question，先回答再顯示衍生方向，且導航不得污染盲判、超過 specificity ceiling 或繞過 capability / Case safety gate。

**Architecture:** 新建純 deterministic `engine/distribution/guided_inquiry.py`。Runtime 不生成自然語言問題，只輸出 suggestion intent、domain/scope、requested/max specificity、reason code 與 suppression 狀態；AI 依 `core/AI工作流程.md` 將 intents 翻成自然繁體中文。Guided Inquiry 只消費當次已合法 materialize 的 structured state，不讀歷史事件內容來生成第一階段建議。

**Tech Stack:** Python 3.9+、標準函式庫、`unittest`、既有 capability manifest / Case Doctor / interpretation metadata、AI distribution build。

**Spec:** `docs/superpowers/specs/2026-09-08-v1.7-reliability-guided-inquiry-design.md`（使用者已於 2026-09-08 核准）

## Global Constraints

- 主動顯示 3～4 題；預設 3 題。
- 第四題只有在明確、互不重複且高價值時才加入。
- 若不足 3 個合法建議，整個 suggestion block suppress，不顯示 1～2 個、不硬湊。
- Opening message 已有 substantive question → 先回答，再 post-answer suggestions。
- Free-form input 永遠 first-class；建議不是強制選單。
- `diagnose_case.health == BLOCKED` → suppress 一般導航，先 recovery guidance。
- Historical Blind Set 等待事件揭露 → suppress。
- 補必要欄位 / mutation confirmation / runtime blocking error / 純安裝下載版本操作 → suppress。
- Navigation 不得讀 verified-event text 來產生第一階段建議。
- Suggestion requested specificity 不得高於當前 evidence ceiling。
- Experimental capability 不因 suggestion 被升格 maturity。

**Interfaces:**
- Entry order:

```text
1 integrity (WARN only, if actionable)
2 overview
3 domain/deep starting point

```

- [ ] **Step 1: Write entry RED tests**

`PASS` entry must not show integrity.

`WARN + case_integrity_action_available=True` must put integrity at index 0.

Fourth suggestion is allowed only when its normalized key `(type, domain, target_scope)` differs from all first three.

- [ ] **Step 2: Define safe entry defaults**

Runtime may use only broad, non-predictive entry intents. It must not claim a life domain is activated without running analysis. Safe generic intents may include:

```text
overview / yearly overview
career domain inquiry
finance/resources domain inquiry
relationship/cooperation domain inquiry
```

If current Project capabilities do not support a target scope, caller must omit it from `time_refinement_scopes`; runtime never invents capability support.

- [ ] **Step 3: Implement default=3, conditional fourth**

ranked = unique_legal_candidates(...)

    selected.append(ranked[3])
if len(selected) < 3:
    suppress

### Task 4: Post-answer ranking + specificity hard gate

**Files:**
- Modify: `engine/distribution/guided_inquiry.py`
- Modify: `tests/test_v17_guided_inquiry.py`

**Interfaces:**
- Post-answer priority:

```text
deep_dive
decision (only if actionable_options_present)
validation (only if forecast_lock_eligible)
time_refine or related_domain as remaining distinct candidate
```

- [ ] **Step 1: Write specificity RED tests**

Define ordering:

```python
_SPECIFICITY = {
    "broad_domain": 0,
    "event_family": 1,
    "event_form": 2,
}
```

Every selected suggestion must satisfy:

```python
_SPECIFICITY[suggestion["requested_specificity"]] <= _SPECIFICITY[current_answer["allowed_specificity"]]
```

- [ ] **Step 2: Add concrete anti-inflation scenario**

Given current answer allows only `event_family` for `career`, no suggestion may request `event_form` such as a specific promotion/title outcome.

Structured output should remain abstract, e.g.:

```python
{
    "type": "deep_dive",
    "domain": "career",
    "requested_specificity": "event_family",
    ...
}
```

Natural-language examples belong in AI docs, not runtime.

- [ ] **Step 3: Implement legal time refinement**

Only choose `time_refine` from caller-provided `time_refinement_scopes`. Do not assume yearly→monthly→daily is always available.

- [ ] **Step 4: Implement related-domain fallback conservatively**

Only use domains explicitly supplied in `current_answer.related_domains`; do not generate a generic “感情/健康/財務也可以問” list after every answer.
