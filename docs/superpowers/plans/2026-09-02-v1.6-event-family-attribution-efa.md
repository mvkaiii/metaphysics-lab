# v1.6 Event-Family Attribution（EFA）Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在不修改 Phase 3 ranking、C1、Q1/T1 或既有 event-family taxonomy 的前提下，建立 deterministic EFA，保留 `EvidenceFeature -> event_family_support` 的完整 provenance，讓後續 child-level authority 能同時保住 recall 與 precision。

**Architecture:** 新增純 Python `event_family_attribution.py`，同時讀取 frozen Phase 3 ranking 與完整 Structural Interpretation EvidenceFeature 集合。Phase 3 仍決定 domain/candidate universe；EFA 只為每個既有 event family 建立 deterministic child row，重用 `evaluate_feature_eligibility()` 判斷 role/scope 合法性，並輸出 direct target support、context evidence、child-opened 狀態、family specificity ceiling 與來源 digest。

**Tech Stack:** Python 3.9、stdlib `json`/`hashlib`、existing `EvidenceFeature`/`evaluate_feature_eligibility`、unittest/pytest、deterministic canonical JSON + SHA-256、既有 AI distribution builder。

**Spec:** `docs/superpowers/specs/2026-09-02-v1.6-event-family-hybrid-accuracy-architecture-design.md`

## Global Constraints

- Base lineage：frozen I1 SHA `a6dfe4a5f9b80f0cb4763dad066e7b5873d29d85`；本 architecture branch 目前只含核准 spec/plan 文件。
- `engine/distribution/evidence_ranker.py` 的 Phase 3 eligibility/ranking semantics 為 frozen authority；本計畫只能呼叫，不得修改。
- `engine/distribution/evidence_models.py` 的 `EvidenceFeature` contract 為 read-only。
- Phase 3 domain set、domain order、`event_families` candidate universe、ranking digest 在相同輸入下必須 byte-equivalent 不變。
- EFA v1 不得新增 event family；只處理 Phase 3 已存在的 `(primary_domain, event_family)`。
- 只有 same-target-scope `target_evidence` 且 `qualification_status != "unqualified"` 可令 `child_opened=True`。
- `modifier`、`timing_trigger`、historical personalization、reality context、不同 scope 的 target evidence 均不得自行開 child。
- `needs_verification` 可開 child，但必須輸出 `required_verification_caveat=True`。
- `experimental` 可開 child，但 experimental-only 不得把 specificity 升至 `concrete_event`。
- family specificity 第一階段最高為 `concrete_event`；不得產生 `highly_specific_event` child authority。
- 不使用任何 private outcome、private label、既有 private aggregate 或已曝光 case 作規則/fixture 輸入。
- `promotion_allowed=false`；本計畫不授權 private evaluation、merge、default switch、tag 或 release。
- TDD 必須先觀察合法 RED，再寫 production code。

from engine.distribution.evidence_models import EvidenceFeature
from engine.distribution.evidence_ranker import rank_evidence


def feature(
    feature_id,
    *,
    system,
    scope="yearly",
    domain="career",
    families=(),
    role="target_evidence",
    maturity="stable",
    qualification="qualified",
    dependency="dep:a",

        feature_id=feature_id,
        system=system,
        scope=scope,
        reference_window={"label": scope},
        primary_domain=domain,
        event_family_support=tuple(families),
        strength_class="strong",
        maturity=maturity,

        source_family="synthetic",
        dependency_family=dependency,
        role=role,
        provenance={"fixture": feature_id},
    )

- [ ] **Step 2: 寫「完整 evidence 不可被 Phase 3 representative 去重吃掉」RED**

- [ ] **Step 3: 建立完整 Phase 3 child universe**

對 `base_ranking["domains"]` 依既有 domain order，對每個 `event_families` candidate 建 row。EFA 不以 feature presence 決定 candidate 是否存在；candidate existence 由 Phase 3 frozen output 決定。

Child ID helper：

```python
def _child_claim_id(target_scope: str, primary_domain: str, event_family: str) -> str:
    safe = all(":" not in item and "\n" not in item and "\r" not in item
               for item in (primary_domain, event_family))
    if safe:
        return f"child:{target_scope}:{primary_domain}:{event_family}"
    token = _digest({
        "target_scope": target_scope,
        "primary_domain": primary_domain,
        "event_family": event_family,
    })[:16]
    return f"child:{target_scope}:{token}"
```

Parent ID 必須與現行 C1/Claim Evidence identity 規則一致；不要重新發明另一個 parent namespace。

- [ ] **Step 4: attribution feature selection**

某 feature 只有在以下條件都成立時才可被該 child 使用：

```python
feature.primary_domain == domain
and event_family in feature.event_family_support
and feature.qualification_status != "unqualified"
```

Role/scope 再依 `evaluate_feature_eligibility()` 結果分類：

```text
eligible + can_open_domain + role=target_evidence + scope=target_scope -> direct target
eligible + role=modifier                                         -> modifier context
eligible + role=timing_trigger                                   -> timing context
```

不同 scope target evidence 不能被降格成 modifier 偷偷使用；若 Phase 3 eligibility 判定 invalid，EFA 不把它放入 supporting arrays。

- [ ] **Step 5: child opening + caveat summary**

```python
child_opened = bool(direct_target_features)
required_verification_caveat = any(
    f.qualification_status == "needs_verification"
    for f in direct_target_features
)
```

`maturity_summary`、`qualification_summary` 必須是 closed deterministic summary，而非 free text；例如排序後 unique states：

```python
maturity_summary = sorted({f.maturity for f in direct_target_features})
qualification_summary = sorted({f.qualification_status for f in direct_target_features})
```

- [ ] **Step 6: family specificity ceiling**

```python
if not direct_targets:
    ceiling = None
else:
    direct_deps = {f.dependency_family for f in direct_targets}
    has_stable = any(f.maturity == "stable" for f in direct_targets)
    ceiling = "concrete_event" if has_stable and len(direct_deps) >= 2 else "event_family"
```

不得輸出 `highly_specific_event`。
