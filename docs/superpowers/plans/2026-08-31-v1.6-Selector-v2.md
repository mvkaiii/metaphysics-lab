**Goal:** 在完全保留 `historical-activation-bazi-v1` 舊輸出與 digest 的前提下，新增 `historical-activation-bazi-v2`，讓低排名年份必須通過 absolute control eligibility、月層 local-spike、separation 與 coverage gate 才能成為 `true_control`，否則可正式 `abstain`。

**Tech Stack:** Python 3.9+、stdlib dataclasses/datetime/zoneinfo/hashlib/json、existing `engine.bazi.calendar`、`engine.bazi.structural_relations`、`unittest`/`pytest`。

**Spec:** `docs/superpowers/specs/2026-08-31-v1.6-Selector-v2-Interpretation-vNext-設計.md`

## Global Constraints

- v1 identity remains exactly `historical-activation-bazi-v1` / `1.0-exp`; existing v1 serialized outputs and selection digests must remain unchanged.
- v2 identity is `historical-activation-bazi-v2` / `2.0-exp`; maturity remains `experimental`; routing remains `on_demand`.
- `relative_low != true_control`; low rank never implies a quiet year or absence of major events.
- `high_activation != event_family certainty`; selector never predicts event domain, event family, auspiciousness or probability.
- Historical/outcome hints remain forbidden inputs: `preferred_years`, `known_event_years`, `event_keywords`, `manual_rank_override`.
- v2 annual ordering reuses the existing `ActivationRankVector` lexicographic ordering; no private-case-derived weights.
- v2 control annual ceiling: `tier1_family_count == 0` and `tier2_family_count <= 2` and no decadal boundary in the annual period.
- Historical local-window strength policy is deterministic: `strong` when Tier 1 exists **or** `tier2_family_count >= 3`; `moderate` when no Tier 1 and `tier2_family_count in {1,2}`; `weak` when only Tier 3 exists; `unspecified` when no evidence exists.
- A historical `local_spike` is a `strong` child month over a `weak` or `unspecified` annual parent. This mirrors Phase 3 local-window semantics; it does not modify the parent annual rank.
- Control separation is established only from `(tier1_family_count, tier1_evidence_count, tier2_family_count, tier2_evidence_count)`; Tier 3 counts and label-year tie-breakers may not manufacture a `true_control` margin.
- v2 evaluates all non-Top-4 annual rows for monthly coverage; the lowest-ranked eligible row with complete coverage, no local spike, and structural separation may be selected as the one `true_control`.
- If no row qualifies: `control_year = None`, `control_selection = "abstain"`, `control_quality = "no_clean_control"`.
- If a row qualifies: `control_selection = "selected"`, `control_quality = "true_control"`; wording still means only “structurally lower than comparison years,” never “nothing important happens.”
- Existing Case Schema 1.1 stays unchanged unless implementation proves an unavoidable incompatibility; this plan is designed to avoid a schema bump.
- Every behavior change follows TDD RED → GREEN; no unrelated refactor.
