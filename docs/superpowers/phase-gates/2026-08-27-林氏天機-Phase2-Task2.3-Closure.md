# 林氏天機 Phase 2 Task 2.3 Closure

日期：2026-08-27

## 正式契約

依 `docs/superpowers/plans/2026-08-26-林氏天機-v1.5-Implementation-Plan.md`，Task 2.3 的目的不是新增 evidence 計算能力，而是證明 feature extraction 不會改寫 deterministic calculation truth。

Task 2.3 acceptance 固定為：

1. `resolve_forecast_context()` 產生的 forecast context 在 feature extraction 前後，canonical bytes 與 SHA-256 digest 必須完全一致。
2. 同一 forecast context 重複呼叫 feature builder，輸出 canonical bytes 與 feature order 必須一致。
3. unsupported / missing scope 必須明確 blocked，不得自行推測、補造或產生 invented features。
4. Bazi / Ziwei qualification、focused tests、full regression、distribution parity、compile 與 strict clean-tree gate 必須全部通過。

## 已存在的 Task 2.3 實作證據

核心 Task 2.3 regression 由 commit `efb1633202c67683f814279311c0f558fe99a65f` 引入，且沒有修改 production evidence calculation code。

`tests/test_distribution_forecast.py::test_evidence_extraction_preserves_forecast_truth_and_is_deterministic`：

- 透過正式 `dispatch("resolve_forecast_context", ...)` 取得 runtime forecast context。
- extraction 前後以相同 canonical JSON encoder 產生 bytes 與 SHA-256 digest。
- assert `before_bytes == after_bytes`。
- assert `before_digest == after_digest`。
- assert evidence result 的 `source_context_digest` 等於 extraction 前 digest。
- 對同一 context 重複 extraction，assert canonical output bytes 相同。
- assert feature IDs 順序相同。

`tests/test_distribution_evidence.py::test_builder_is_byte_deterministic_and_preserves_feature_order`：

- 對同一 synthetic deterministic context 重複 extraction。
- assert canonical output bytes 與 feature order 完全一致。

`tests/test_distribution_evidence.py::test_missing_or_unsupported_scope_is_explicitly_blocked`：

- 缺少 requested scope declaration 時，必須回報 `evidence_scope_blocked` / `missing_requested_scopes`。
- unsupported target scope 必須回報 `evidence_scope_blocked`。
- requested scope 未 materialize 時，必須回報 `evidence_scope_blocked`。

## Phase 邊界

Task 2.3 不新增或修改：

- Bazi / Ziwei calculation truth
- evidence domain/event-family mapping
- feature role policy
- maturity / qualification semantics
- weight / score / rank / probability
- eligibility / specificity policy

其中 weight、ranking、eligibility、specificity 仍屬 Phase 3，Task 2.3 不得提前實作。

## Closure 原則

本文件只固定 Task 2.3 的 acceptance 與既有 regression ownership，不為了產生新的 implementation diff 而重寫已存在的 purity tests。

Task 2.3 只有在本 closure commit 所在 exact head 通過完整 Phase Gate，且 strict clean-tree 與 generated distribution artifact gate 維持通過後，才可正式標記完成。
