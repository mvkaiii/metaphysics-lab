## 1. 決策摘要

Phase 4 暫不直接實作。先插入 Phase 3.5，補齊沒有歷史事件資料時的 deterministic base interpretation。

正式採用方案 A：

> **獨立 Structural Interpretation Layer**

資料流固定為：

```text
Deterministic Chart / Forecast Context
        ↓
Cold-start Structural Interpretation
        ↓
EvidenceFeature v1
        ↓
Phase 3 Eligibility / Ranking
        ↓
Unpersonalized Cold-start Baseline
        ↓
Phase 4 Historical Personalization
        ↓
Personalized Ranking
```

Phase 3.5 不取代 Phase 3 ranker，不修改 Historical Calibration，不讓 AI 自由讀 raw chart 後自行發明分數。

Phase 3.5 啟用後，新的正式 semantic mapping identity 固定升版為：

```text
lin_tianji_domain_v2-exp
```

既有 `lin_tianji_domain_v1-exp` 僅代表 Phase 2/3 時期的 legacy coarse mapping，不得在新 formal prospective path 中與 v2 同時具有 ranking authority。

## 2. 問題定義

目前 Phase 2 / Phase 3 的工程邊界是正確的，但 Evidence normalization 的命理語意仍過粗。

### 2.1 八字現況

目前一般 prospective evidence 主要使用：

```text
目標干支
→ 目標天干十神
→ 固定單一 primary_domain
→ 少數 event_family_support
```

例如正官直接映射 career、正財直接映射 finance。

但一般 prospective path 尚未把以下已可 deterministic 重現的結構訊號正式轉成 EvidenceFeature：

- 本命四柱與目標流年／月／日／時的干支互動；
- 當前大運與目標層的干支互動；
- 完整柱伏吟；
- 六沖、六合；
- 三合／三會完整與 partial pattern；
- 刑；
- 害；
- 破；
- 天干五合；
- 歲運並臨；
- 重複訊號 suppression / de-duplication。

上述結構目前有一部分只在 Historical Activation Selector 中作相對活化排序，不代表一般 prospective Evidence Engine 已經具備同等 cold-start 解讀能力。

### 2.2 紫微現況

目前 prospective evidence 主要將 materialized flowing star 所落宮位映射成 domain。

底層其實已經存在：

- flowing star identity / category；
- scope palace / natal palace；
- fine-cycle transformations；
- flying edges；
- transformation target palace；
- geometric relation；
- maturity / qualification / provenance。

但這些訊號尚未形成一個正式、版本化、可測試的 cold-start semantic interpretation policy。

### 2.3 直接進 Phase 4 的風險

如果在上述 baseline 不完整時先加入 Historical Personalization，歷史資料可能實質變成「主要判斷來源」，而不是「個人化排序修正」。

這會破壞 v1.5 原本要求的順序：

```text
Current-period metaphysical evidence
→ base ranking
→ historical personalization
```

因此 Phase 3.5 的存在是 Phase 4 的前置完整性條件。

## 3. 核心 invariant

Phase 3.5 必須滿足以下不可退讓條件。

### 3.1 Cold-start invariant

在完全沒有 historical event material 的情況下，系統仍必須只靠命盤與固定算法，產出 deterministic：

- opened domains；
- event-family candidates；
- target strength class；
- evidence provenance；
- Phase 3 ranking；
- specificity ceiling；
- local spike / active-window input。

### 3.2 No-history dependency invariant

Phase 3.5 的 public API、runtime action、模組 import graph 與 tests 不得讀取：

- `驗證事件紀錄`；
- Historical Calibration finalized records；
- known event year；
- actual event text；
- Kai 2026 outcome；
- subject-specific preference learned from event history。

純 relation table / deterministic calculation helper 若由舊 historical module 抽成中立共用 helper，不算 historical event dependency；但正式 implementation 必須使 shared relation kernel 脫離 historical data path，避免 prospective layer 對 `engine.historical.*` 形成語意依賴。

### 3.3 Phase 3 authority invariant

Phase 3.5 只負責把 deterministic chart facts 解讀成更完整的 `EvidenceFeature`。

它不得：

- 改 Phase 3 ordinal policy；
- 改 domain ownership gate；
- 改 dependency de-duplication 原則；
- 改 specificity ceiling 規則；
- 改 ranking digest 定義；
- 直接產出機率。

### 3.4 Phase 4 separation invariant

Phase 4 只能接收 Phase 3.5 + Phase 3 已完成的 unpersonalized baseline。

Phase 4 不得回頭改寫：

- deterministic chart；
- structural interpretation records；
- EvidenceFeature source truth；
- base ranking digest。

## 4. Scope / Non-goals

### 4.1 Phase 3.5 包含

1. 八字 structural relation interpretation。
2. 紫微 dynamic structural interpretation。
3. Closed semantic mapping policy。
4. Deterministic strength-class assignment。
5. Dependency-family grouping，避免同一底層訊號灌票。
6. EvidenceFeature v1 output。
7. Runtime / generated distribution parity。
8. Synthetic / public qualification style tests。

### 4.2 Phase 3.5 不包含

- Historical Personalization；
- outcome-based re-weighting；
- Kai 2026 tuning；
- 喜用神自動判定；
- 格局主觀評分；
- 神煞大全；
- 新的 probability model；
- AI 自由決定 domain / strength；
- concrete-event classifier；
- highly-specific-event generator；
- 紫微尚未 deterministic materialize 的新細運算法；
- 奇門行動層。

## 5. Architecture

### 5.1 新責任層

Phase 3.5 建立一個獨立的 Structural Interpretation Layer，概念模組責任如下：

```text
engine/distribution/structural_interpretation.py
    ├─ orchestration / canonical output
    ├─ no history input
    └─ returns EvidenceFeature-compatible records

engine/distribution/bazi_structural_interpretation.py
    ├─ target semantic seed
    ├─ natal / decadal / target relations
    ├─ relation suppression
    └─ Bazi strength + event-family semantics

engine/distribution/ziwei_structural_interpretation.py
    ├─ palace domain ownership
    ├─ flowing-star semantic category
    ├─ transformation / flying semantics
    ├─ same-scope aggregation
    └─ Ziwei strength + event-family semantics
```

最終檔名可在 implementation plan 依 repo 命名慣例微調，但責任邊界不得合併回 `forecast.py` 或 `evidence_ranker.py`。

### 5.2 中立 Bazi relation kernel

Historical Activation Selector 已有 deterministic relation tables / suppression concept。

Phase 3.5 implementation 應把「純干支關係判定」整理成中立的 Bazi structural helper，使：

```text
historical selector
prospective structural interpretation
```

可以共用同一 canonical relation truth，而不是複製兩套六合／六沖／刑害破 tables。

此 refactor 必須：

- 不改 Historical Selector v1 的既有 selection result；
- 原 selector tests 全部保持通過；
- shared helper 不接受事件資料；
- relation truth 與 interpretation semantics 分開。

## 6. Input contract

Phase 3.5 不直接重算出生盤，也不接受自由文字命理描述。

輸入只能來自已 materialized deterministic context。

### 6.1 Bazi required context

至少需要：

```text
natal day master
natal four pillars
resolved current decadal period when applicable
target pillar per requested scope
target ten god per requested scope
boundary / qualification status
source provenance
```

`resolve_forecast_context()` 目前已有 target flow-year/month/day/hour 與 ten gods，但 Phase 3.5 需要 forecast context 額外攜帶「只讀的 Bazi natal structural context」與「目標時間對應的 current decadal context」。

新增 context 必須直接來自 `normalized_natal.project.bazi` 已存的 deterministic facts，不得重新猜大運。

Current Bazi decadal selection 固定使用已存 period 的半開區間：

```text
start_datetime <= target_datetime < end_datetime
```

若 target 落在第一個大運開始以前，current decadal context 合法為 `None`；不得自行回推一個不存在的前置大運。若同一 target 同時命中兩個 stored periods，視為資料矛盾並 fail closed。

### 6.2 Ziwei required context

沿用既有 requested scope envelope：

```text
scope
reference
flowing_star_layer
materialized_flowing_stars
resolved_cycle when available
transformation_layer when available
decadal_period when available
maturity
qualification / validation
```

Phase 3.5 不因缺少某個 experimental fine-cycle layer 就自行補造。

## 7. Bazi Structural Interpretation v1-exp

Profile：

```text
lin_tianji_bazi_structural_v1-exp
```

### 7.1 Semantic seed

目標 scope 的天干十神保留為 semantic seed。

沿用現有十神 closed mapping 作 domain ownership 起點，不讓 relation 本身憑空創造完全無關 domain。

例如：

```text
正官 / 七殺 → career
正財 / 偏財 → finance
比肩 / 劫財 → peers
食神 / 傷官 → expression
正印 / 偏印 → learning_support
```

這是 Project interpretation mapping，不是「十神必然等於某現實事件」。

### 7.2 Structural relation strength

八字 relation activation class 採用與既有 Historical Selector 結構層級一致的 conservative mapping：

#### strong

- `decadal_boundary`，僅作 coarser modifier，不可偽裝 target event；
- `sui_yun_bing_lin`；
- `natal_pillar_repeat`；
- `branch_clash_natal`；
- `branch_clash_decadal`；
- `completes_three_harmony`；
- `completes_three_meeting`；
- `completes_three_punishment`。

#### moderate

- `branch_six_harmony`；
- `partial_three_harmony`；
- `partial_three_meeting`；
- `branch_punishment_support`；
- `branch_repeat`；
- `stem_combination`。

#### weak

- `branch_harm`；
- `branch_break`；
- `stem_repeat`。

#### unspecified

- 沒有上述已版本化 structural relation；
- 或只能取得 semantic seed，沒有足夠 relation context。

Phase 3.5 不把「沒有 strong relation」翻譯成「事件不會發生」。strength 只代表結構活化程度，不代表吉凶。

### 7.3 Suppression

沿用 canonical structural suppression 原則：

- 歲運並臨吸收同一 target 的 lower-tier stem/branch repeat；
- 完整柱伏吟吸收同一 natal component 的 lower-tier repeat；
- 完整三合／三會／三刑成立時，對應 partial pattern 不重複計數；
- 同一 canonical pattern 即使命盤有重複支，也只能形成一個 canonical relation record。

### 7.4 Bazi event-family overlay

十神原有 event-family candidates 保留。

Structural relation 只可從 closed generic overlay 增加「落地型態」，不得直接生成 concrete event：

```text
repeat/reactivation family
    → recurrence_or_reactivation

clash / punishment / harm / break family
    → friction_or_change

harmony / stem combination family
    → alignment_or_binding

three-harmony / three-meeting completion family
    → structure_formation

sui_yun_bing_lin / major repetition family
    → amplified_repetition
```

這些 generic families 必須與 semantic seed 所擁有的 domain 綁定；例如 career domain + `friction_or_change` 仍只是「工作／職責領域的摩擦或變化」，不能直接翻成「離職」。

### 7.5 Bazi aggregation / dependency family

每個 scope + semantic domain 最多產生一個 canonical Bazi interpreted feature。

同一 target pillar 下的多個 natal relation 不可各自變成獨立 ranking vote。

概念 dependency family：

```text
bazi.structural:<scope>:<target-pillar>:<primary-domain>
```

feature provenance 可保留完整 canonical relation list，但 ranker 只能看到一個同源 aggregate feature。

這可避免：

```text
同一流年同時沖兩個本命支
→ 被錯算成兩個獨立系統證據
```

## 8. Ziwei Structural Interpretation v1-exp

Profile：

```text
lin_tianji_ziwei_structural_v1-exp
```

### 8.1 Domain ownership

宮位仍是 Ziwei domain ownership 的 deterministic structural anchor。

現有 12 宮 mapping 保留，例如：

```text
官祿宮 → career
財帛宮 → finance
夫妻宮 → partnership
疾厄宮 → health
遷移宮 → mobility_external
田宅宮 → home_property
```

星曜／四化／飛化只能修飾該 structural target 的語意與 strength，不得讓一顆星自由創造與落宮無關的 domain。

### 8.2 Flowing-star semantic categories

第一版只使用 engine 已正式保存的 category，不使用 AI 自己認星性。

Closed mapping：

```text
soft    → support_or_coordination
lucun   → resource_accumulation
tough   → pressure_or_friction
tianma  → movement_or_change
flower  → relationship_visibility
helper  → support_or_resolution
```

這些都是 event-family candidates，不是吉凶判決。

### 8.3 Transformation semantic families

Fine-cycle layer 若已 materialize transformation / flying edge，允許使用：

```text
祿 → resource_or_attraction
權 → responsibility_or_control
科 → recognition_or_mediation
忌 → constraint_or_friction
```

Transformation target palace 決定 domain；不得只因「化忌」三字就跨 domain 產生健康、離職、分手等 concrete event。

### 8.4 Geometric relation

已有 deterministic geometric relation 時，可記錄：

```text
same_palace
opposite_palace_incoming
normal
```

v1-exp 中 geometric relation 只用於 same-scope signal aggregation 與 provenance，不單獨升格 specificity。

### 8.5 Ziwei strength policy

因目前 flowing-stars / fine-cycle 多數仍為 experimental，v1-exp 採 conservative strength：

```text
strong:
    同一 scope、同一 domain 至少有兩種不同 structural families 共同活化，
    且其中至少一種來自 transformation/flying，另一種來自 flowing-star placement。

moderate:
    同一 scope、同一 domain 有一個 qualified transformation/flying family；
    或至少兩個不同 flowing-star semantic categories 共同落在同一 domain。

weak:
    同一 scope、同一 domain 只有一個 qualified flowing-star semantic category。

unspecified:
    只能確認 palace/domain，但 semantic source 不完整。
```

這裡的 strength 是 activation strength，不是正負方向。`support_or_coordination` 與 `pressure_or_friction` 可以同時存在於同一 domain；系統必須保留混合語意，不得為了製造單一方向而刪除其中一側。

`needs_verification` source 可保留 feature，但 qualification status 必須傳遞；`unqualified` 不得被 Phase 3 ranking 採用。

### 8.6 Ziwei aggregation / dependency family

同一 scope 的 flowing-star placements 本質上共用同一 source resolution，不可每顆星算獨立票。

每個 scope + source reference + domain 最多形成一個 canonical Ziwei interpreted feature。

概念 dependency family：

```text
ziwei.structural:<scope>:<source-reference>:<primary-domain>
```

同一 source layer 內多星只提升該 aggregate feature 的 semantic richness / strength，不提升 independent system count。

## 9. EvidenceFeature contract

Phase 3.5 維持既有 `EvidenceFeature` schema，不新增必填欄位。

輸出仍使用：

```text
feature_id
system
scope
reference_window
primary_domain
event_family_support
strength_class
maturity
qualification_status
source_family
dependency_family
role
provenance
```

### 9.1 Mapping identity

新的 formal mapping profile 固定為：

```text
lin_tianji_domain_v2-exp
```

v2 的差異是：EvidenceFeature 不再只是十神／宮位粗 mapping，而是由 structural interpretation aggregate 後產生。

舊 `lin_tianji_domain_v1-exp` 可保留供 regression / legacy fixture 使用，但不得被 runtime formal prospective path 默默繼續使用。

### 9.2 Provenance 新增內容

可在 provenance 內 versioned 保存：

```text
structural_profile
semantic_profile
canonical_relations
semantic_families
aggregation_basis
source_context_digest
```

不得把 raw actual events 放入 provenance。

### 9.3 Byte determinism

相同：

```text
normalized natal
+ target datetime
+ requested scopes
+ rule/profile versions
```

必須得到完全相同 canonical JSON bytes、feature order 與 digest。

輸入 sequence 的非語意順序若可 canonicalize，輸出不得因此漂移。

## 10. Phase 3 compatibility

Phase 3.5 不是新的 ranker。

現有 Phase 3 policy 保持：

- target_evidence 才能 open domain；
- modifier / timing_trigger 不得自己創建 domain；
- dependency de-duplication；
- cross-system convergence；
- maturity factor；
- event-family / concrete-event specificity ceiling；
- local spike non-mutating comparison；
- ranking digest。

### 10.1 不修改 Phase 3 score authority

Phase 3.5 透過更好的 features 改善 Phase 3 input；不得直接改：

```text
ordinal_score_scaled
ordinal_scale
rank
allowed_specificity
ranking_digest
```

新的 features 合法地造成新的 ranking result / digest 不算「改寫 Phase 3 digest governance」；禁止的是偷改 digest algorithm 或在 rank 後回寫 score。

任何 Phase 3 policy 變更都必須另開 policy version，不能藏在 3.5 裡。

## 11. Runtime contract

正式新增 runtime action：

```text
interpret_structural_evidence
```

Input：

```text
forecast_context
target_scope
```

Input schema 不包含 history 欄位；unknown top-level history/event/calibration 欄位必須 fail closed，而不是靜默忽略。

Output：

```text
structural_profile_version
mapping_profile = lin_tianji_domain_v2-exp
source_context_digest
features
interpretation_digest
```

`rank_evidence` 繼續只吃 features，不直接讀 raw chart。

### 11.1 Compatibility authority

既有 `build_evidence_features()` 在 Phase 3.5 完成後固定改為 **compatibility wrapper**：

```text
build_evidence_features(...)
    → Structural Interpretation Layer
    → project to existing evidence envelope
```

它不得保留一套平行的 legacy coarse ranking path。

若需要測 legacy `lin_tianji_domain_v1-exp`，必須透過明確 legacy/private test helper 或 frozen fixture 驗證，不得由正式 runtime action 自動 fallback。

因此 Phase 3.5 完成後只有一條 formal prospective evidence authority：

```text
interpret_structural_evidence / compatibility wrapper
→ lin_tianji_domain_v2-exp
```

## 12. Error handling

### 12.1 Fail closed

以下情況直接 fail closed：

- natal four pillars shape 不合法；
- target pillar 非合法干支；
- current decadal context 來源矛盾；
- duplicated canonical relation identity；
- Ziwei source reference 不一致；
- transformation target 無法映射到合法 palace；
- unknown semantic profile；
- unknown relation class；
- unknown history/event/calibration input field；
- non-canonical / non-JSON-safe provenance；
- tampered source digest。

### 12.2 Graceful degradation

以下情況可降級而不是整體失敗：

- 某 experimental Ziwei fine-cycle layer unavailable；
- boundary caution；
- 只有 Bazi 或只有 Ziwei 某一 system 可提供合格 target evidence。

降級時必須：

- 保留 qualification / maturity；
- 不補造缺失 layer；
- 不把缺失當 negative evidence；
- 不提升 specificity。

- threshold tuning；
- strength class boundary tuning；
- event-family ontology tuning。

Kai 2026 若未來用於 Phase 3.5，只能作：

- regression reproduction；
- no-history isolation verification；
- anti-leak test；
- baseline preservation。

## 14. Test strategy

Phase 3.5 必須使用 TDD，先 RED 再 GREEN。

### 14.1 Bazi tests

至少鎖定：

1. 十神 semantic seed 不因 history 改變。
2. strong / moderate / weak relation class 正確。
3. 完整 pattern suppression lower-tier duplicate。
4. 同一 target 對多 natal components 不灌成多個 independent votes。
5. current decadal relation 可作 modifier，但不越權 open target domain。
6. target scope relation 決定 target feature strength。
7. generic relation family 不得生成 concrete event。
8. input order 不影響 canonical result。
9. stored decadal period 採半開區間 selection；childhood pre-decadal 合法為 None。
10. neutral relation refactor 不改 Historical Selector v1 selection / digest。

### 14.2 Ziwei tests

至少鎖定：

1. palace owns domain。
2. star category 只能修飾落宮 domain。
3. transformation target palace owns transformation domain。
4. 祿／權／科／忌只產生 closed generic semantic family。
5. 同一 source layer 多星不變成獨立票。
6. flowing-star + transformation same-domain activation 可提升 strength。
7. mixed semantic families 必須同時保留，不強行變成單一吉凶方向。
8. experimental maturity 不因 signal count 變 stable。
9. missing experimental layer 只降級，不自由補造。

### 14.3 Cross-system tests

至少鎖定：

1. Bazi + Ziwei 同 domain 可由 Phase 3 視為 cross-system convergence。
2. Bazi 與 Ziwei 不同 domain 時各自保留，不強行統一。
3. Phase 3.5 不改 Phase 3 ranking policy constant。
4. 完全沒有 history material 時可產生完整 baseline。
5. 任意 history/event/calibration payload 塞入 Phase 3.5 API 必須 fail closed。
6. `lin_tianji_domain_v1-exp` 不得成為 formal runtime fallback。

### 14.4 Baseline acceptance test

建立 synthetic cold-start case，完全不建立任何 historical event material。

完整執行：

```text
resolve_forecast_context
→ interpret_structural_evidence
→ rank_evidence
```

必須得到非空、deterministic、可追溯 baseline。

任何外部 historical event 檔案內容增加、移除或改寫時，只要 deterministic natal / target context 不變，Phase 3.5 output 必須 byte-identical。

### 14.5 Regression / portability

必須維持：

- modular runtime tests；
- generated `dist/ai/metaphysics_lab.py` parity；
- build reproducibility；
- strict clean-tree gate；
- existing Historical Selector selection invariance；
- Phase 2 EvidenceFeature schema tests；
- Phase 3 ranking tests。

## 15. Phase 3.5 task decomposition

### Task 3.5.1｜Structural Context Foundation

- forecast context 補 Bazi natal structural facts；
- deterministic current Bazi decadal resolution；
- neutral Bazi relation kernel；
- historical selector regression invariance。

Gate：沒有 interpretation semantics 前，先證明 structural truth 可重現且無 history dependency。

### Task 3.5.2｜Bazi Structural Interpretation

- semantic seed；
- canonical relations；
- suppression；
- strength classes；
- generic event-family overlay；

## 17. Acceptance definition

Phase 3.5 完成的最低標準不是「測試有過」，而是以下命題都成立：

1. **零歷史資料也能產生可用 baseline。**
2. **八字不再只靠目標天干十神做粗 mapping，而會納入已版本化 structural relations。**
3. **紫微不再只靠落宮 mapping，而會納入 engine 已 materialize 的 star category / transformation / flying semantics。**
4. **semantic mapping 明確升版為 `lin_tianji_domain_v2-exp`，不靜默改寫 v1。**
5. **同源訊號不灌票。**
6. **不同體系可以收斂，也可以保留衝突。**
7. **activation strength 與吉凶方向分離。**
8. **Experimental 永遠仍是 Experimental。**
9. **沒有 history input path。**
10. **Phase 3 ranker authority 與 digest governance 不被弱化。**
11. **正式 runtime 只有一條 evidence authority，不保留 legacy fallback。**
12. **Phase 4 必須建立在這個 unpersonalized baseline 之後。**
13. **完整 CI 與 strict clean-tree gate 全綠。**

只有這些條件全部成立，才可將 Phase 3.5 視為完成並開始 Phase 4。
