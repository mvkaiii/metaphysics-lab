# v1.6 Prospective Claim-Authority Set Governance Design

Status: DESIGN_ONLY / NOT_IMPLEMENTED / NOT_PROMOTION_AUTHORITY  
Profile: `lin_tianji_prospective_claim_authority_set_v1`  
Base authority: `c2d111b3e1b410a7208b8d4ba0585e8000d30a87`  
Frozen v1.6 ancestor: `eaf03116bf5e02b08b4b51caed2cb2c31f796686`  
Promotion allowed: false

## 1. Purpose

The first real private Complete-Census S1 cycle contains more than one prospective case. Each case has its own resolved prospective-window policy and therefore its own valid `claim_authority_manifest` digest. The frozen S1 claim-universe lock, however, carries one `claim_authority_profile` and one `claim_authority_digest` for the entire source-manifest census.

This design adds one outcome-blind governance layer that binds the exact set of per-case claim-authority manifests into one deterministic composite authority. The composite authority is used only as provenance for the S1 batch lock. It does not change any prediction, structural mapping, EFA child, render decision, scoring rule, or promotion rule.

## 2. Problem statement

For a single INCLUDE case, the existing authority chain is valid:

`window-scope policy -> per-case claim-authority manifest -> yearly structural/ranking/EFA child universe -> S1 claim-universe lock`

For multiple INCLUDE cases, the per-case manifest digest cannot be reused as the one S1 batch digest because the manifest contains the case-specific scope-policy digest. Different registered windows therefore correctly produce different per-case claim-authority digests.

The missing authority is a deterministic set-level binding:

`{case_id -> validated per-case claim-authority manifest} -> composite claim-authority set digest`

Without this layer, choosing one case's digest, dropping the other case, or inventing a manually shared digest would destroy provenance or violate Complete-Census semantics.

## 3. Non-goals

This change does not:

- modify frozen v1.6 structural mappings, Phase 3 ranking, EFA, C2, HCC, HOC, Legacy Adapter, Q1, T1, paired evaluation, or oracle semantics;
- alter how a prospective window resolves to `target_scope=yearly`;
- create, remove, rename, filter, rank, or render child claims;
- make `work` / `finance` intake labels a post-hoc child filter;
- merge or promote the separate Y1 yearly-Ziwei research authority;
- read verified events, outcomes, oracle answers, Legacy output, Candidate/HOC output, Q1/T1 results, or post-lock adjudication;
- authorize merge, release, tag, default-branch switch, or model promotion.

## 4. Decision

Add an immutable **Prospective Claim-Authority Set** authority.

The authority consumes exactly:

1. the S1 source-manifest case census needed to derive the INCLUDE case set; and
2. one already validated per-case `claim_authority_manifest` for every INCLUDE case.

It produces exactly one set-level authority manifest whose canonical digest is the `claim_authority_digest` stored in the S1 claim-universe lock.

The set authority profile is:

`lin_tianji_prospective_claim_authority_set_v1`

The set must exact-match the S1 INCLUDE case identity set. No INCLUDE case may be omitted and no excluded or foreign case may be added.

## 5. Data model

### 5.1 Input

Recommended input schema:

`v1.6-prospective-claim-authority-set-input.v1`

```json
{
  "source_manifest": { "...": "validated S1 source manifest" },
  "case_authorities": [
    {
      "case_id": "opaque-case-id",
      "claim_authority_manifest": { "...": "validated per-case manifest" }
    }
  ],
  "promotion_allowed": false
}
```

`case_id` is opaque. The authority must not infer identity, dates, domains, or outcomes from the text of the ID.

### 5.2 Output

Output schema:

`v1.6-prospective-claim-authority-set.v1`

```json
{
  "schema_version": "v1.6-prospective-claim-authority-set.v1",
  "claim_authority_profile": "lin_tianji_prospective_claim_authority_set_v1",
  "source_manifest_digest": "<validated S1 source-manifest digest>",
  "case_authorities": [
    {
      "case_id": "opaque-case-id",
      "claim_authority_profile": "lin_tianji_prospective_claim_authority_manifest_v1",
      "claim_authority_digest": "<validated per-case digest>"
    }
  ],
  "promotion_allowed": false,
  "claim_authority_digest": "<sha256 canonical output body without claim_authority_digest>"
}
```

The output intentionally stores only per-case identity and validated authority identity, not the full per-case scope or structural payload.

## 6. Canonicalization and digest rules

All digests use canonical JSON:

- UTF-8;
- sorted object keys;
- separators `(',', ':')`;
- `allow_nan=false`;
- lowercase SHA-256 hex.

Before digesting:

- `case_authorities` is sorted lexicographically by `case_id`;
- duplicate `case_id` values fail closed;
- every per-case manifest is validated by the existing `validate_claim_authority_manifest` authority;
- the output records the validated manifest's own `claim_authority_profile` and `claim_authority_digest`;
- caller-supplied digest summaries are not trusted as substitutes for validating the actual per-case manifest.

Input ordering therefore cannot change the resulting set digest.

## 7. Complete-Census binding

The set builder must derive the expected INCLUDE set from the validated S1 source manifest using frozen S1 eligibility semantics.

Required equality:

`set(case_authorities.case_id) == set(S1 INCLUDE case_id)`

Failure modes:

- missing INCLUDE case -> fail closed;
- extra excluded case -> fail closed;
- extra unknown/foreign case -> fail closed;
- duplicate case -> fail closed;
- zero cases while S1 has eligible INCLUDE cases -> fail closed.

If S1 legitimately has zero INCLUDE cases, no real claim-universe lock is eligible; the composite authority must not be used to manufacture an eligible S1 receipt.

## 8. Per-case authority integrity

Each case authority must remain case-specific.

A per-case authority digest changes when any bound semantic authority changes, including:

- its prospective-window policy digest;
- structural candidate authority identifier/digest;
- mapping profile;
- Phase 3 authority;
- EFA authority;
- resolved target scope.

The composite set digest therefore also changes when any member authority changes.

This preserves the distinction between, for example, a Q4 window and an H2 window while still allowing both cases to participate in one Complete-Census S1 batch.

## 9. S1 handoff

The S1 sequence becomes:

`case intake -> private registry snapshot -> S1 source manifest -> per-case window-scope lock -> per-case claim-authority manifest -> composite claim-authority set -> per-case outcome-free yearly structural/ranking/EFA child universe -> S1 claim-universe lock -> S1 frame -> S1 receipt`

For the S1 claim-universe lock:

- `claim_authority_profile` = `lin_tianji_prospective_claim_authority_set_v1`
- `claim_authority_digest` = composite set `claim_authority_digest`

The S1 locked claim IDs remain the exact per-case EFA child inventories. The composite authority does not touch claim IDs.

## 10. Private/public boundary

Public repository may contain:

- implementation;
- schema/profile constants;
- synthetic fixtures;
- general tests;
- governance docs;
- aggregate/digest-only receipts where already permitted.

Public repository must not contain:

- real private source manifest;
- real opaque case IDs;
- real per-case authority manifests;
- real composite set manifest;
- real EFA child IDs;
- real S1 claim-universe lock/frame;
- outcome or oracle material.

Real artifacts remain outside git.

## 11. API surface

Recommended isolated module:

`engine/distribution/prospective_claim_authority_set.py`

Minimal public functions:

```python
build_claim_authority_set(
    source_manifest,
    case_authorities,
    promotion_allowed=False,
) -> dict

validate_claim_authority_set(
    payload,
    source_manifest,
) -> dict
```

The module may reuse frozen validators from:

- `claim_consumption_sampling_eligibility` for source-manifest validation / INCLUDE derivation;
- `claim_authority_manifest` for per-case manifest validation.

It must not import or invoke prediction output generation, EFA construction, HOC, Legacy, oracle, Q1, or T1 scoring.

## 12. Fail-closed behavior

Reject:

- unknown or missing fields at every contract level;
- malformed/invalid source manifest;
- malformed per-case authority manifest;
- duplicate case IDs;
- missing INCLUDE cases;
- added excluded/foreign cases;
- caller-supplied set digest mismatch;
- per-case manifest digest mismatch;
- unsupported per-case authority profile;
- `promotion_allowed != false`;
- non-canonical digest text.

No manual override may substitute a shared digest for multiple distinct per-case manifests.

## 13. Testing requirements

Implementation follows RED -> GREEN TDD.

Required tests:

1. Two INCLUDE cases with different valid per-case authority digests build one valid composite authority.
2. Reversing input case order produces byte-identical canonical output and the same composite digest.
3. Duplicate case ID fails closed.
4. Omitting one INCLUDE case fails closed.
5. Adding an excluded case fails closed.
6. Adding an unknown case fails closed.
7. Tampering one per-case manifest digest fails closed.
8. Changing one per-case window-policy digest changes that per-case manifest digest and therefore the composite digest.
9. Changing one structural candidate / Phase 3 / EFA authority changes the composite digest.
10. Unknown fields fail closed at set input, member, and serialized-output levels.
11. `promotion_allowed=true` fails closed.
12. Serialized set digest tamper fails closed.
13. The set's case identity set exact-matches the S1 INCLUDE set.
14. The S1 claim-universe lock accepts the composite profile/digest as provenance without changing frozen claim-ID completeness validation.
15. No change is made to existing structural mapping, EFA, C2, HCC, HOC, Legacy, Q1, T1, or paired evaluator files.
16. General regression suite remains green.

Synthetic fixtures must use only synthetic opaque IDs.

## 14. Integration boundary

The implementation should be additive and isolated.

Expected new/changed surface:

- new `engine/distribution/prospective_claim_authority_set.py`;
- new focused tests and synthetic fixtures;
- optional thin CLI only if needed for real private artifact generation;
- S1 integration test proving the composite profile/digest can be carried as provenance.

Do not change frozen S1 eligibility rules or claim-universe case/claim completeness semantics unless a test proves the existing validator rejects the new provenance profile for purely schema-level reasons. If such a schema compatibility issue is found, stop and design that compatibility change separately rather than silently broadening S1.

## 15. Why not split the S1 census

Splitting Q4 and H2 into separate S1 batches would make the sampling frame depend on an operator choice rather than the locked source-manifest census. That creates unnecessary selection discretion and weakens the Complete-Census guarantee.

The composite authority keeps one census while preserving case-specific semantic provenance.

## 16. Why not force one per-case digest

Forcing different windows to share one per-case claim-authority digest would erase the case-specific scope-policy binding. It would make the digest less informative and would permit a semantic authority change to be hidden behind a manually reused identifier.

The composite set is therefore the minimal authority that preserves both provenance and Complete-Census semantics.

## 17. Governance and promotion

This is research infrastructure only.

- Base/frozen authorities remain immutable.
- `promotion_allowed=false` at every layer.
- Real private artifacts stay outside git.
- No outcome/oracle/scoring data is used during composite authority creation.
- This design does not authorize private scoring.
- This design does not authorize merge/tag/release/default switch/model promotion.
- After implementation is verified green, the private S1 cycle may resume from source-manifest lock through composite authority, child-universe lock, frame, and receipt only.
