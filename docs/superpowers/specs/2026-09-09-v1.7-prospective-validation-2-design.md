# Metaphysics Lab v1.7｜Prospective Validation 2.0 設計

## 1. 目的

Prospective Validation 2.0 的目的不是提高命理預測的表面命中率，而是把「這筆結果到底屬於哪一種驗證情境」固定成 deterministic、可重現、可稽核的分類，避免把已知安排、既存但尚未揭露的現實、或歷史回顧混入 clean prospective denominator。

本設計只處理驗證治理，不改寫八字／紫微算法，不改 Phase 3 ranking，不提升 Selector v2／Interpretation v2 maturity，也不修改已鎖定的 v1.5 forecast lock。

## 2. 相容性底線

- Project Contract 維持 `1.1`。
- Runtime Schema 維持 `1.1`。
- Case Schema 維持 `1.1`。
- `engine.distribution.prospective.lock_prospective_forecast()` 的既有輸入、輸出、canonical bytes 與 digest 必須保持相容。
- 舊 Phase 1 / v1.5 lock 不要求 migration，也不得為了 v2 分類重寫既有 lock。
- 新分類資料以 sidecar validation context 保存；Case 06／07／08 可把它與原 lock 一起 append，無需新增 canonical slot。
- 新能力先維持 `experimental` + `on_demand`。

## 3. 四種 context class

固定只有四種：

1. `clean_prospective`
   - 問題與整個 prediction window 都在 knowledge cutoff 之後。
   - lock 時對目標事件沒有已知現實資訊。
   - 唯一可以進 clean prospective denominator 的類別。

2. `conditional_prospective`
   - 問題與 prediction window 在 cutoff 之後，但 lock 時已有部分或完整前置安排／現實條件。
   - 可以做策略與結果追蹤，但不得算 clean prospective hit。

3. `hidden_existing_reality`
   - 被測現實在 knowledge cutoff 以前已存在，但 lock 時對模型／分析流程保持未知，之後才揭露。
   - 可用來測盲讀能力，但絕對不得混入 clean prospective denominator。

4. `retrospective_calibration`
   - 目標窗口在 knowledge cutoff 以前已結束，屬歷史回顧／校準。
   - 可作 calibration evidence，但不得混入 clean prospective denominator。

不得新增「probably clean」「mostly prospective」等模糊類別來救分母。

## 4. Deterministic classifier contract

新增：

```python
classify_validation_context(payload: Mapping[str, object]) -> dict
```

輸入必須**剛好**包含：

```text
forecast_id
locked_at
knowledge_cutoff_at
question_mode
knowledge_state_at_lock
prediction_window
```

固定 enum：

```text
question_mode = future_forecast | hidden_existing_reality | retrospective_calibration
knowledge_state_at_lock = unknown | partial | known
```

`prediction_window` 必須剛好包含 timezone-aware ISO-8601 `start` / `end`。

固定時間規則：

- `locked_at >= knowledge_cutoff_at`。
- `prediction_window.start < prediction_window.end`。
- `future_forecast`：`knowledge_cutoff_at < prediction_window.start` 且 `locked_at < prediction_window.start`。
- `hidden_existing_reality`：`prediction_window.end <= knowledge_cutoff_at`，且 `knowledge_state_at_lock` 必須是 `unknown`。
- `retrospective_calibration`：`prediction_window.end <= knowledge_cutoff_at`。
- 任何 prediction window 跨越 cutoff 的情況一律 fail closed，要求拆成兩筆，不得由 classifier 猜哪一段算 prospective。

固定分類規則：

```text
future_forecast + unknown       -> clean_prospective
future_forecast + partial/known -> conditional_prospective
hidden_existing_reality         -> hidden_existing_reality
retrospective_calibration       -> retrospective_calibration
```

若 mode、knowledge state 與時間關係互相矛盾，回傳 structured error；不得自動改類別。

## 5. Classifier output

成功時固定輸出：

```text
status = classified
classifier_version = prospective-validation-v2-exp
forecast_id
locked_at
knowledge_cutoff_at
question_mode
knowledge_state_at_lock
prediction_window
context_class
clean_denominator_eligible
adjudication_earliest_at
outcome_status_at_lock = pending
reason_code
canonical_digest
```

`clean_denominator_eligible` 只有 `clean_prospective` 為 `true`。

`adjudication_earliest_at`：

- `clean_prospective` / `conditional_prospective` = `prediction_window.end`
- `hidden_existing_reality` / `retrospective_calibration` = `locked_at`

`canonical_digest` 使用 canonical UTF-8 JSON（sorted keys、compact separators、禁止 NaN）對**不含 digest 自身**的完整 normalized body 做 SHA-256。

## 6. Validation summary

新增：

```python
build_validation_summary(payload: Mapping[str, object]) -> dict
```

輸入：

```text
{
  "records": [
    {
      "validation_context": <classify_validation_context output>,
      "verification_state": "pending | matched | partial | not_matched | cannot_recall"
    }
  ]
}
```

規則：

- 每筆 `validation_context` 必須重驗 canonical digest；篡改 `context_class`、eligibility、時間或 knowledge state 都要 fail closed。
- `pending` 不進任何已裁決 denominator。
- `cannot_recall` 不可 scorable。
- clean denominator 只接受 `context_class=clean_prospective`、`clean_denominator_eligible=true` 且 verification state 為 `matched|partial|not_matched`。
- `conditional_prospective`、`hidden_existing_reality`、`retrospective_calibration` 即使結果是 matched，也只能列入 excluded context counts，不能增加 clean matched count 或 clean denominator。
- 不計算 accuracy rate、不宣稱方法優劣；只輸出可稽核的 count metadata。
- verification state 由既有 outcome authority／人工 adjudication 提供；summary 不解析自然語言 outcome，也不重新判定 matched / partial / not_matched。

## 7. Runtime 與 capability

新增 runtime actions：


新增 capability：

```text

```

初始 metadata：

```text

```

依賴既有 `distribution.prospective_forecast_governance`，但不得修改它的 v1.5 rule version 或既有 lock contract。

## 8. Case 與 distribution

- Case Schema 1.1 繼續以 append-first tracking record 保存 JSON-safe payload。
- 新 `validation_context` 可以與 `prospective_forecast_lock` 同存於 06／07；重大決策需要追蹤時可同存於 08。
- 不新增 09 slot，不做 Case migration。
- `dist/ai` 只能透過 `tools/build_ai_distribution.py` 官方 generator 重建，不得手改 generated artifacts。
- modular runtime 與 bundled `metaphysics_lab.py` 的兩個新 action 必須 parity。

## 9. Anti-leak / anti-gaming

- classifier 不讀驗證事件內容，不讀 outcome text，不讀 05 的事件內容來決定 context class。
- `knowledge_state_at_lock` 必須在 outcome reveal 前固定；事後不能因結果好壞改成 clean。
- hidden existing reality 永遠不能因「模型當時不知道」而升成 clean prospective；事件在 cutoff 前已存在就是不同驗證類型。
- retrospective calibration 永遠獨立於 prospective denominator。
- 不因任何分類提高命理 confidence、specificity 或 ranking。

## 10. Acceptance criteria

1. 四類 deterministic classification 在固定輸入下可重現。
2. 矛盾 mode/time/knowledge 組合 fail closed。
3. hidden existing reality matched case 對 clean denominator 的貢獻永遠是 0。
4. conditional prospective matched case 對 clean denominator 的貢獻永遠是 0。
5. retrospective matched case 對 clean denominator 的貢獻永遠是 0。
6. clean prospective 的 matched/partial/not_matched 才能形成 clean scorable count。
7. `cannot_recall`、`pending` 不進 clean scorable count。
8. 舊 v1.5 forecast lock fixture 的 canonical digest 維持 `b9b465c43fe1e903601cb9b726ef0c691810a674b2c074146a1b30c7ee9d1524`。
9. Case Schema 仍為 1.1，舊 lock 無 migration。
10. modular/bundled runtime parity，official generator check PASS。
