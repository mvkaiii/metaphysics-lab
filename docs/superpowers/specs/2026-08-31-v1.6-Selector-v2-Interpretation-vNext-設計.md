## 一、問題定義

v1.5 已具備兩套彼此分離、可稽核的能力：

1. `historical.activation_selector`：以 deterministic Bazi structural relations 對最近 10 個已完成流年排序，固定選 Top 4 high + Bottom 1 control。
2. 林氏天機 Interpretation Contract：限制 AI 不得重排 deterministic truth、不提高 specificity、不把歷史個人化或現實背景冒充盤面訊號。

近期 Historical Blind Calibration 暴露兩種不同 failure mode：

### A. Control semantics failure

v1 selector 的 `control_year` 是「排序最後一名」，不是通過絕對低活化資格的 `true_control`。

目前程式：

```text
ranked[-1] -> control
```

`control_quality` 只標示：

```text
Tier 1 > 0        -> relative_low
Tier 1 = 0, T2>0 -> acceptable_control
T1=0, T2=0       -> strong_control
```

但 `acceptable_control` 仍會被強制選為 control。

### B. Interpretation overreach

Historical blind wording 曾把：

```text
relative / acceptable low activation
```

擴張成：

```text
沒有結構性大轉折 / 主要沿既有軌道延續
```

這個推論超過 selector 本身的 authority。

反向案例也存在：年度 activation 很強，但實際未形成可確認重大事件；若 AI 將「強 activation」直接翻譯為指定事件家族，會產生 false positive。

因此 v1.6 的核心不是讓 AI「講更多」，而是：

> **把 activation strength、local spike、domain localization、event-family inference、specificity、abstention、historical calibration 分成不同 authority。**

---

## 二、版本治理

本設計定位為 `v1.6.0`，不是 `v1.5.1`。

理由：

- Selector profile / control semantics 會改變。
- 新增 absolute control eligibility 與 abstention。
- Interpretation vNext 會新增正式 evidence-chain / cross-system disclosure 行為。
- 若進入 runtime，屬新的可執行規則層或 capability behavior，不符合 `VERSION.md` 對 patch「不改演算法語意」的定義。

### 不改變的 release identity

v1.5.0 tag / GitHub Release / release-time evidence 永遠保持 immutable；v1.6 不回寫 v1.5 release snapshot。

---

## 三、設計原則

### 3.1 Authority separation

固定資料流：

```text
Raw / External / Project chart facts
    -> deterministic structural relations
    -> activation selection / ranking
    -> domain + event-family structural interpretation
    -> cross-system evidence packet
    -> specificity + abstention contract
    -> AI natural-language rendering
    -> blind lock
    -> later outcome evaluation
```

每層只能收窄或解釋上游，不得偷偷建立第二套盤面 truth。

### 3.2 Relative low 不等於 quiet year

硬性 invariant：

```text
relative_low != true_control
```

任何對外 wording 不得因「十年排名最低」自動推出「沒有重大事件」。

### 3.3 High activation 不等於 concrete event

硬性 invariant：

```text
high_activation != event_family certainty
high_activation != good_or_bad
```

Activation 只表示結構互動密度／強度。

### 3.4 Local spike 不改寫 parent truth

月／日／時的局部高峰只能：

- 宣告 `local_spike` 或 `active_window`
- 影響 control eligibility
- 收窄觀察時間窗

不得把年度 rank retroactively 改成另一個 rank。

### 3.5 Private calibration 不進共用 repo

真實命主事件只保存在 private Case / qualification environment。

共用 repo 只保存：

- synthetic fixture
- anonymized acceptance pattern
- aggregate hit / partial / miss counts
- digests / rule versions / test status

不得把私人事件全文寫入共用測試或 docs。

# Part A｜Historical Activation Selector v2

## 四、Capability identity

v1 必須保留：

```text
historical-activation-bazi-v1
rule_version = 1.0-exp
```

v2 候選：

```text
historical-activation-bazi-v2
rule_version = 2.0-exp
implementation = experimental until qualification passes
routing = on_demand
```

v2 不得修改、重寫或重新 digest 舊 v1 historical lock。

---

## 五、v2 年度分類

v2 不只輸出 high / control。

固定 role vocabulary：

```text
sustained_high
localized_spike
relative_low
true_control
uncertain
```

### `sustained_high`

年度 rank 本身達 high eligibility；child scopes 可有或沒有局部峰值。

### `localized_spike`

年度不是 high，但至少一個正式 eligible child scope 出現可驗證 local spike，因此該年不得作 true control。

### `relative_low`

年度在比較窗內排名偏低，但尚未通過 true-control 絕對資格。

### `true_control`

年度與必要 child-scope checks 都通過 control eligibility。

### `uncertain`

必要輸入、child-scope coverage 或 separation 不足以判定 high / control；不得硬選。

---

## 六、Annual rank 保持 deterministic、非 probability

v2 可重用現有：

- `engine/bazi/structural_relations.py`
- `ActivationEvidence`
- tier family / evidence count
- cross-layer Tier 1

年度 ordering 仍可使用 lexicographic structural rank；v1.6 不以單一 private case 反推新的神祕權重。

任何新增 numeric summary 都只能是 deterministic ordinal / diagnostic，不得標示事件機率或命中率。

---

## 七、Control eligibility

Control selection 分成兩步：

```text
Step 1: 找 annual relative-low candidates
Step 2: 對 candidate 做 absolute eligibility gate
```

至少必須檢查：

### 7.1 Annual Tier gate

以下任一成立，不能是 `true_control`：

- 有 Tier 1 annual evidence
- 有 decadal boundary
- annual rank 超過 profile 定義的 control ceiling

### 7.2 Local-window gate

若正式 child-scope ranking / local-window detector 找到：

```text
window_type = local_spike
```

則：

```text
control_eligible = false
role = localized_spike
```

v2 優先重用林氏天機 Phase 3 已有的 local-window concept；不得另造互相衝突的「historical peak」定義。

### 7.3 Separation gate

最低年度不能只因排名最低就成 control。

需要版本化的 `control_margin` / ordinal separation 規則，證明它與第二低或其餘年度有足夠差距。

規則必須：

- deterministic
- fixture-tested
- 不使用任何 historical event answer
- 不以特定命主年份硬編碼

### 7.4 Coverage gate

如果該 candidate 所需 child-scope coverage 不完整，輸出：

```text
role = uncertain
control_eligible = false
```

不得假設「沒算到 spike = 沒 spike」。

---

## 八、Abstention

v2 必須允許沒有 control：

```text
control_year = null
control_selection = abstain
```

使用情境：

- 所有 relative-low candidate 都有 local spike
- separation 不足
- coverage 不足
- input validation / maturity 不足

Historical Blind Calibration 上層必須接受 zero-control output，不得 fallback 回 `ranked[-1]`。

---

## 九、v2 output contract

至少新增：

```text
profile_id
rule_version
ranked_periods[]

annual_role
annual_rank_vector
annual_control_eligibility
control_rejection_reasons[]

local_window_status
local_windows[]

control_year
control_selection
control_quality
selection_digest
```

若保留 v1 相容欄位，必須明確標記其 compatibility semantics，不得讓 `control_quality` 繼續暗示 quiet-year prediction。

# Part B｜Interpretation vNext

## 十、目標

Interpretation vNext 不新增命盤 facts，也不自行排盤。

目標：

1. 吸收 Astralium 八字／紫微 Prompt 中有價值的 reading order。
2. 保留 Metaphysics Lab deterministic authority / blind lock / cutoff / specificity。
3. 採 evidence-chain，讓每個主要 claim 都能回溯。
4. 八字與紫微可以 convergence、different-layer 或 conflict，不強制統一。
5. 沒有足夠 evidence 時可以 abstain。

---

## 十一、Bazi reading order

Bazi interpretation 建議固定內部順序：

```text
1. 日主與四柱層次
2. 月令提綱
3. 藏干 / 透干 / 得令 / 通根 / 生扶 / 克洩耗
4. 格局線與用神入口
5. 扶抑 / 調候 / 病藥 / 通關若有，分欄保留，不硬合成唯一喜用
6. 本命合沖刑害破與柱位
7. 關係距離 / 貼鄰資訊若資料源提供
8. 神煞只作 auxiliary
9. 大運
10. 流年
11. 已 qualification 的 Project 流月 / 流日 / 流時
```

### 禁止事項

- 不能只用五行 count 自動判身強弱。
- 不能把十神名稱直接等同事件。
- 不能把神煞名稱直接等同吉凶或 concrete event。
- 不同用神方法不得無標示合併成唯一「真正喜用神」。

---

## 十二、Ziwei reading order

Ziwei interpretation 建議固定：

```text
1. 命宮 / 身宮 / 福德
2. 命財官遷三方四正
3. 十二宮對宮軸線
4. 主星、輔煞、亮度放回宮位 / 會照
5. 生年四化
6. 本命飛化（有則用）
7. 大限 / 當前階段
8. 流年
9. 小限只作已存在之輔線
10. Fine cycle 只使用 Project runtime 已正式提供且符合 maturity / routing 的層級
11. 重點看多層反覆牽動的宮位、軸線、主題
```

紫微不得因 Bazi 結論而回頭改盤，也不得為了「交叉印證」強行把不同 domain 說成一致。

---

## 十三、Cross-system roles

v1.6 固定三種跨體系關係：

```text
independent_convergence
layered_complement
conflict_or_divergence
```

### `independent_convergence`

Bazi 與 Ziwei 以不同 deterministic source 同時支持相同 domain / event family。

可提高 evidence clarity，但不能自動提高到 concrete-event probability。

### `layered_complement`

兩系統不是說同一件事，但層級互補，例如：

```text
Bazi -> activation / timing / resource-pressure nature
Ziwei -> career / family / finance domain localization
```

### `conflict_or_divergence`

兩邊指向不同 domain 或方向。

必須保留：

- Bazi evidence
- Ziwei evidence
- 各自 scope / maturity
- why-not-resolved

不得由 AI 直接選一邊並刪除另一邊。

---

## 十四、Claim Evidence Packet

AI 寫自然語言前，每個主要 claim 必須能對應到 structured packet：

```text
claim_id
primary_domain
event_family_candidates[]
time_scope

bazi_evidence[]
ziwei_evidence[]
source_layers[]
independent_support_count

cross_system_relation
conflicts[]
assumptions[]

base_allowed_specificity
effective_specificity
abstention_status
confidence_class
```

### confidence class

固定概念：

```text
high_confidence
moderate_confidence
low_confidence
```

Confidence 是 evidence / qualification / convergence 的表達，不是事件發生機率。

對外可以翻譯為：

- 高度確信
- 中度推測
- 低度推測

---

## 十五、Fact -> Rule -> Inference chain

對外不需要暴露 raw engineering IDs，但重要結論必須可以解釋成：

```text
盤面 / 運限事實
-> 使用的傳統 / Project interpretation rule
-> 推論到 domain / event family
-> specificity ceiling / confidence
```

這是 anti-Barnum 與 anti-hallucination contract。

---

## 十六、Abstention Contract

Interpretation vNext 必須正式支援：

```text
abstain_domain
abstain_event_family
abstain_timing
abstain_concrete_event
```

典型語意：

- 「盤面支持工作領域活躍，但不足以合理指定離職。」
- 「年度互動強，但目前無法從現有 evidence 鎖定落在合作還是工作。」
- 「年度相對低，但不能據此判定全年平靜；細時間層存在／尚未檢查局部峰值。」

AI 不得因使用者期待「講細一點」而突破 contract。

# Part C｜Prompt / Interpretation Bake-off

## 十七、Variant 定義

### V0｜Current

v1.5 current behavior / locked baseline。

### V1｜Astralium Classical

使用 Astralium-style Bazi + Ziwei reading order；不使用 Historical Personalization。

### V2｜Evidence-chain

使用：

```text
fact -> rule -> inference -> confidence
```

強化 abstention，不要求跨體系一定合參。

### V3｜Hybrid Structural

Bazi activation / timing + Ziwei domain localization + conflict preservation。

### V4｜Hybrid + Historical Personalization

V3 加 Phase 4 bounded historical personalization。

V4 必須遵守 per-target cutoff；任何 target year 都只能使用 cutoff 前已確認事件。

## 十九、Historical vs Prospective

### Historical dataset

用途：

- debug
- failure analysis
- model comparison
- regression

不得用來宣稱 prospective accuracy。

### Prospective dataset

正式評估必須：

1. 先有 `knowledge_cutoff_at`。
2. Stage 1 blind forecast immutable lock。
3. 保存 `matched_if / not_matched_if`。
4. 事件發生後才 evaluate。
5. Stage 2 calibration 不回寫 Stage 1。

只有 prospective accumulated evidence 才能支持「vNext 真的提高預測表現」的產品結論。

# Part D｜Acceptance Cases

## 二十、公開 synthetic acceptance patterns

共用 repo 至少要建立以下 synthetic fixtures，不使用私人事件原文。

### AC-01｜Relative-low annual + strong monthly spike

期待：

```text
annual_role = localized_spike
control_eligible = false
```

不得輸出：

```text
true_control
quiet_year
no_major_change
```

### AC-02｜Annual high + no reliable event-family localization

期待：

```text
activation = high
event_family = abstain / broad candidate set
```

不得因 high activation 硬指定 relationship / career / finance。

### AC-03｜True control

年度低、child scopes 無 local spike、separation 足夠、coverage 完整。

期待：

```text
annual_role = true_control
control_eligible = true
```

即使如此，自然語言仍只能說：

> 相較其他比較年份，結構活化較低。

不得說「一定沒大事」。

### AC-04｜No clean control

所有低排名候選都不通過 gate。

期待：

```text
control_selection = abstain
control_year = null
```

### AC-05｜Bazi/Ziwei independent convergence

兩個獨立體系同時支持同 domain。

期待：

```text
cross_system_relation = independent_convergence
```

不得轉成事件 probability。

### AC-06｜Bazi/Ziwei layered complement

Bazi 提供 timing / activation，Ziwei 提供不同層的 domain localization。

期待：

```text
cross_system_relation = layered_complement
```

### AC-07｜Bazi/Ziwei conflict

期待保留雙方 evidence，不強行統一。

### AC-08｜Specificity ceiling

只有 domain support 時不得輸出 concrete event；只有 event-family support 時不得輸出具體職稱、金額、醫療程序等。

### AC-09｜Cutoff contamination

V4 target 的 personalization 若包含 cutoff 後事件，必須 fail closed / reject。

### AC-10｜Historical lock immutability

v1 historical lock digest 不因 v2 re-analysis 改變。

## 二十一、Private qualification patterns

私人 Case 可以用來驗證：

1. v1 control false negative 是否被 v2 正確識別為 `localized_spike` 或至少 `not_true_control`。
2. high activation / no major outcome case 是否因 vNext abstention 降低 false positive。
3. 已知 matched high-year 是否仍能保留 domain / event-family alignment。
4. Ziwei 對團隊／家庭／財務等 domain localization 是否在不看答案的條件下提供增益。

共用 repo 只能提交 aggregate：

```text
case_count
matched / partial / missed counts
false-positive count
abstention count
contamination violations
fixture / output digests
```

不得提交 private event text。

# Part H｜Decision Rules

## 二十六、何時停止，不進 v1.6 runtime

以下任一成立即可停止：

- v2 只是把更多年份判成 high，沒有改善 control false negative。
- local spike 規則在 synthetic / private qualification 上造成大量 false alarm。
- V3/V2 合併後 unsupported inference 反而上升。
- V4 只有在使用 cutoff 後資料時才看起來比較好。
- improvement 只能在單一命主成立。

停止不代表失敗；保留 v1.5 baseline，研究結果可只進 docs / research notes。

---

## 二十七、推薦 implementation sequence

若本 spec 通過使用者 review，implementation plan 應依下列 gate 拆分：

```text
Task Group 1: freeze v1 regression + synthetic acceptance fixtures
Task Group 2: Selector v2 annual role / true-control / abstain
Task Group 3: local-window integration for control eligibility
Task Group 4: Claim Evidence Packet + cross-system relation
Task Group 5: Interpretation abstention / specificity contract
Task Group 6: V0-V4 offline evaluator + cutoff-safe V4
Task Group 7: private qualification aggregate
Task Group 8: distribution / docs / release qualification
```

每一 Task Group 都必須可單獨 review；不得在前一 gate RED 時繼續堆後面的功能。

---

# 二十八、核心結論

v1.6 不以「讓命理講得更像」為目標，而以三個可驗證改進為目標：

1. **Selector 不再把相對最低年自動當成真正低活化控制年。**
2. **Interpretation 不再把 activation 強弱直接等同具體事件；沒有足夠證據時正式 abstain。**
3. **Bazi + Ziwei 的合參從自由文字改成可追溯 evidence-chain，保留 convergence、互補與衝突。**

如果這三點在 synthetic、historical debug 與後續 prospective lock 中都成立，v1.6 才值得正式發布。
