# Metaphysics Lab v1.6 — Event-Family Hybrid Accuracy Architecture

## Status and provenance

- Design date: `2026-09-02`.
- Design status: approved in chat; implementation not started.
- Research branch: `research/v1.6-event-family-hybrid-accuracy-architecture`.
- Branch base: frozen I1 GitHub SHA `a6dfe4a5f9b80f0cb4763dad066e7b5873d29d85`.
- I1, S1, T1, O1, Q1, C1, Coordination C, Phase 3 ranking, Interpretation candidate semantics, frozen oracle behavior, and existing private governance remain read-only in this architecture cycle.
- Prior private outcomes, labels, aggregates, and case-level evidence are not design inputs for this architecture.
- No private evaluation is authorized by this design document.
- `promotion_allowed=false` throughout this research architecture until a separately authorized release decision exists.

## Problem

The current v1.6 pipeline is stronger at domain-level evidence control than at event-family-level authorization.

`EvidenceFeature` already carries:

- `primary_domain`;
- `event_family_support`;
- `system`;
- `scope`;
- `role`;
- `dependency_family`;
- `maturity`;
- `qualification_status`;
- provenance.

Phase 3 opens and ranks domains. For each opened domain, it unions the event-family support of target features into the domain's `event_families`. It separately de-duplicates evidence by dependency family for domain-ranking representatives. Claim Evidence later preserves the domain candidate set but does not preserve each selected evidence row's original `event_family_support` field. C1 then authorizes one parent claim per `(target_scope, primary_domain)`.

This creates a structural gap:

- the system may correctly know that a domain is active;
- the same domain may contain several event-family candidates;
- downstream authorization may no longer be able to prove which exact evidence supported which event family;
- a domain-level render authority can therefore be broader than the evidence actually supports at child-event level.

A downstream-only suppression layer can reduce false positives, but it cannot recover attribution information that disappeared earlier. It can therefore improve precision while harming recall.

The project goal is broader:

> Increase the number of supported event-family claims that are correctly surfaced, while preventing unsupported event families, unsupported specificity, false convergence, and narrative invention.

The architecture must therefore improve both recall preservation and render precision without turning the renderer into a new inference authority.

## Research objective

The target behavior is:

1. supported child events should not be lost merely because domain aggregation compressed provenance;
2. unsupported child events must not become renderable merely because the parent domain is active;
3. Bazi and Ziwei evidence must remain independently attributable;
4. valid single-system evidence must not be discarded merely because the other system lacks matching materialized evidence;
5. cross-system convergence must be recognized only at the same event-family granularity;
6. different supported event families may coexist as parallel Hybrid claims without being falsely merged;
7. specificity must never exceed the authority of the child evidence or the parent C1 ceiling;
8. the Hybrid renderer must express authorized content, not invent new event families, causality, or specificity;
9. improvement claims must be measured prospectively against a frozen baseline, not inferred from readability or post-hoc interpretation.

## Success definition

This architecture does not define success as "more abstention" or "fewer sentences."

The target direction is:

```text
supported-child recall:           up or non-inferior
unsupported-child rendering:      down or zero
specificity overreach:             down or zero
false convergence:                 zero
narrative invention:               zero
provenance loss:                   zero
determinism failures:              zero
```

A candidate that reduces false positives by suppressing valid child claims is not an accuracy improvement.

A candidate that increases raw hit count by rendering many unsupported candidates is also not an accuracy improvement.

For future paired prospective evidence, the research target is Pareto improvement: candidate supported-child hits must be at least the legacy baseline, candidate unsupported renders must be no greater than baseline, and at least one accuracy dimension must improve strictly before the result may be described as improvement evidence. This is a research conclusion rule, not release authorization.

## Non-goals

This first architecture cycle must not:

- change frozen Phase 3 domain ranking;
- change existing domain scores, weights, thresholds, or policy constants;
- change C1 behavior;
- change Q1 or the existing T1 strict-zero policy;
- change S1 or I1 eligibility rules;
- expand the event-family taxonomy;
- invent event families not already present in the frozen Phase 3 candidate universe;
- retune metaphysical mappings from private outcomes;
- use historical personalization, reality context, modifiers, or timing triggers to open a child event by themselves;
- parse prior private results to choose rules;
- infer semantic conflict merely because Bazi and Ziwei mention different event families;
- introduce a new numerical Hybrid score;
- introduce arbitrary max-N event-family budgets;
- merge, default-switch, tag, release, or authorize production promotion.

# 1. Event-Family Attribution (EFA)

## 1.1 Purpose

EFA preserves the relationship that already exists in immutable `EvidenceFeature` data:

```text
feature -> primary_domain -> event_family_support
```

It does not predict a new event and does not rank domains.

Its purpose is to prevent attribution loss between Structural Evidence and downstream claim authorization.

## 1.2 Inputs

EFA consumes only frozen/general production inputs:

- the full immutable Structural Interpretation `EvidenceFeature` set for the target scope;
- the exact frozen Phase 3 ranking for that scope;
- the target scope;
- existing provenance digests.

EFA must inspect the complete eligible Structural Evidence set, not only the Phase 3 dependency-family representatives in `feature_ids`.

Reason: Phase 3 domain ranking and event-family attribution answer different questions. Dependency de-duplication is valid for domain ranking but must not erase the fact that another target feature supports a different child event family.

## 1.3 Candidate universe

EFA may only emit child rows where:

```text
primary_domain is present in frozen Phase 3
AND
event_family is present in that Phase 3 domain's event_families
```

EFA v1 must not add an event family that is not already in the frozen Phase 3 candidate set.

This deliberately separates two research questions:

1. Can preserving already-existing event-family provenance improve recall and precision?
2. Is the upstream metaphysical `event_family_support` mapping itself incomplete?

Question 2, if needed, requires a separate later research cycle.

## 1.4 Child-opening authority

A child event family may be opened only by direct target evidence at the same target scope.

Required conditions for at least one opening feature:

```text
feature.primary_domain == child.primary_domain
child.event_family in feature.event_family_support
feature.role == target_evidence
feature.scope == target_scope
feature.qualification_status != unqualified
```

The following may attach context but may not open a child by themselves:

- `modifier`;
- `timing_trigger`;
- historical personalization;
- reality context;
- a different scope's target evidence.

This mirrors the existing Phase 3 principle that modifiers and timing triggers cannot open a domain without target-owned evidence.

## 1.5 Maturity and qualification semantics

EFA does not convert uncertainty into automatic abstention.

- `qualified + stable`: normal direct child support.
- `qualified + experimental`: may open the child, but experimental status cannot increase confidence or specificity by itself.
- `needs_verification`: may open the child, but the child must carry a required caveat into C2/HOC.
- `unqualified`: cannot open or independently support the child.

This prevents a recall collapse caused by treating every experimental or verification-needed feature as invalid while still preserving user-facing caution.

## 1.6 Child identity

Child identity must be deterministic and derived only from frozen structured fields.

Conceptual identity:

```text
parent_claim_id + event_family
```

Canonical public form should be equivalent to:

```text
child:<target_scope>:<primary_domain>:<event_family>
```

Unsafe delimiter/newline cases must use the same canonical-digest discipline already used elsewhere in the repository.

The implementation plan may choose the exact helper name, but identity must be stable across input permutation and must not depend on private labels or rendered text.

## 1.7 Per-child evidence map

Each EFA child row must preserve at least:

```text
child_claim_id
parent_claim_id
primary_domain
event_family
target_scope
candidate_source = phase3
bazi_target_feature_ids
ziwei_target_feature_ids
modifier_feature_ids
timing_trigger_feature_ids
direct_target_dependency_families
direct_target_systems
maturity_summary
qualification_summary
required_verification_caveat
family_specificity_ceiling
source_ranking_digest
source_structural_interpretation_digest
```

Feature provenance remains available for technical audit. User-facing output does not expose raw internal feature vectors unless a technical-audit surface explicitly requests them.

## 1.8 Family specificity ceiling

EFA reuses existing ordinal specificity semantics rather than inventing a new score.

For one event family:

```text
no direct same-scope target support
    -> no child authority

>= 1 direct same-scope target support
    -> event_family ceiling

stable direct support
AND >= 2 independent direct target dependency families
    -> concrete_event eligible ceiling
```

Experimental-only support cannot independently raise a child from event-family to concrete-event authority.

No EFA rule may create `highly_specific_event` authority in this first cycle unless an already-frozen upstream authority explicitly supplies that ceiling and the implementation design separately proves compatibility. The default first-cycle ceiling is therefore at most `concrete_event`.

## 1.9 EFA determinism

EFA output must be canonical and digest-bound.

Input permutation must not change:

- child set;
- child identity;
- evidence membership;
- system/dependency summaries;
- specificity ceiling;
- bundle digest.

# 2. C2 Hierarchical Claim Authority

## 2.1 Purpose

C1 remains the frozen parent-domain render authority.

C2 adds child-event-family authority below C1 without modifying the parent decision.

C2 answers:

> Given an existing parent claim and an EFA child attribution, may this specific child be rendered, must it be caveated, or must it be withheld?

## 2.2 Inputs

C2 consumes:

- frozen C1 claim-consumption bundle;
- EFA bundle;
- matching target scope and provenance digests.

C2 must reject mismatched source identity, target scope, parent claim identity, Phase 3 candidate set, or digest provenance.

## 2.3 Parent fail-closed rule

If C1 parent decision is:

```text
abstain_claim
```

all children of that parent must be:

```text
abstain_child
```

C2 cannot reopen a parent that C1 has closed.

## 2.4 Child authorization

For a C1-renderable parent:

- EFA child with direct opening support may be `render` or `render_with_caveat`;
- EFA candidate without direct opening support must be `abstain_child`;
- modifier-only or timing-only support must never produce a renderable child.

Conceptual decision set:

```text
render
render_with_caveat
abstain_child
```

## 2.5 Child specificity

The final child specificity is the most conservative authority among the child and parent ceilings:

```text
authorized_child_specificity = min(
    EFA family_specificity_ceiling,
    C1 parent authorized_specificity
)
```

C2 cannot raise specificity above either source.

If the parent is only `domain` specificity, a child event family cannot be rendered as an event-family prediction even if EFA has direct support; the child remains audit-preserved but non-renderable under the parent authority.

## 2.6 Caveat semantics

A child must be `render_with_caveat` when any required limiting condition exists, including at least:

- parent C1 already requires a caveat;
- child depends on `needs_verification` direct support;
- child direct support is experimental-only;
- only one materialized system directly supports the child;
- parent/child specificity was conservatively downgraded;
- an explicit upstream conflict/divergence marker applies to that child.

The exact deterministic reason-code ordering belongs in implementation, but the reason universe must be general-only and frozen before private evaluation.

## 2.7 No absence penalty

If one metaphysical system has no legally materialized evidence for the target scope, its absence must not be treated as contradiction or negative support against the other system.

A valid Bazi-only child or Ziwei-only child may therefore remain renderable with an appropriate single-system caveat.

# 3. Hybrid Claim Composer (HCC)

## 3.1 Purpose

HCC does not decide metaphysical truth and does not reopen C2-abstained children.

It organizes already-authorized child claims into a Hybrid representation that preserves:

- source-system identity;
- convergence where real;
- parallel sibling signals where different;
- layered complement where support exists at different roles/scopes;
- valid single-system claims;
- explicit divergence when upstream evidence actually materializes it.

## 3.2 Renderable Claim Selection becomes visibility classification

HCC must not implement a destructive "top N child claims" selector.

Every C2 `render` or `render_with_caveat` child remains present in the machine-readable HCC bundle.

Only `abstain_child` is `audit_only` and unavailable to ordinary rendering.

Visibility classes are:

```text
primary
secondary
audit_only
```

These are presentation classes, not truth labels.

## 3.3 Presentation tier inheritance

HCC must not create a new numerical Hybrid ranking.

Child presentation tier inherits the existing frozen Interpretation domain presentation:

```text
parent domain in Interpretation.primary_domains
    + renderable child
    -> child visibility = primary

parent domain in Interpretation.secondary_domains
    + renderable child
    -> child visibility = secondary

C2 abstain_child
    -> child visibility = audit_only
```

This preserves the current domain presentation authority instead of adding a second scoring engine.

## 3.4 Event-family order inheritance

Within a domain, HCC preserves existing event-family presentation order:

- if existing approved personalization provides `personalized_event_family_order`, use it exactly;
- otherwise use the frozen Interpretation/Phase 3 event-family candidate order;
- HCC may group related claims for narrative structure but must not silently rerank child evidence based on a new score.

No child disappears merely because it is later in the inherited order.

## 3.5 Hybrid relation classes

### `direct_convergence`

Both Bazi and Ziwei have direct same-scope target evidence for the same child event family.

This relation is event-family-level. Same-domain support alone is insufficient.

### `single_system_qualified`

Exactly one materialized system has direct same-scope target support for the child.

This remains a valid claim when C2 permits it. Missing evidence from the other system is not contradiction.

### `layered_complement`

One system directly opens the child at target scope while another system contributes a valid modifier/timing/background relationship to the same child family without opening it independently.

The complementary system cannot increase the child's existence authority by itself.

### `parallel_sibling`

Bazi and Ziwei support different valid child event families under the same domain.

Example:

```text
Bazi  -> career / role_change
Ziwei -> career / leadership_change
```

These claims may be composed under a shared career theme, but they must not be relabeled as direct convergence.

### `divergence`

HCC may emit divergence only when an existing upstream structured authority/provenance explicitly materializes a conflict or directional divergence relevant to the child claims.

Different event-family names alone are not evidence of contradiction.

HCC must preserve explicit divergence rather than force a unified conclusion.

## 3.6 Hybrid relation does not create render authority

Relation classification occurs after C2 authorization.

A Hybrid relation may affect:

- grouping;
- wording obligations;
- caveat requirements;
- explanation structure.

It may not:

- reopen an abstained child;
- add a new event family;
- raise specificity;
- convert a modifier into target evidence;
- convert a secondary domain into a higher-ranked domain;
- erase source-system provenance.

# 4. Hybrid Output Contract (HOC)

## 4.1 Purpose

HOC is the final structured authority presented to the language renderer.

The renderer's job is language realization, not claim discovery.

## 4.2 Minimum structured fields

Each renderable HOC unit must contain at least:

```text
child_claim_id
parent_claim_id
primary_domain
event_family
target_scope
source_systems
hybrid_relation
visibility
c2_decision
authorized_specificity
required_caveats
supporting_feature_ids
source_evidence_digest
source_c1_digest
source_efa_digest
source_c2_digest
```

Audit-only rows remain in a separate technical-audit collection and must not be exposed to ordinary renderer input.

## 4.3 Renderer permissions

The renderer may:

- translate structured claims into natural Traditional Chinese;
- group parallel authorized claims under a broader already-authorized domain theme;
- explain that Bazi and Ziwei support the same child independently;
- explain that different systems support different sides of the same domain;
- preserve required caveats;
- distinguish primary and secondary observations;
- state explicit divergence when supplied by HCC.

## 4.4 Renderer prohibitions

The renderer must not:

1. create a new event family;
2. raise specificity;
3. create unsupported causal chains;
4. turn parallel sibling claims into direct convergence;
5. infer contradiction from missing materialization;
6. erase explicit divergence;
7. remove a required caveat;
8. convert modifier/timing context into target evidence;
9. use `audit_only` claims;
10. transform a broad authorized event family into a specific real-world event unless the structured specificity authority allows it.

Example of permitted synthesis:

```text
career / role_change
career / leadership_change
```

may become:

> 工作角色與權責結構都有調整訊號。

It must not become:

> 你一定會跳槽升主管。

unless those concrete events are independently authorized.

## 4.5 Hybrid reading behavior

The user-facing reading should remain coherent and non-mechanical.

A typical output structure may express:

- core convergent themes;
- parallel Bazi/Ziwei child signals;
- secondary valid observations;
- explicit uncertainty or divergence;
- strategy implications kept separate from forecast truth.

HOC constrains what may be said; it does not force the renderer to expose internal field names or feature vectors.

# 5. Q2 — Child-Level General/Synthetic Qualification

## 5.1 Why Q2 is separate from Q1

Existing Q1 qualifies frozen C1 parent claims. It expects exact C1 claim IDs and domain-level authorization decisions.

The new architecture introduces event-family child identities, HCC relations, visibility classes, and narrative-boundary invariants. Reusing Q1 would conflate two contracts.

Q1 and T1 therefore remain frozen and unchanged.

Q2 is a new independent research qualification authority for the new child-level pipeline.

## 5.2 Q2 scope

Q2 must be independent of production C2/HCC decision code in the same way Q1 is independent of C1 policy.

It scores frozen structured outputs against synthetic/general expectations.

It must not tune EFA, C2, HCC, or HOC.

## 5.3 Synthetic fixture matrix

The baseline general/synthetic matrix must include at least:

1. one domain with two event families where only one has direct target support;
2. modifier-only support that cannot open a child;
3. timing-only support that cannot open a child;
4. Bazi and Ziwei direct support for the same child -> direct convergence;
5. Bazi and Ziwei direct support for different child families -> parallel siblings;
6. single-system qualified child while the other system is not materialized;
7. layered complement where target support comes from one system and context from another;
8. parent C1 abstain -> all children fail closed;
9. parent specificity lower than child evidence ceiling -> child capped by parent;
10. stable multi-dependency child eligible for concrete-event ceiling;
11. experimental-only child remains renderable only with caveat and no specificity upgrade;
12. `needs_verification` child requires caveat;
13. unqualified evidence cannot open a child;
14. explicit upstream divergence is preserved;
15. different family names without explicit conflict are not labeled divergence;
16. primary-domain child inherits primary visibility;
17. secondary-domain child inherits secondary visibility;
18. C2-abstained child becomes audit-only;
19. personalized event-family order is preserved exactly;
20. input permutations yield byte-identical canonical output/digests.

## 5.4 Q2 counters

At minimum Q2 must measure:

### Attribution

```text
supported_child_miss_count
unsupported_child_open_count
role_scope_attribution_error_count
provenance_loss_count
```

### Authority

```text
over_render_count
under_render_count
specificity_overreach_count
specificity_excessive_downgrade_count
caveat_omission_count
unnecessary_caveat_count
```

### Hybrid composition

```text
false_convergence_count
missed_convergence_count
parallel_merge_error_count
divergence_erasure_count
false_divergence_count
false_absence_penalty_count
visibility_loss_count
```

### Output-contract safety

```text
narrative_invention_count
unsupported_causality_count
audit_leak_count
renderer_specificity_overreach_count
```

### Integrity

```text
identity_mismatch_count
source_digest_failure_count
determinism_failure_count
```

## 5.5 General synthetic PASS

The baseline synthetic fixture is intentionally exact and deterministic.

`general_conformance_status=PASS` requires every negative counter above to equal zero.

This strict-zero synthetic gate is a capability gate, not a private release threshold.

It specifically prevents the degenerate solution where the system abstains from everything: valid expected children are part of the oracle, so blanket abstention produces `supported_child_miss_count` and/or `under_render_count` failures.

`promotion_allowed=false` in Q2.

# 6. Frozen Legacy Adapter for Paired Comparison

## 6.1 Purpose

To test whether the new architecture really improves event-family accuracy, the project needs a deterministic baseline on the same child-level evaluation surface.

Natural-language post-hoc interpretation is not an acceptable baseline adapter.

## 6.2 Baseline source

The Legacy Adapter consumes only frozen structured legacy outputs, including the existing Interpretation event-family candidate set and C1 parent authorization.

For each legacy parent claim:

- if parent C1 is not renderable, no child is baseline-renderable;
- if parent authorized specificity is below `event_family`, no child is projected as an event-family render;
- if parent is renderable at `event_family` or above, the adapter deterministically projects the event-family candidates that the existing parent contract makes available at that specificity.

This exposes the breadth of the legacy parent authorization without parsing prose.

The exact adapter contract must be frozen and synthetically tested before any new private evaluation.

## 6.3 No result-aware adaptation

The Legacy Adapter must not:

- inspect private outcomes;
- use free-form renderer text to choose favorable mappings after the fact;
- relabel one legacy event family into another based on what happened;
- change after oracle reveal.

# 7. Paired Prospective Blind Evaluation

## 7.1 Purpose

Synthetic PASS proves that the architecture can preserve recall and precision under known structured conditions.

It does not prove that real metaphysical event prediction improved.

Real improvement evidence requires new, previously unexposed prospective evaluation.

## 7.2 Paired design

For each legally eligible new case, the frozen Legacy baseline and frozen new candidate must be evaluated against the same eventual child-level oracle.

The two systems must be independently sealed before outcome knowledge may influence scoring.

### Future prospective case

For a genuinely future case:

1. intake/provenance eligibility is established;
2. Legacy output is generated and sealed before the outcome window;
3. new candidate output is generated and sealed before the outcome window;
4. no outcome is used for tuning either output;
5. after the outcome window, an independent structured oracle is adjudicated and sealed;
6. both frozen outputs are scored against the same oracle exactly once.

### Previously unexposed historical case

For a legally eligible historical case:

1. source provenance and never-exposed status are verified;
2. an independent oracle may be prepared and sealed before candidate scoring;
3. Legacy and candidate outputs are generated without oracle access;
4. both are scored once against the same sealed oracle.

In both modes, case-level private content remains outside public repository artifacts.

## 7.3 Paired research metrics

The paired report should include aggregate-only comparisons such as:

```text
supported_child_hit_count
supported_child_miss_count
unsupported_child_render_count
specificity_overreach_count
caveat_error_count
false_convergence_count
narrative_invention_count
```

Recall and precision ratios may be reported when denominators are defined, but research conclusions should also retain raw paired counts to avoid denominator artifacts on small samples.

## 7.4 Improvement evidence rule

A single paired case may be described only as first prospective evidence, not universal proof.

A candidate may receive the research label `PARETO_IMPROVEMENT_EVIDENCE` for a paired evaluation only when:

```text
candidate supported_child_hit_count >= legacy supported_child_hit_count
candidate unsupported_child_render_count <= legacy unsupported_child_render_count
candidate specificity_overreach_count <= legacy specificity_overreach_count
candidate narrative_invention_count <= legacy narrative_invention_count
AND
at least one of the above dimensions improves strictly
```

This label does not authorize release or merge.

Other possible research labels are:

```text
NON_INFERIOR_NO_STRICT_GAIN
TRADEOFF
REGRESSION
```

Private release policy, if ever needed for this new architecture, must be designed and frozen separately from general-only rationale before private results are opened.

## 7.5 Exactly-once and exposure governance

Any evaluated private case becomes exposed after scoring and cannot be reused as prospective evidence or tuning input.

A failed private cycle cannot be retuned against the same case and rerun as if prospective.

Existing Q1/T1/S1/I1 governance remains intact and is not relaxed by Q2.

# 10. Failure behavior

All new structured layers fail closed on:

- malformed or non-canonical input;
- unknown required-schema fields where strict schema applies;
- duplicate child IDs;
- source digest mismatch;
- target-scope mismatch;
- parent-child domain mismatch;
- event family outside the frozen Phase 3 candidate universe;
- child specificity above parent authority;
- C2 child render under a C1-abstained parent;
- renderer access to audit-only content;
- mismatched Legacy/Candidate/oracle evaluation identities.

No layer silently repairs inconsistent input.

# 12. Governance conclusion

This architecture separates four responsibilities:

```text
EFA
    preserves supported-event recall and provenance

C2
    prevents unsupported child rendering and specificity overreach

HCC/HOC
    preserves correct Bazi/Ziwei Hybrid composition without inventing truth

Q2 + paired prospective evaluation
    measures whether the system actually becomes more accurate rather than merely more conservative
```

The intended product behavior is therefore:

> Catch more of the event families that existing structured evidence genuinely supports, do not render event families that lack direct authority, preserve Bazi/Ziwei differences and convergence honestly, and prevent the language renderer from upgrading structured evidence into unsupported real-world claims.
