# Metaphysics Lab v1.9.0｜發布說明

> 發布日期：**2026-10-03**  
> 正式版本：**v1.9.0**  
> 正式發布提交：以 Git tag `v1.9.0` 與 GitHub Release 指向的提交為正式依據

> 文件維護註記（2026-10-04）：本頁於正式發布後只做台灣繁體中文用語與可讀性修正。此修正不改變 `v1.9.0` 標籤、GitHub Release、已發布檔案內容或雜湊摘要，也不改變任何版本契約、功能成熟度、預設啟用方式與歷史驗證證據。正式發布身分與技術狀態仍以 `GitHub`、`VERSION.md`、`runtime_info` 與既有驗證紀錄為準。

v1.9.0 是一個以**出生時間不確定性、個案本命修訂完整性與鎖定紀錄可追溯性**為核心的小版本更新。這一版把先前分散在候選盤、本命修訂與盲判鎖定中的規則收斂成可重現的正式執行流程，同時新增候選盤摘要視覺化。

本版**不包含任何功能成熟度升級為 `stable`**，也不更動 selector v1／interpretation v1 的預設地位。

## 使用者會感受到的改變

### 1. 出生時間不確定時，不再被迫猜一個時間

出生時間現在明確分成：

- `exact`：已知精確時間
- `bounded`：只知道一段範圍
- `unknown_time`：目前不知道出生時間

系統不會為了完成排盤，自行補區間中點、12:00、任意時辰或夏令時間重複時段中的某一個時間點。

當資料允許時，會建立**候選盤面集合（Candidate Envelope v2）**，保留所有合法候選狀態，只把所有候選一致的部分視為確定資料。

### 2. 引導式本命建立（Guided Natal Build）成為建盤的正式流程依據

`natal.guided_build_state` 會依目前的結構化出生資料、地點解析、候選盤與個案資料狀態決定下一步。

AI 只能依執行環境回傳的 `next.action` 執行，不再以聊天記憶自行判斷「是不是已完成」，也不能替使用者挑候選盤或出生時間。

### 3. 專案規格升為 1.3，個案資料格式仍維持 1.1

v1.9.0 的專案規格（Project Contract）從 1.2 升到 **1.3**，新增本命修訂與本命基礎檔案的綁定資訊：

- `natal_revision_id`
- `base_case_digest`
- `case.replace_natal_base`

個案資料格式（Case Schema）仍是 **1.1**，因此不需要做破壞性的整批資料結構移轉。

既有使用 Project Contract 1.2 的個案資料仍可讀取，也不要求整批重建私人個案資料。

### 4. 個案本命修訂完整性（Case Revision Integrity）

如果出生資料、候選盤或已採用本命發生實質修正，新的本命基礎檔案（Base Case）會產生新的修訂版本識別。

安全替換本命基礎資料時：

- 重新建立 00～04 本命基礎檔案
- 保留既有 05～08 追蹤／歷史檔案
- 保留修訂版本沿革
- 不把舊事件紀錄改寫成新本命原本就有的證據

### 5. 鎖定來源追溯（Lock Provenance v2）

新建立、可辨識本命修訂版本的鎖定紀錄可以綁定：

- 命主識別
- `natal_revision_id`
- `base_case_digest`
- 當時使用的正式本命基礎檔案
- 預測方法版本

因此新的前瞻預測鎖定紀錄、第一階段盲判鎖定紀錄與歷史事件校準鎖定紀錄，都能明確回答「當時到底綁的是哪一版本命資料」。

**舊鎖定紀錄維持不可變**：不補寫來源追溯資訊、不重新簽署，也不重算原有雜湊摘要。

### 6. 候選盤摘要視覺化（Visualization P1）

新增公開功能：

`render_candidate_envelope_summary`

它可以把 Candidate Envelope v2 轉成依固定規則產生的 SVG、純文字替代版與結構化摘要，顯示：

- 出生時間精度
- 合法候選數、實際盤面狀態數與尚未解析的時間分支
- 候選時間區間
- 所有候選一致、隨候選改變、未判定與不可用的欄位數
- 目前允許與暫時禁止的分析範圍

這項視覺化功能只負責呈現。它**不做候選排名、不提供機率、不選出生時間，也不新增預測證據**。

## 升級方式

從 **v1.8.0 升到 v1.9.0**，請三檔一起同步：

1. `metaphysics_lab.py`
2. `metaphysics_core.md`
3. `project_instructions.txt`

建議直接下載：

`Metaphysics-Lab-v1.9.0-User-Package.zip`

既有的 `命主索引.md`、私人個案資料、驗證事件、流年／問事／重大決策紀錄與所有已鎖定預測都應保留。

更新完成後執行 `runtime_info`，確認：

```text
Capability Manifest        1.0
```

## 既有資料如何處理

### 既有 Project Contract 1.2 個案資料

相容性測試仍保留既有契約識別字串 `既有 1.2 Case`；實際意義就是既有 Project Contract 1.2 個案資料。

既有資料仍可讀取，不需要為了安裝 v1.9.0 立即批次改寫。

只有當本命基礎資料真的需要更新，或新流程明確要求把本命基礎檔案綁定到新的修訂版本時，才使用正式的本命修訂流程。

### 舊鎖定紀錄

相容性測試中的既有識別字串為 `舊 lock`；既有發布契約同時保留 `不回填`、`不重簽` 兩個歷史相容性識別。正文統一使用「不補寫來源追溯資訊、不重新簽署」等自然中文說明。

舊鎖定紀錄保留原始內容與識別資訊。

v1.9.0 **不補寫、不重新簽署，也不重新計算舊鎖定紀錄的雜湊摘要**。

新的修訂版本綁定只影響之後新建立的鎖定紀錄。

## 研究與成熟度邊界

v1.9.0 是軟體與資料治理版本更新，不是預測效度升級。

Candidate Envelope v2、Guided Natal Build、Lock Provenance v2與Visualization P1的加入，代表流程變得更可重現、可稽核，也較不容易誤用；**不代表命理預測準確率因此被證明提高**。

目前各項功能是否已實作、成熟度與啟用方式，仍以 `runtime_info` 回傳的技術資訊為正式依據。
