# Metaphysics Lab v1.9.0｜發布說明

> 發布日期：**2026-10-03**  
> 正式版本：**v1.9.0**  
> 正式發布提交：以 Git tag `v1.9.0` 與 GitHub Release target 為 authority

v1.9.0 是一個以**出生時間不確定性、個案修訂完整性與可追溯鎖定**為核心的小版本更新。這一版把先前分散在候選盤、Case 修訂與盲判鎖定中的規則收斂成可重現的正式 runtime 流程，同時新增候選盤摘要視覺化。

本版**不包含 Stable promotion**，也不更動 selector v1／interpretation v1 的預設地位。

## 使用者會感受到的改變

### 1. 出生時間不確定時，不再被迫猜一個時間

出生時間現在明確分成：

- `exact`：已知精確時間
- `bounded`：只知道一段範圍
- `unknown_time`：目前不知道出生時間

系統不會為了完成排盤自行補中點、12:00、任意時辰或 DST fold occurrence。

當資料允許時，會建立 **Candidate Envelope v2**，保留所有合法候選狀態，只把所有候選一致的部分視為確定資料。

### 2. Guided Natal Build 成為建立本命的流程 authority

`natal.guided_build_state` 會依目前結構化出生資料、地點解析、候選盤與 Case 狀態決定下一步。

AI 只能依 runtime 回傳的 `next.action` 執行，不再以聊天記憶自行判斷「是不是已完成」、也不能替使用者挑候選盤或出生時間。

### 3. Project Contract 升為 1.3，但 Case Schema 仍維持 1.1

v1.9.0 的 Project Contract 從 1.2 升到 **1.3**，新增本命修訂與 Base Case 綁定：

- `natal_revision_id`
- `base_case_digest`
- `case.replace_natal_base`

Case Schema 仍是 **1.1**，因此不是破壞性的 schema migration。

既有 1.2 Case 仍可讀；不要求整批重建私人 Case。

### 4. Case Revision Integrity

如果出生資料、候選盤或已採用本命發生實質修正，新的 Base Case 會產生新的 revision identity。

安全替換本命基礎資料時：

- 重新建立 00～04 Base Case
- 保留既有 05～08 追蹤／歷史檔案
- 保留 revision lineage
- 不把舊事件紀錄改寫成新本命的既有證據

### 5. Lock Provenance v2

新的 revision-aware lock 可以綁定：

- subject
- `natal_revision_id`
- `base_case_digest`
- canonical Base Case source files
- method version

這讓新的 prospective lock、Stage 1 blind lock與Historical Calibration lock都能明確回答「當時到底綁的是哪一版本命資料」。

**舊 lock 維持不可變**：不回填 provenance、不重簽、不重算 digest。

### 6. Visualization P1

新增公開 action：

`render_candidate_envelope_summary`

它可以把 Candidate Envelope v2 轉成 deterministic SVG、純文字替代版與結構化摘要，顯示：

- 出生時間精度
- legal / materialized / unresolved occurrence
- 候選時間區間
- invariant / variant / undetermined / unavailable fact counts
- blocked / allowed analysis scope

Visualization P1 只是呈現層。它**不做候選排名、不提供機率、不選出生時間，也不新增預測證據**。

## 升級方式

從 **v1.8.0 升到 v1.9.0**，請三檔一起同步：

1. `metaphysics_lab.py`
2. `metaphysics_core.md`
3. `project_instructions.txt`

建議直接下載：

`Metaphysics-Lab-v1.9.0-User-Package.zip`

既有的 `命主索引.md`、私人 Case、驗證事件、流年／問事／重大決策紀錄與所有已鎖定預測都應保留。

更新完成後執行 `runtime_info`，確認：

```text

Runtime Schema             1.1

Capability Manifest        1.0
```

## 既有資料如何處理

### 既有 1.2 Case

既有 1.2 Case 保持 readable，不需要為了安裝 v1.9.0 立即批次改寫。

只有當本命基礎資料真的需要更新，或新流程明確要求建立 revision-bound Base Case 時，才走正式的 Case Revision Integrity 路徑。

### 舊 lock

舊 lock 保持原始 bytes與identity。

v1.9.0 **不回填、不重簽、不重新計算舊 lock digest**。

新的 revision-bound lock只影響新建立的鎖定紀錄。

v1.9.0 是軟體與資料治理release，不是預測效度promotion。
