# v1.6 Claim Consumption Qualification Q1

## Purpose

Q1 adds a deterministic qualification authority for the already-frozen Claim Consumption C1 output. It measures whether each C1 authorization is appropriate against an independently adjudicated structured oracle.

Q1 **does not tune C1**. The production policy remains upstream and read-only. The evaluator does not recompute Bazi, Ziwei, Claim Evidence, Coordination, ranking, or C1 decisions.

## Input schema

Schema: `v1.6-claim-consumption-qualification-input.v1`.

Each input is classified as either:

- `synthetic_validation`; or
- `private_external_evaluation`.

Each case contains only:

- opaque `case_id`;
- the public C1 `claim_consumption_bundle`;
- structured expectations keyed by `claim_id`;
- `cutoff_contamination`;
- deterministic `input_digest`.

The expectation contract uses:

- `expected_authorization`;
- `minimum_acceptable_specificity`;
- `maximum_specificity`;
- `caveat_required`.

`minimum_acceptable_specificity` is required for renderable claims because a maximum alone can detect overreach but cannot detect excessive downgrade.

Unknown fields fail closed. This intentionally rejects raw or identifying fields such as subject names, birth data, event text, narrative notes, or equivalent private payload.

## Metrics

The aggregate evaluator records:

- decision alignment: `matched / partial / missed`;
- over-render;
- under-render;
- caveat omission;
- unnecessary caveat;
- specificity overreach;
- specificity excessive downgrade;
- cutoff contamination.

Specificity is ordered conservatively:

`domain < event_family < concrete_event < highly_specific_event`.

## Synthetic conformance

For `synthetic_validation`, the baseline oracle is designed to be fully matched. General conformance requires zero cutoff contamination, zero over-render, zero specificity overreach, zero partial alignment, and zero missed alignment.

Negative tests mutate synthetic cases to verify all counters and fail-closed schema paths. These synthetic mutations are not private evidence and are not used to tune C1.

## Private governance

Q1 does not reuse **prior private** Interpretation domain/event-family labels as claim-level authorization labels. Those contracts measure different things.

A `private_external_evaluation` input must come from a separately adjudicated claim-level oracle that was **sealed** before candidate scoring. The evaluator emits an **aggregate-only** report: no case IDs, claim IDs, domains, reason codes, subject data, or event text are returned in the public report.

For private inputs Q1 currently reports `METRICS_ONLY` unless cutoff contamination forces `FAIL`. It intentionally does not define acceptable non-zero private under-render or unnecessary-caveat thresholds from previous private outcomes.

`promotion_allowed` is always `false` in Q1. Q1 is measurement authority, not release authority, and cannot promote a release by itself.

Before any future Q1 private run, the project must separately freeze any release thresholds from general rationale only, prepare and seal the claim-level oracle, freeze a candidate SHA, pass local and Hosted general gates, and then run the private external evaluation exactly once.

## CLI

```bash
python tools/evaluate_v16_claim_consumption_qualification.py --input PATH
python tools/evaluate_v16_claim_consumption_qualification.py --input PATH --output REPORT.json
```

Without `--output`, the report is written deterministically to stdout. With `--output`, exactly the same bytes are written to the file and stdout remains empty.
