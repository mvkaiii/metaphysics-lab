# v1.6 Prospective Case Intake Runbook

## Purpose

這份 runbook 定義新 private case 如何在進入 S1 之前被首次登錄與鎖定。Intake 只處理來源、首次納入時間與 candidate exposure provenance；它不評命理答案、不產生 claim-level oracle，也不取代 frozen S1 complete-census authority。

正式 profile：`lin_tianji_claim_consumption_prospective_case_intake_v1`。

## Accepted origins

### `FUTURE_EVENT`

Case 必須在 outcome 尚未知道時完成 intake，所以 `outcome_availability_at_intake=PENDING`。先登錄、後等待 outcome，避免事件發生後才挑選看起來有利的案例。

### `HISTORICAL_UNEXPOSED`

已發生的歷史 case 可以首次加入研究母體，但 `outcome_availability_at_intake=KNOWN`，且必須能證明：

- source record 在 intake 前已存在；
- 這是該 case 首次進入這條研究線；
- case 從未對目前或先前相關 candidate 暴露；
- source / first-intake / exposure provenance 都可重現。

不能因為事件是歷史事件就自動視為乾淨 control。

## Provenance fail-closed

以下任一證據無法驗證時，intake 結果固定為 `INELIGIBLE_SOURCE_PROVENANCE`：

- source provenance；
- first-intake provenance；
- candidate exposure provenance。

若已確認曾對 candidate 暴露，固定為 `INELIGIBLE_PREVIOUSLY_EXPOSED`。換 case ID、換 branch、換 digest 或重新登錄都不能洗掉 exposure history。

## Registry snapshots

Real registry 永遠留在 git 外。Public repo 只保存空白 template、JSON schema、synthetic tests 與本 runbook。

每次更新 private registry 都建立新的 snapshot：

1. 讀取上一份 registry；
2. 保留所有既有 records 原封不動；
3. 只 append 新 case；
4. 新 snapshot 的 `previous_registry_digest` 必須等於上一份 `registry_digest`；
5. `registry_locked_at` 不得倒退；
6. 舊 record 不得修改、刪除或重新分類。

這個 hash chain 是 first-intake provenance 的一部分，而不是 scoring authority。

## Handoff to S1

`ELIGIBLE_FOR_S1_SOURCE` 只代表 provenance intake 合格，**不代表 S1 INCLUDE**。後續仍由 frozen S1 根據 cutoff、confirmation、input validity、scope、exposure 與 outcome-free claim universe 建立 complete-census frame。

因此合法順序是：

`case intake -> private registry snapshot -> S1 source manifest / claim-universe lock -> S1 frame / receipt -> claim adjudication -> O1 -> candidate -> Q1 -> T1`

任何 `INELIGIBLE_SOURCE_PROVENANCE` 或 `INELIGIBLE_PREVIOUSLY_EXPOSED` case 都不得靠人工 override 直接送入 S1。

## Operational checklist

- 先決定 `FUTURE_EVENT` 或 `HISTORICAL_UNEXPOSED`，不可事後改 origin 來取得資格。
- 對 source artifact、first-intake evidence、exposure evidence 各自產生 SHA-256 digest；private raw evidence 不進 git。
- 建 registry snapshot 時使用 explicit output path。
- 建完後執行 validator，只把 aggregate verification 留在公開 audit；不要公開 opaque case ID 或 private provenance digests。
- intake 不會自動搜尋、挑選、補齊或重新解釋 cases。
