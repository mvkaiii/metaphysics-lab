## 1. Research question

Can Python add a deterministic claim-consumption authority between frozen Claim Evidence / Coordination output and Hybrid AI rendering, without changing Phase 3 ranking, claim candidates, domain ordering, confidence authority, or the frozen Coordination C semantics?

The new layer answers only whether an already-authorized claim may be consumed by a renderer:

- `render`
- `render_with_caveat`
- `abstain_claim`

It does not create, rerank, rewrite, merge, or delete upstream evidence or claims.

## 2. Position in the architecture

```text
EvidenceFeature
  -> Phase 3 Ranking
  -> Interpretation v1 authority
  -> Claim Evidence Packet
  -> frozen Coordination C
  -> Claim Consumption Contract C1
  -> Hybrid AI renderer
```

C1 is downstream of Coordination and upstream of Hybrid rendering.

## 5. Deterministic decision policy

### 5.1 Validation first

The builder MUST fail closed when any of these invariants fail:

- either source bundle digest is invalid;
- source target scopes differ;
- source ranking digests differ;
- source structural interpretation digests differ;
- packet and coordination domain sets differ;
- one domain has more than one packet or relation;
- relation contains an unsupported coordination label;
- specificity labels are invalid;
- coordination cap is more permissive than Phase 3 / packet authority;
- packet identity/provenance required for consumption is malformed.

Malformed authority is a contract error, not a renderable claim.

### 5.2 Authorized specificity

`authorized_specificity` is the most conservative of:

1. packet `effective_specificity`;
2. coordination `coordination_specificity_cap`.

C1 can preserve or downgrade specificity only. It can never upgrade it.

### 5.3 `abstain_claim`

A valid claim receives `abstain_claim` when there is no same-scope target-system support:

```text
system_support_count == 0
```

Reason code:

`no_same_scope_target_support`

This is a consumption decision only. The upstream packet remains present and unchanged for audit.

### 5.4 `render_with_caveat`

A valid claim receives `render_with_caveat` when it is renderable but at least one conservative condition applies:

- `coordination_relation` is `single_system_support`;
- `coordination_relation` is `parallel_context`;
- `coordination_relation` is `parallel_signals`;
- `coordination_relation` is `layered_complement`;
- authorized specificity is lower than packet effective specificity;
- packet confidence is `low_confidence`;
- packet contains any existing abstention label that limits event-family, timing, or concrete-event claims.

Possible deterministic reason codes:

- `single_system_support`
- `parallel_context`
- `parallel_signals`
- `layered_complement`
- `specificity_downgraded`
- `low_confidence`
- `existing_abstention`

Reason codes are sorted in a fixed canonical order.

### 5.5 `render`

A claim receives `render` only when:

- it has at least one same-scope target system;
- no `render_with_caveat` condition applies;
- no abstain condition applies.

The common high-authority case is direct same-domain convergence with no downstream restriction.

## 6. Explicit non-goals

C1 MUST NOT:

- change `primary_domain`;
- change Phase 3 rank;
- create/remove/reorder event-family candidates;
- reorder primary/secondary domains;
- introduce another primary-domain display limit;
- create new evidence;
- alter `EvidenceFeature`;
- alter legacy Claim Evidence Packet data;
- change `coordination_relation`;
- infer explicit counterevidence not present in upstream schema;
- raise specificity;
- raise confidence;
- introduce probability semantics;
- allow AI to override the Python decision.

## 7. General/synthetic test matrix

G1. Same-domain direct convergence: render when no existing caveat applies; never raise specificity.

G2. Layered complement: renderable only with caveat; modifier never becomes a new target claim.

G3. Disjoint career + finance / career + partnership: frozen Coordination `parallel_signals` remains parallel; both valid claims remain present and independently consumable with caveat. Different domains alone never cause abstention or conflict.

G4. Single-system support: renderable with caveat; consumer must not invent cross-system support.

G5. Malformed/mismatched source authority: fail closed before any decision bundle is emitted.

G6. Coordination cap below packet effective specificity: authorized specificity downgrades.

G7. Coordination cap cannot raise packet authority.

G8. Packet/relation input ordering: identical canonical output and digest.

G9. Legacy `conflict_or_divergence` must not override Python Coordination `parallel_signals`.

G10. Mutation guard: input bundles, v1 output, Claim Evidence, and frozen Coordination output remain unchanged.

G11. Zero same-scope target-system support: `abstain_claim` with `no_same_scope_target_support`.
