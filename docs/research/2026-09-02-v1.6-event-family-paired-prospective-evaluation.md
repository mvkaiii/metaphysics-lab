# v1.6 Event-Family Paired Prospective Evaluation Runbook

## 目的

本流程用同一份 sealed child-level oracle，比較 frozen Legacy projection 與 frozen Hybrid candidate（EFA/C2/HCC/HOC）的 structured output。目標是同時觀察「有沒有多命中」與「有沒有少亂講」，而不是從自由文字 prose 事後挑有利解讀。

本流程只提供研究證據，不提供 release authority。所有輸出固定 `promotion_allowed=false`。

## 核心邊界

- Legacy Adapter 只能讀 frozen structured legacy outputs，不讀 renderer prose、outcome 或 oracle。
- Candidate 使用 frozen HOC structured output；paired evaluator 不重算 EFA/C2/HCC/HOC，也不改寫 authority。
- Legacy 與 Candidate 必須使用同一個 frozen child universe。
- Oracle child set 必須與兩個 arms exact-match；不能在 outcome reveal 後新增 event family。
- `indeterminate` 不進 supported hit / miss 或 unsupported render 的 accuracy denominator，也不能拿來調規則。
- 評估 report 只輸出 aggregate metrics，不輸出 case ID、child ID、domain、event family 或 outcome row。

## Future case sequencing

Future case：**Legacy + Candidate 必須在 outcome window 前生成並 seal。**

建議順序：

1. 完成 prospective intake 與 eligibility。
2. 凍結 shared child universe。
3. 生成並凍結 Legacy Adapter bundle。
4. 生成並凍結 Candidate HOC bundle。
5. 保存兩 arm source digests 與 case `input_digest`。
6. 等 outcome window 結束後，才依既定 structured rubric 建立 oracle。
7. seal oracle，取得 aggregate-only receipt。
8. verify oracle seal。
9. exactly-once 執行 paired evaluator。
10. 將該 evaluated case 標記為 permanently exposed。

## Historical case sequencing

Historical case：**必須先證明 never-exposed/source provenance，oracle 先 seal，outputs 生成時不可讀 oracle。**

若無法證明歷史資料在 candidate / Legacy output 產生前沒有被看過，該 case 不得當 prospective evidence 使用。

## Oracle 規則

Oracle 只保存 structured child outcome：

- `supported`
- `unsupported`
- `indeterminate`
- `maximum_supported_specificity`
- `caveat_required`
- `expected_cross_system_relation`

Oracle 不保存 raw event narrative。Seal receipt 只保存 aggregate identity 與 digests。

Seal：

```bash
python tools/seal_v16_event_family_paired_oracle.py \
  seal \
  --oracle ORACLE.json \
  --child-universe UNIVERSE.json \
  --receipt RECEIPT.json
```

Verify：

```bash
python tools/seal_v16_event_family_paired_oracle.py \
  verify \
  --oracle ORACLE.json \
  --child-universe UNIVERSE.json \
  --receipt RECEIPT.json
```

## Paired evaluation

```bash
python tools/evaluate_v16_event_family_paired.py \
  --input PAIRED_INPUT.json
```

或寫入檔案：

```bash
python tools/evaluate_v16_event_family_paired.py \
  --input PAIRED_INPUT.json \
  --output REPORT.json
```

Evaluator 比較：

- `supported_child_hit_count`
- `supported_child_miss_count`
- `unsupported_child_render_count`
- `specificity_overreach_count`
- `caveat_error_count`
- `false_convergence_count`

Research label：

- `PARETO_IMPROVEMENT_EVIDENCE`
- `NON_INFERIOR_NO_STRICT_GAIN`
- `TRADEOFF`
- `REGRESSION`

`PARETO_IMPROVEMENT_EVIDENCE` 只是 research label，不是 merge、default switch、tag 或 release 授權。

## 不可違反的 freeze / exposure 規則

- 兩個 arms 必須對同一 child universe / oracle。
- Oracle reveal 後不可改 Legacy Adapter、Candidate、Q2、paired rule。
- 任何 evaluated case scoring 後永久 exposed。
- FAIL/REGRESSION 不得用同 case retune 再跑。
- Private FAIL 不得放寬 threshold 或改 rubric 來讓同 case 重新 PASS。
- `promotion_allowed=false`。
- 本 infrastructure freeze cycle 不建立真實 private oracle、不建立真實 private paired report，也不執行 private scoring。

若未來要開始 real private paired cycle，必須另行明確授權，重新走 intake → freeze both outputs → seal/reveal oracle → exactly-once paired scoring。
