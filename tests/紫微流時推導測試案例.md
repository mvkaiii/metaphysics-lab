# 紫微流時推導測試案例

- 規則版本：v1.0-exp
- Capability：`ziwei.flow_hour_palaces`
- 測試資料：公開／合成案例，不使用真實命主私人出生資料
- 核心公式：`flow_hour_index = (flow_day_index + hour_branch_index) mod 12`

## Case A：一般月代表時辰

前置條件：既有 day engine 已得到流日命宮 `辰`。

| 時辰 | offset | 預期流時命宮 | 實際 | 結果 |
|---|---:|---|---|---|
| 子 | 0 | 辰 | 辰 | PASS |
| 丑 | 1 | 巳 | 巳 | PASS |
| 午 | 6 | 戌 | 戌 | PASS |
| 亥 | 11 | 卯 | 卯 | PASS |

對應合成輸入：

```text
birth_lunar_month = 5
birth_hour_branch = 戌
flow_year_branch = 酉
lunar_month = 1
lunar_day = 2
is_leap_month = false
```

## Case B：十二宮跨界

前置條件：流日命宮為 `亥`。

```text
子時 offset 0 → 亥
丑時 offset 1 → 子
```

確認十二宮索引循環，不會超出 `亥` 後停止。

結果：PASS。

## Case C：閏月前半

合成輸入：閏五月十五日、子時。

既有 day engine 結果：`酉`。

flow-hour 只繼承 day 結果並加子時 offset 0：

```text
流日命宮 酉 + 子時 0 = 流時命宮 酉
```

結果：PASS。

## Case D：閏月後半

合成輸入：閏五月十六日、子時。

既有 day engine 依 Project 規則得到：`亥`。

flow-hour 不把十六日重置成第一日，也不重新判定 effective month：

```text
流日命宮 亥 + 子時 0 = 流時命宮 亥
```

結果：PASS。

## Case E：民用時間不得偷轉

以下不是合法 `hour_branch`：

```text
14:00
下午兩點
2pm
空字串
```

core 應拋出 `ValueError`，由上游 Resolver 負責民用時間解析。

結果：PASS。

## 驗證結論

目前案例支持：

- 流日命宮起子時。
- 每一時辰順行一宮。
- 十二宮正確循環。
- 閏月完全繼承 day engine 的既有結果。
- flow-hour core 不負責民用時間、時區或日界政策。

此紀錄只支持 `Experimental / On-demand`，不代表 Stable。
